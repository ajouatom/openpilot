# Wiki·Carrot Web 렌더링 계약

GitHub Wiki와 Carrot Web은 같은 설정 설명에서 같은 정보·순서·의미를 제공한다. 시각 모양은 각 환경의 디자인 체계를 따르므로 같을 필요가 없다.

## 처리 흐름

```text
Wiki Markdown
→ 설정·구역 마커 추출
→ GFM AST 파싱
→ 콘텐츠 스키마·허용 노드 검증
→ URL·HTML 정화
→ 콘텐츠 토큰 변환
→ Carrot Web 공용 컴포넌트
→ 기존 Carrot Web 디자인 토큰
```

Carrot Web은 GitHub Action이 `carrot-wip` 기준으로 생성·검증해 실제 Wiki에 동기화한 `Settings-Catalog.json`과 해당 페이지 Markdown만 조회한다. 설정 하나는 언어별 독립 Markdown 파일 하나에 대응하며, 한 파일에는 설정 블록이 하나만 존재한다. 자동 페이지와 인덱스는 하나의 Wiki 커밋으로 갱신되며 개발·생성물 전용 저장소 브랜치는 만들지 않는다.

- 페이지 제목과 목록 이름은 Carrot Web의 현재 언어별 표시 제목과 동일하다.
- 파일명은 표시 제목에서 만든 로케일별 안전한 Wiki 이름이며, 설정의 영속 식별자는
  파일명이 아니라 파라미터다.
- 전체 설정 목록의 계층과 순서는 Carrot Web이 사용하는 `menu` 계층과 순서가 같다.
- 기존 Wiki 사이드바 구조는 보존하고 `설정 이해하기 > 전체 설정` 아래의 한국어
  메뉴 계층과 설정 링크를 Carrot Web과 같은 순서로 생성기가 관리한다.
- 기존 비관리 Wiki 문서와 이름이 충돌하면 게시를 중단하며 덮어쓰지 않는다.

```text
https://raw.githubusercontent.com/wiki/ajouatom/openpilot/Settings-Catalog.json
https://raw.githubusercontent.com/wiki/ajouatom/openpilot/{PAGE}.md
```

Wiki 직접 편집이 잘못되었거나 게시 작업이 중간에 실패하면 새 인덱스를 게시하지 않는다. 브라우저는 이전 인덱스와 마지막 정상본을 유지한다.

정규식은 마커 경계를 찾는 용도로만 사용한다. Markdown 자체는 GFM AST로 처리한다.

## 호환 매핑

| 의미 | GitHub Wiki | Carrot Web | 폴백 |
|---|---|---|---|
| 제목·문단 | GFM 제목·문단 | 문서 제목·본문 | 일반 텍스트 |
| 강조·코드 | GFM 강조·코드 | 강조·코드 텍스트 | 일반 텍스트 |
| 목록·순서 | GFM 목록 | 목록·절차 컴포넌트 | 줄 단위 텍스트 |
| 알림 | GitHub Alert | 상태 알림 컴포넌트 | 등급이 포함된 문단 |
| 링크 | GFM 링크 | 안전한 링크 컴포넌트 | URL이 제거된 링크 문구 |
| 이미지·영상 | 이미지·링크 | 미디어 카드 | 대체 문구·본문 설명 |
| 표 | GFM 표 | 넓은 화면 표 | 좁은 화면 키·값 목록 |
| 접기 | `<details>` | 공개·접기 컴포넌트 | 펼쳐진 본문 |
| Mermaid | GitHub 도식 | 지원된 도식 컴포넌트 | 동등한 텍스트 설명 |

새 문법을 허용하려면 Wiki 표현, AST 매핑, Web 컴포넌트, 폴백, 의미 동등성 테스트를 함께 추가한다.

## 콘텐츠 토큰

```text
identity.param / identity.title / identity.summary
overview.type / default / range / step / unit / options / menu
behavior.change / conditions / scope
usage.adjust / apply / verify / recover / restart
reference.example / technical
```

- 토큰은 번역 문구나 Wiki 제목과 분리된 안정적인 식별자다.
- 같은 의미는 설정·언어와 관계없이 같은 토큰을 사용한다.
- 알 수 없는 토큰은 렌더링하지 않고 검사 오류로 기록한다.
- 새 토큰은 기존 토큰으로 표현할 수 없을 때만 스키마와 함께 추가한다.
- 알림·미디어·관계·수명주기는 중복 Markdown 토큰으로 만들지 않고 해당 구조화 필드를 `참고` 또는 지정 구역에 배치한다.

## Carrot Web 디자인 계약

- 기존 의미 기반 공용 컴포넌트와 토큰을 우선한다.
- Wiki는 색상·간격·폰트·테두리·반경·그림자를 지정하지 않는다.
- 페이지별 인라인 스타일, 임의 색상값, 고정 폭, 일회성 CSS 클래스를 금지한다.
- 문서 전용 값이 필요하면 기존 토큰을 조합하고, 불가능할 때만 공용 토큰으로 추가한다.
- 실제 구현 시 저장소에 존재하는 토큰을 확인해 연결하며 이 문서에서 가상의 CSS 변수명을 확정하지 않는다.
- DOM 읽기 순서와 시각 순서를 일치시킨다.

## 안전·폴백

- Raw HTML·스크립트·이벤트 속성은 렌더링하지 않는다.
- 링크는 내부 앵커와 안전한 HTTP(S)만 허용한다.
- 스키마·해시·언어 검증에 실패하면 해당 새 콘텐츠를 표시하지 않는다.
- 검증된 마지막 원격 정상본이 있으면 유지하고, 없으면 설명 탭의 빈 상태를 표시한다.
- 장치 내부 Markdown과 로컬 문서 API는 설정 상세 설명의 폴백으로 사용하지 않는다.
- Wiki 편집 실패나 원격 요청 실패가 설정 조회·변경을 막으면 안 된다.

## 반응형·접근성

- 320 CSS px와 400% 확대에서 본문에 양방향 스크롤이 생기지 않는다.
- 제목 단계와 논리적 읽기 순서를 유지한다.
- 색상·아이콘·이미지·영상 없이 핵심 의미를 전달한다.
- 링크와 버튼은 단독으로 읽어도 목적을 알 수 있는 이름을 사용한다.
- 문서 언어는 BCP 47 `lang`, 필요한 방향은 `dir`로 표시한다.
- 숫자·날짜·백분율은 브라우저 `Intl` 계열 포매터를 사용한다.

## 동등성 검사

대표 Markdown 고정 문서마다 다음을 검사한다.

1. Wiki와 Web에서 제목·문단·목록 순서가 같다.
2. 모든 콘텐츠 토큰이 정확히 하나의 Web 컴포넌트나 폴백으로 연결된다.
3. 차단된 문법이 정보 손실 없이 안전한 표현으로 낮아진다.
4. 언어별 자리표시자와 선택지 코드가 같다.
5. 좁은 화면에서도 핵심 정보가 생략되지 않는다.
