# 신호등 위치 학습과 밝기·시간 변화 시험 — 2026-10-10

사용자는 위치 정답을 이용한 학습을 실제로 시도하고 학습 방법을 설명해 달라고 요청했다.
작업 중 가로 신호등의 좌/우 점등 위치와 이전 프레임의 변화만으로 상태를 알 수 있는지도
질문했다. **검출 ONNX 두 개를 실제로 학습·생성했고, 명암/시간 규칙도 영상으로 시험했다.**
일부 가능성은 보였지만 검출기와 규칙 모두 차량 교체/제어용으로 승격하지 않는다.
원래 주행모델의 x/v/a와 신호출발 조건, 차량 파일/설정은 변경하지 않았다.

## 학습의 의미와 범위

현재 작업은 카메라 RGB를 입력으로 하는 별도 모델의 지도학습이다. 영상에 신호등 몸체
사각형과 적색/녹색 정답을 직접 붙이고, 분류 오차와 위치 오차를 줄이도록 역전파로
가중치를 갱신했다. ONNX는 학습된 계산/가중치의 실행 파일이다. 주행 로그가 늘거나
주행 중이라는 이유로 스스로 가중치가 바뀌는 온라인/강화학습이 아니다.

원래 내부 주행 ONNX는 앞차·차선·경로와 x/v 등을 예측한다. 확인한 modelV2 변환
계약에는 신호등 위치/색의 명시적인 객체 목록이 없다. 이번 작업은 그 전체 모델의
미세조정이나 x/v 출력 수정이 아니다. 직전 [색상 재학습](signal_dusk_training_20261010.md)은
잘라낸 사진의 색 분류였고 위치는 바깥 탐색 프로그램이 골랐다. 새 ONNX는 각 탐색 창의
색 분류와 신호등 몸체 좌표를 함께 출력한다. 전체 화면을 한 번에 받는 대형 검출기는 아니다.

## 정답과 학습

기존 만남별 분할을 유지하고 각 만남/카메라/색에서 최대 세 장을 일정 간격으로 선택했다.
75장에 한 신호등의 몸체 경계를 직접 표시하고 확대 그림으로 확인했다. 약 4px 높이의
흐린 한 장과 상단에 잘린 한 장은 위치 학습/평가에서 제외했다. 남은 신호 사진은
학습 21, 개발 17, 별도 평가 35장이다. 기존 검토된 배경 33개는 학습 21, 개발 12개다.
전광판/표지 5개는 학습 쪽에만 들어간다. 학교 앞 주간/저녁은 모두 학습/선택에서 제외했다.
이미 분석한 영상이므로 새로운 도로의 독립 검증이 아니며 사진당 한 신호만 표시한 부분 정답이다.

알려진 신호를 포함하도록 위치·크기를 달리 자르고, 배경은 검토된 영역 안에서만 잘랐다.
학습 2,688, 개발 348, 별도 420개 입력이 생겼다. 총 3,456개는 증강 입력 수이며
독립적인 신호 사진 3,456장을 확보한 것이 아니다. RGB 96x48과 고정 정규화 색 특징을 사용했다.

- 첫 모델: Conv 6→16→24→32, 단계별 평균 풀링, Flatten 576→64,
  분류 3개와 sigmoid 중심 x/y·폭·높이 4개. 48,687개 파라미터를 새로 학습.
- 두 번째: 첫 모델이 개발 녹색에서 실패한 뒤 시도했다. 기존 c091 색상 분류 39개
  파라미터를 고정하고, 새 모델이 분류 보정과 위치를 학습한다. 총 48,726개 중
  학습 가능한 수는 48,687개다. 첫 별도 평가를 본 뒤의 탐색적 후속 시험이다.

각 구조는 AdamW lr0.001, weight decay0.0001/0.01, 600회 갱신, batch64,
200/400/600 checkpoint의 여섯 후보다. 밝기0.5~1.3, 채널 이득0.9~1.1 증강.
클래스 균형 교차 엔트로피 + 5×양성 위치 SmoothL1(beta0.1)을 최소화했다.
개발 손실로 첫 모델0.0001/200, 두 번째0.01/600을 선택해 고정한 뒤 별도 평가했다.

## 검출 결과

기존과 같은 667개 창, 신호 점수0.8, 신규 출력 박스의 NMS IoU0.3, 상위5개를 사용했다.
337개 전체 사진을 재생했으며 실제 NV12 실시간 입력과 비트 단위로 같은 실험은 아니다.

| 전체 화면 색 정답 | 기존 c091 | 처음부터 학습 | 색상 지식 유지 |
|---|---:|---:|---:|
| 개발 일반 카메라 | 59/76 | 0/76 | 66/76 |
| 별도 일반 카메라 | 108/109 | 30/109 | 105/109 |
| 별도 광각 카메라 | 26/44 | 34/44 | 17/44 |

첫 모델은 대부분 판단을 유보하거나 적색을 골라 별도 광각에서 색 정답34/44처럼 보여도
녹색을 하나도 검출하지 못했다. 두 번째는 개발 녹색16/33→23/33으로 개선됐으나,
별도 일반 카메라 적색→녹색0/66→2/66, 광각7/34→26/34로 퇴행했다.
학습한 표지 장면의 전체 화면에서도 녹색 오인3/5가 남았다.

상위5개 중 **색도 맞고 표시한 신호와 IoU0.3 이상**인 수는 첫 모델 모두0,
두 번째 학습17/21, 개발5/17, 별도13/35다. IoU0.5에서는11/21,2/17,3/35다.
사진의 모든 신호를 표시하지 않았으므로 전체 객체 precision/mAP를 주장하지 않는다.
색 정답과 객체 위치 정답은 다르며, 어느 경우도 해당 차로 연결을 입증하지 않는다.

## 사용자 제안: 색을 버리고 점등 위치와 변화를 보기

배열을 알고 같은 신호등을 정확히 따라간다면 유용한 단서다. RGB를
0.2126R+0.7152G+0.0722B 명암으로 바꾸고, 좌/우 밝기의 90백분위에서 몸체 중앙값을
뺀 대비를 비교했다. 초기 좌/우1/4 영역은 밝은 하늘/테두리가 섞여 실패했다.
후속 방식은 몸체 x=1/8·7/8, y=1/2, 반경=높이0.32의 작은 원 안을 비교했다.
같은 자료를 보고 수정한 것이므로 독립 검증으로 취급하지 않는다.

최대 대비>=0.05, (우−좌)/(최대대비+0.05)>0.2이면 녹색, <-0.2이면 적색,
그 외는 불명이다. 시간 규칙은 적색 관찰 최소3회 후, 마지막10개 적색 관찰의 중앙값보다
좌측 대비가0.02 이상 감소하고 우측이0.02 이상 증가한 녹색 후보가3프레임 연속일 때 확인한다.
기준은 각 실행 전에 고정했고 결과에 맞춰 숫자를 탐색하지 않았다.
이 시간 규칙은 학습된 신경망이 아닌 별도 영상 처리 프로토타입이다.

4구간480프레임을20Hz로 읽었다. 위치는 **수동 박스를 선형 보간**하고 범위 밖은 끝 박스를
유지했다. 미래의 수동 박스도 쓰는 보조 재생이므로 인과적인 자동 추적이나 실시간 성능 검증이 아니다.
네 구간 중 하나는 학습 만남, 하나는 개발, 둘은 별도 평가 만남이며 모두 이미 분석한 구간이다.

| 구간 | 첫 시각적 녹색 이후 첫 확인 | 적색 중 확인 | 실제 녹색 중 조건 충족 |
|---|---:|---:|---:|
| 출발 방향 교차로 | 0.106s | 0 | 53/76 |
| 귀환 대형 교차로 | 0.099s | 0 | 53/56 |
| 늦게 출발한 학교 앞 | 0.156s | 0 | 47/145 |
| 귀환 마지막 교차로 | 0.400s | 0 | 39/47 |

처음 네 전환은 모두 확인했지만 지속 인식은 불안정하다. 학교 앞 단일 명암 판정은
실제 녹색145프레임 중48개를 적색으로 읽고6개는 불명이다. 색 분류기의 신호 상태,
출발 Go, 실제 차량 반응 시간과 위 숫자를 동일시하지 않는다.
별도 정지 사진35장의 명암 정답은25/35이고 적색20장 중2장을 녹색으로 읽었다.
따라서 네 짧은 전환에서 적색 중 확인이0이라는 결과가 일반적인 오출발 방지를 입증하지 않는다.

신호등/전구 위치와 동일 객체 추적이 전제다. 역광·반사·작은 크기·영상에서의 간헐적 소등,
화살표/직진 구별, 다른 차로 신호 연결을 아직 해결하지 않았다. 모든 가로/세로 배열이나
녹색으로 처음 진입한 상황에 이 전환 규칙이 그대로 적용되는 것도 아니다.
