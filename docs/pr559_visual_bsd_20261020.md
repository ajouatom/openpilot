# PR #559: independent visual BSD lifecycle

Reviewed https://github.com/ajouatom/openpilot/pull/559 at contributor commit
`090dbac9370508d0765fdf2ab62240673cd34ff8` (navipilot / jixiexiaoge).

## Accepted behavior

- `ShareData` retains its existing service/onroad lifecycle and lane recognition.
- New persistent `OnnxBsdEnabled` defaults to **off**, including upgrades with
  existing `ShareData=1`. Camera BSD users must explicitly enable it.
- Disabling visual BSD releases the OpenCV network reference and invalidates its
  results while lane inference and camera snapshots remain available. Vehicle BSD
  and existing vision freshness/eligibility checks remain in place.
- TCP 7711 no longer sends general car/model/control telemetry. Only fresh Tesla
  `DAS_road` stop-line distance and traffic-light colour retain the existing packet
  envelope. External clients relying on removed telemetry must adapt. The local
  vision result publisher remains independent.

## Corrections made during integration

The original PR allowed concurrent HTTP/camera refreshes to apply stale settings
and reload a disabled network. Serialize the parameter read and model transition.
Clear results and follow-up timing immediately on either toggle transition, and
reject camera work/results belonging to an earlier toggle generation.

Carrot Web now recognizes healthy lane-only operation, keeps real enabled-model
and lane-camera failures visible, displays BSD off, includes its toggle in the BSD
settings group, and masks stale BSD detections. Older status payloads without the
new flag retain their original behavior. Generated web bundles were rebuilt.

The contributor test Params dictionary is now instance-local; its startup test
uses the existing fake transport fixture. Korean/English user guides and the
Korean/English/Chinese setting descriptions explain the new opt-in behavior.
