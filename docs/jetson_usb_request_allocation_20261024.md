## Change

A protocol-2 Jetson peer can advertise the exact `carrot_request_chunks_v1` descriptor. The comma FunctionFS sender then wraps large inference/HUD/navigation/Wi-Fi requests in complete frames no larger than 32 KiB. Legacy peers, protocol 3 and other transports retain their existing path. HELLO resets negotiation on every connection.

Each envelope carries the original kind, sequence, total size, offset and complete-payload CRC32. The receiver bounds assembly to 1 MiB and 0.5 seconds, rejects gaps, conflicting duplicates, corruption and interleaving, and dispatches only a complete input. Identical full-envelope replays do not execute inference twice. A completed sequence remains committed through the original session handler. HELLO and session replacement discard partial assembly.

Simply shrinking raw `writev` chunks would expose the existing DWC3 whole-transfer replay behavior as duplicated bytes inside an inference payload. Independent framed envelopes preserve stream alignment. A bounded-envelope ENOMEM aborts the request instead of silently splitting it into unframed smaller writes. This reduces the contiguous allocation requirement; it is not a promise that a 32 KiB allocation can never fail.

The write path also uses `_signal.pthread_sigmask`, the same C primitive called by the standard `signal.pthread_sigmask` wrapper, preserving the complete original mask and restoration on failure. This avoids repeated Python enum construction for every signal in every envelope write. Signal blocking, watchdog arm/disarm and abort semantics remain intact.

The model, input content, recurrent-state semantics, scheduling priorities, synchronous inference exchange, IPC deadlines and validity checks remain unchanged. There is no concurrent model-frame pipeline or deadline extension.

## Preserve the logical queue during inference

The original read-ahead queue holds two complete logical messages plus one reader-owned message, enough for a HUD snapshot and two media fragments while the session thread runs inference. Small transport envelopes accidentally consumed those queue slots individually. The actual read-ahead class reproduces a blocked reader with a simulated busy GPU consumer and bounded HUD/media inputs; old code fails both ordinary and repeated-envelope versions.

NAV source `69c46427892e0fd2279ce37e8a35ceeefd379b0d` / Wip `ac716fd138` assembles checked envelopes in the reader before entering the existing two-message queue. It preserves one bounded 1 MiB assembly, CRC/age/order checks, HELLO reset, duplicate suppression and owned queue payloads. Corrupt/interrupted/wrong-protocol inputs never reach inference. The existing session sequence check still commits execution. Actual session dispatch executes one exact reconstructed input after duplicated envelopes. This does not delay or cache model maps or change model inputs.

The owner also proposed sending model maps during GPU inference for use on the next frame. Current canonical model maps have fixed 256x256 uint8 wire size (64 KiB), independent of visual complexity; the phone/HUD map video is separate and variable-sized.
