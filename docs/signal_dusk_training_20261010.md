# 추가 주행 자료로 신호 ONNX 재학습 — 2026-10-10

사용자 요청대로 가중치를 실제로 다시 학습하고 새 ONNX 두 개를 만들어 검증했다.
일부 오인식은 줄었지만 다른 교차로의 녹색 검출이 악화되어 두 후보 모두 승격하지 않는다.
대상은 별도 카메라 신호 분류기다. 원래 주행모델의 x/v/a, 신호출발 조건, 차량 설정은 변경하지 않았다.

## 자료와 사전 고정 설계

[추가 저녁 주행 분석](ioniq5_signal_dusk_20261010.md)의 시각 정답과
[주간 학교 앞 분석](ioniq5_signal_1090_20261010.md), 기존 시각 정답을 사용했다.
카메라에 색이 불명확한 사진과 전환 중 혼합 프레임은 학습/정답률에서 제외했다.
기존 신호 158개 + 배경 28개, 주간 추가 62개, 저녁 추가 122개로 총 370개다.

- 학습 129개: 기존 두 만남과 저녁 출발 방향의 두 만남. 전광판/도로표지 배경 5개 포함.
- 개발 88개: 기존 두 만남과 저녁 귀환 대형 교차로.
- 별도 평가 153개: 기존 회귀 사례, 주간 학교 앞 두 카메라, 저녁 학교 앞과 마지막 교차로.

학교 앞 주간/저녁 자료는 모두 학습과 모델 선택에서 제외했다. 만남 단위로 나누고
같은 만남의 인접 프레임을 무작위 분할하지 않았다. 다만 자료는 이미 분석한 것이며,
반복 장소와 연속 프레임이 포함된다. 새로운 도로에서의 독립 검증으로 해석하지 않는다.

학습 전에 protocol.json에 분할, 구조, 증강, 후보와 선택 방법을 기록했다.
입력은 RGB float32 [0,1], bilinear 96x32. CAN/차량 상태/원래 모델 예측을 입력이나
정답으로 사용하지 않았다. 배경/적색/녹색 3분류이며 신호 방향·차로 연결은 학습하지 않는다.

1. 기존 색상 특징 12개 → Linear 3의 **39개 파라미터**를 재학습했다.
2. 같은 색상 특징에 3x3 Conv 3→12, 평균 풀링, Conv 12→16, 공간 평균/최댓값을
   결합한 Linear 44→3을 학습했다. **2,215개 파라미터**다.

두 모델 모두 기존 c091 모델의 색상 가중치로 초기화했다. 합성곱은 새로 초기화하고
모두 학습했다. AdamW, seed 20261011, weight decay 0.0001/0.01,
200 epoch, epoch당 두 번 갱신, 50/100/200 checkpoint로 총 12개 후보를 평가했다.
밝기 0.35~1.3, 채널 이득 0.9~1.1 증강. 만남/클래스별 가중치를 균등하게 한 뒤
배경·적색 비용 2, 녹색 비용 1을 적용하고 정규화했다.

구조별 개발 균형 로그 손실로 색상 0.01/100, 합성곱 0.01/200을 선택하고,
두 선택을 파일에 고정한 뒤 별도 평가를 실행했다. 개발 로그 손실은 기존 0.227,
재학습 색상 0.468, 합성곱 0.302로 기존보다 나쁘다. 새 후보를 만들었다는 사실이
기존 모델보다 낫다는 뜻은 아니다.

## 전체 화면 탐색 결과

차량 관찰기와 같은 상단 60%/중앙 90%, 667개 창, 점수 0.8 기준을 고정했다.
337개의 색이 확인된 전체 사진을 세 모델에 똑같이 입력했다.
기록된 RGB 영상 재생이며 원래 VisionIPC NV12 입력과 비트 단위로 같지는 않다.

| 색이 맞은 프레임 | 기존 c091 | 색상 재학습 | 합성곱 결합 |
|---|---:|---:|---:|
| 개발용 일반 카메라 | 59/76 | 46/76 | 50/76 |
| 별도 평가 일반 카메라 | 108/109 | 86/109 | 107/109 |
| 별도 평가 광각 카메라 | 26/44 | 20/44 | 36/44 |

현재 차량 관찰기는 **일반 카메라만** 사용한다. 별도 평가를 모두 합친 134/153 →
143/153만 제시하면 광각 개선이 일반 카메라의 퇴행을 가리므로 적절하지 않다.
일반 카메라 개발용 녹색 검출은 기존 16/33 → 합성곱 7/33, 별도 평가는 42/43 → 41/43이다.
일반 카메라의 적색→녹색은 개발/별도 평가 모두 두 모델에서 0이지만 제한된 자료다.
광각 적색→녹색은 7/34 → 1/34로 줄었고, 녹색 검출도 9/10 → 6/10으로 줄었다.

색이 맞아도 잘못된 물체를 골랐을 수 있다. 별도 일반 카메라 평가에서 색이 맞고
선택 창이 검토 영역과 조금이라도 겹치는 수는 두 모델 모두 99/109다.
검토 영역은 정확한 객체 박스가 아니므로 이 수치는 검출 정확도나 차로 연결 검증이 아니다.
대표 선택 영역을 영상에 그려 확인했으며, 옆의 빨간 물체/다른 신호를 고르는 실패가 남았다.

## 학교 앞 지연과 전광판

신호 검토 영역만 잘라 주는 별도 검사는 기존 63/153 → 합성곱 111/153이다
(0.8 이상으로 정답을 낸 수; argmax 정답은 77 → 113).
저녁 학교 앞 녹색 영역에서는 0/25 → 25/25지만, 전체 화면 녹색 검출은 두 모델 모두
24/25이고 첫 녹색 검출도 같은 475번 사진이다. **실제 출발 지연 개선을 입증하지 않는다.**
학교 앞의 넓은 검토 영역에는 먼 신호등이 들어 있고 가까운 상부 신호등은 빠져 있다.
대표 적색/녹색 원본과 자른 영역을 모든 추가 만남에 대해 다시 확인했다.

학습한 전광판·표지 5개를 잘라 입력하면 0.8 이상 녹색 오인은 5/5 → 0/5다.
그러나 두 개는 여전히 녹색이 argmax이며, 점수만 0.8 아래가 되었다.
이 다섯 **학습 장면의 전체 화면**을 추가 재생하면 잘못된 녹색 선택은 2/5 → 1/5다.
남은 사례는 다른 위치의 녹색 계열 물체를 고른다. 다섯 장에서의 개선은 학습 자료에 대한
결과이며 새로운 전광판에 일반화했다는 증거가 아니다. 기존 live 기록과 영상 재생의
점수/순위 차이가 있어 live의 5회 오인을 재생 전체 화면의 5회로 그대로 계산하지 않았다.
