# 새 야간 자료를 포함한 주행 ONNX 미세조정 — 2026-10-10

사용자는 이전 자료의 실패 결과를 새 야간 자료에도 적용해서 설명한 점을 지적하고,
새 자료를 포함해 원본 ONNX를 다시 학습하도록 요청했다. 이번에는 **실제로 새 야간
영상을 학습에 포함했고, 기존 주행 ONNX에서 시작한 여섯 개 전체 ONNX를 생성했다.**
별도 색상 인식기를 다시 학습한 작업이 아니다. 여섯 설정 모두 개발 검증을 통과하지
못했고, 진단용 선택 후보도 별도 평가에서 적색 오출발 두 구간을 해결하지 못했다.
차량의 모델·프로세스·제어·설정은 변경하지 않았다.

## 기존 학습을 유지하며 바꾼 범위

시작 모델은 기존 내부 `driving_supercombo.onnx`이며 SHA256은
`f73a9e535523d5e9acb9e642c64e33d631825dc8ba74123757d107cedd047bb5`다.
무작위 초기화로 기존 주행 학습을 버린 것이 아니다.

- `linear`: 기존 마지막 plan 출력층에서 0.5초 이후 x/v/a 평균값 75개 행만 학습한다.
  실제 조정 대상은 가중치·편향 19,275개다.
- `plan`: 위 행과 함께 원래 존재하던 `in_layer.plan`, `res_layer.plan.0/2`를 학습한다.
  영상 인코더, 공유 시간 특징 계산층, 다른 출력 분기는 고정한다. 학습 때만 사용하는
  적색/녹색 보조 분류 손실도 추가한다. 보조 분류기는 ONNX로 내보내지 않는다.
- 두 방식에서 사건별 학습 비중 0.1/0.3/1.0을 비교했다. Adam, 500스텝,
  배치 256, 학습률 0.00002, 고정 seed를 사용했다. 각 후보는 같은 원본에서 시작한다.
- 기존 주행과 감속 접근의 출력 보존, 횡방향·불확실성 출력 보존 손실을 함께 사용한다.
  `plan` 방식은 공유 plan 특징을 바꾸므로 횡방향 출력도 바뀔 수 있고 실제로 바뀌었다.
  `linear` 역시 x/v가 횡방향 계획기에 사용되므로 차량의 횡방향 동작 보존을 뜻하지 않는다.

**이번에도 영상 인코더 자체를 역전파 학습한 것은 아니다.** 이전의 마지막 선형층
학습보다 넓은, 기존 궤적 계산 분기의 미세조정이다. 여섯 ONNX 모두 원래 그래프 구조와
입출력 형상을 유지하므로 별도 실행 프로세스가 추가되는 후보는 아니다.

## 자료와 정답

도로/광각 44,400쌍, 37개 구간을 원본 모델로 연속 재생해 plan 분기 입력을 다시 추출했다.
카메라 frame ID 쌍의 불일치와 desire 누락은 없었다.

| 자료 | 구간 | 이번 용도 |
|---|---|---|
| 새 야간 1091 | 11–22, 12개 | 11–14 학습, 15–17 개발, 18–22 평가 |

한 번의 연속 신호 대기는 구간 경계를 넘어도 같은 역할에 둔다. 인접 프레임을 무작위로
학습/검증에 나누지 않았다. 다만 모두 이전에 영상을 검토했던 같은 차량·지역·날짜의
자료이며 장소 중복도 있다. 독립된 새 도로에서의 맹검 성능으로 해석하면 안 된다.

학습 표본은 적색 정차 861개, 녹색 뒤 기록 궤적 95개, 기존 출력 보존 576개다.
적색·녹색은 네 번의 대기/출발 사건에서 가져온 시간적으로 상관된 표본이다.
적색 정답은 실제 속도 절댓값 0.03m/s 미만이고 이후 10초도 적색인 경우만 사용한다.
0.5초 이후 x/v/a를 0으로 학습한다. 적색에서 잘못 움직인 주행을 올바른 출발로
학습하지 않는다. 녹색은 검토한 출발 구간의 실측 속도/가속도와 속도 적분 거리다.
이는 기록 주행 모방이며 최적 궤적이나 장애물 통과 허가의 정답이 아니다.

개발 표본은 적색 1,265개, 녹색 100개, 보존 259개이며, 평가 표본은 적색 859개,
녹색 보존 85개, 녹색 지연 29개, 보존 837개다. 정차 조건을 만족하지 않는 일부
신호 구간은 정지 정답 표본 수가 0이다. 그런 장면을 정지선 정답으로 억지 사용하지 않았다.

**미터 단위 정지선 위치를 새로 정답 표시한 작업은 아니다.** 기존 감속 접근을 보존하는
손실은 포함했지만 실제 정지선 정차 오차를 검증한 것은 아니다.

## 여섯 후보의 결과

선택 규칙은 개발 검증 위반 수가 적은 후보, 동률이면 사건별 적색 terminal-v 평균
절대오차가 작은 후보 순이다. 선택 기록을 저장한 뒤 평가 구간을 계산했다. 어느 검증
조건이든 실패하면 제어 적용 대상이 아니다. 가장 덜 실패한 후보도 성공 모델이 아니다.

| 후보 | 개발 조건 위반 수 | 개발 적색 사건별 평균 오차(m/s) |
|---|---:|---:|
| linear 0.1 | 5 | 0.564 |
| linear 0.3 | 7 | 0.594 |
| linear 1.0 | 9 | 0.589 |
| plan 0.1 | 19 | 0.644 |
| plan 0.3 | 21 | 0.632 |
| plan 1.0 | 22 | 0.610 |

가장 강한 `plan 1.0`에서 한 야간 적색 대기 사건의 10초 뒤 속도 절대오차는
**0.563→0.495m/s**로 줄었다. 그러나 다른 주간 적색 사건은 **0.364→0.753m/s**로
악화됐고, 야간 사건의 v10>5m/s 표본 세 개가 그대로 남았다. 음수 미래 속도도 늘었다.
개발 보존 표본의 예측 횡방향 위치 최대 차이는 2.240m였다. 이는 **예측값 차이**이지
차량이 실제로 그만큼 옆으로 움직였다는 뜻이 아니다.

진단용으로 선택된 `linear 0.1`도 개발 야간 적색 오차가 0.563→0.643m/s였고,
평가 야간 적색은 1.028→1.097m/s였다. 주간 학교 앞 녹색 지연 창의 v10 평균은
0.787→0.867m/s, 해질녘 학교 앞은 0.978→1.016m/s로 변화가 작았다.
평가 보존 표본의 x10 평균 절대 변화 1.884m도 미리 정한 1m 한도를 넘었다.

## 실제 ONNX 검증과 출발 판단 재생

- 여섯 전체 ONNX를 생성하고 ONNX checker를 통과했다. 후보·학습 상태를 보관하기 위해
  동일 seed/설정으로 학습을 다시 실행했으며 선택 모델 SHA256이 동일했다.
  두 번째 실행에서 검증 결과를 보고 학습 설정을 변경하지 않았다.
- 선택 모델과 `plan 1.0` 전체 ONNX 각각 실제 카메라 입력 259개로 GPU 추론했다.
  두 모델 모두 plan 밖 출력은 원본과 정확히 같았다. 선택 모델의 plan 횡방향 출력도
  이 입력들에서 정확히 같았다. `plan 1.0`의 횡방향 위치 최대 차이는 1.8125m였다.
- 학습 계산과 전체 FP16 ONNX의 최대 차이는 선택 모델 x 0.137m/v 0.0180m/s,
  `plan 1.0` x 0.138m/v 0.0156m/s였다. 영상 특징 재구성과 실제 차량 출력 사이에는
  별도 차이가 있다. 원본 재생의 구간별 v10 MAE 중앙값은 0.224m/s, 최대 0.510m/s다.
- 변경하지 않은 `check_model_stopping` 함수를 기록된 차량/레이더 상태 및 이전 xState와
  함께 재생했다. 실제 기록 출력을 넣으면 사건 창 318/318개의 신호 상태가 일치했다.

| 새 야간 사건 창 | 원본 재구성의 진행 판단 프레임 | 선택 후보 |
|---|---:|---:|
| 12번, 4–11초 적색 오출발 | 88 | 88 |
| 16번, 19–25초 보행자/리드 상태 전환 | 19 | 19 |
| 20번, 40–43초 적색 접근 | 1 | 0 |

이는 시간적으로 상관된 **판단 프레임 수**이며 독립적인 성공률이 아니다. 원본/후보 모두
같은 기록 입력을 사용했고 후보에 따른 차량 이동·앞차 거리·카메라 변화는 시뮬레이션하지
않았다. 첫 두 오출발 창은 해결하지 못했으며, 세 번째 한 프레임 감소도 물리적 감속
개선을 입증하지 않는다. 녹색 다섯 전환 중 네 곳의 첫 Go 시각은 같았고, 한 곳만 약57ms
앞당겨졌다. 구간 끝의 다음 구간 입력이 아직 없는 일곱 행은 제외했다.

16번의 기록에는 모델의 적색 판단이 유지되는 동안에도 리드 모드 이탈로 출발 가능한
상태가 된 경로가 있다. 이 부분은 원본 모델 출력만 고치는 시험과 별도로 봐야 한다.
새 모델이 신호를 잘 판단하면 모든 출발 경로가 자동으로 막힌다고 보장할 수 없다.
