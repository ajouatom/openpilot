# Ioniq 5 PE 추가 주행: 적색 중 재가속과 추가 학습 자료

2026-10-10 추가 주행을 수집하고 영상·모델·플래너·제어를 대조했다.
문제 구간은 `00001090--7b14158a8e--30`의 약 46.7~53.6초다.
실제 적색 중 첫 재가속, 브레이크 해제, RES 재활성화 후 두 번째 재가속이 기록됐다.
이번 작업은 분석과 정답 자료 작성 및 기존 ONNX의 PC 평가다.
출발 조건, 모델 가중치, 차량 프로그램/설정은 변경하지 않았다.

## 수집과 정합

- NAS 업로드 목록에 새 주행이 없어 연결된 차량에서 닫힌 로그를 수집했다.
  route 1090의 qlog 35개로 주행 구간을 찾고, segments 26~33의 rlog,
  일반/광각 영상, qcamera 총 733,785,430 bytes를 원본 파일 크기와 확인했다.
- 9,600 modelV2 모두 valid, 카메라 frame ID 누락 없음.
  연속 카메라 EOF 간격 최대 60.622ms. 이 사실이 모든 실행 지연을 배제하지는 않는다.
- longitudinalPlan 9,596개 모두 `modelMonoTime`으로 해당 모델 출력과 정확히 연결했다.
  판단 재구성에서는 `radarStateMonoTime`도 사용했다. carState는 플래너 발행 직전 값으로
  연결했으며 실제 SubMaster 수신 순간의 완전 재현은 아니다.
- 원본 `check_model_stopping` 함수를 AST로 추출해 실행한 결과, 사건 구간 220개 판단이
  기록된 trafficState와 220/220 일치했다. 매 단계 이전 xState는 기록값을 사용했다.
  전체 제어기/차량의 폐루프 시뮬레이션은 아니다.
- route 시작 initData는 `8afb265ea8`, 앞선 정차 중 관찰기 수정 후 차량 버전은
  `df7cc14549`였다. 두 버전의 carrot_functions.py는 동일하다.
  route 시작 commit만으로 현재 관찰기 버전을 판정하면 안 된다.

## x[-1]이 크지 않은데 출발한 이유

`openpilot/selfdrive/carrot/carrot_functions.py:check_model_stopping`의 출발 후보는 다음과 같다.

```python
model_v = self.vFilter.process(v[-1])  # 최근 10개 예측 끝속도의 평균
startSign = model_v > 5.0 or model_v > (v[0] + 2)
```

정지 조건이 거짓이면서 출발 후보가 5회 연속이면
`startSignCount * 0.05 > 0.2`가 성립해 trafficState가 green이 된다.
이는 신호등 색상 분류 결과가 아니라 모델의 미래 이동 예측을 이용한 상태 이름이다.
큰 x[-1]을 별도로 요구하는 출발 조건은 없다.

| segment 30 시각 | 기록과 의미 |
|---|---|
| 46.668s | traffic red → off, x[-1]=18.00m, 평균 끝속도=3.281m/s. 정지 조건이 먼저 풀림. |
| 47.006s | 제어 가속도 명령이 양수로 바뀜. 아직 green 전환 전. |
| 47.108s | xState e2eStop → e2eCruise, trafficSignGreen. x[-1]=34.458m, v[-1]=7.633m/s, 평균=4.967m/s, v[0]=2.303m/s. `4.967 > 2.303+2` 성립, 출발 후보 5회. |
| 47.827s | 브레이크 입력. 47.831s longActive=false. 직전 가속 명령 최고 +1.352m/s². |
| 50.318~50.358s | 적색 정지 상태로 복귀. |
| 51.108s | 다시 e2eCruise/green. x[-1]=38.262m, 평균 끝속도=6.625m/s. 이 순간 제어는 아직 disabled. |
| 51.087~51.230s | accelCruise(RES) 버튼 누름/해제 기록. 51.236s longActive=true. |
| 52.611s | 두 번째 브레이크 입력. 52.616s longActive=false. 그전 가속 명령 최고 +2.353m/s². |

첫 green 전환은 clocks 기준 한국 시각 **16:09:15.777**,
두 번째는 **16:09:19.777**이다. 가속 페달 입력, leadOne 감지,
외부 carrotMan 신호 전환으로 출발한 사례가 아니다.
두 번째 활성화는 RES 버튼 뒤에 일어났으며, 모델이 해제된 제어를 스스로 켠 것은 아니다.
표의 가속도는 명령값으로 실제 차체 가속도와 구분한다.

`trafficState=off`에도 함수 하단에서 `stop_model_x=1000`으로 설정한다.
따라서 정지 제약이 풀리는 시점은 green 전환보다 앞설 수 있다.
이번 로그의 양의 가속 명령도 green보다 약 102ms 먼저 시작한다.
이 실행 경로를 확인했지만 사용자가 원하지 않은 출발 임계값 수정은 하지 않았다.

모델의 10초 궤적도 확인했다. 첫 green 프레임에서 현재 예측 속도는 2.30m/s,
2.5초 뒤는 약 0.70m/s, 10초 뒤는 7.63m/s다.
즉 모델은 감속 후 다시 움직이는 미래를 예측했다. 전체 이동거리 x[-1]은 34.46m여도
끝속도는 높을 수 있다. 그 끝속도를 출발 판단에 사용하는 구조가 이번 증상을 설명한다.
어떤 화소/내부 특징이 미래 재가속 예측을 만들었는지는 이 로그만으로 확정하지 못했다.
반대편 차량 통과와 신호 영상의 가시성 변화는 조사 후보이지 입증된 원인이 아니다.

## 별도 색상 ONNX는 무엇을 기록했나

실제 제어용 내부 ONNX는 기존 `f73a9e53...` 그대로다.
별도 색상 ONNX `c091fad2...`는 `signalColorShadow`만 기록하며
modelV2나 플래너로 결과를 전달하는 경로가 없다.

segment 30의 입력 프레임 44.650, 46.403, 48.202, 49.952, 51.705, 53.452초
6회 모두 red를 기록했고 영상의 적색과 일치했다.
점수는 0.99996 이상이지만 보정된 신뢰도나 독립적인 정확도 증거는 아니다.
간격이 약 1.75초이므로 연속적인 정지 보장도 아니다.
기록 전용이어서 기존 모델의 오출발을 막을 수 없다.

후속 정상 녹색 전환은 두 카메라를 함께 확인해야 했다.
segment 31의 광각 22.5초에는 적색, 23.0초에는 녹색이 보인다.
플래너 green/출발 전환은 23.311초다.
같은 frame ID의 일반 카메라는 23초 부근에 신호등 발광색이 보이지 않고,
26.75초경부터 녹색이 보인다. 색상 관찰기의 첫 녹색 입력은 26.949초다.
따라서 일반 카메라만 보고 23.311초 출발까지 오출발로 분류하면 잘못된 정답이 된다.

두 카메라의 동일 segmentId/frameId와 EOF를 대조했다.
예를 들어 segment 31, frame index 460은 양쪽 모두 frame ID 37662,
EOF 차이는 약 0.014ms다. 시간 불일치로 몇 초 차이가 생긴 사례가 아니다.
LED 점멸/노출/영상 처리 중 무엇이 발광 소실을 만들었는지는 아직 검증하지 않았다.
광각에도 일부 프레임은 발광색이 보이지 않으므로 어느 한 카메라가 항상 우월하다고
일반화할 수 없다.

## 추가 학습 가능성과 이번에 만든 자료

직접 검토한 **82장**, 한 교차로 조우의 자료를 새로 만들었다.
영상에서 색이 보이는 적색 50장, 녹색 12장, 픽셀로 판독 불가 20장이다.
각 행에 원본 영상/이미지 SHA256, 카메라 종류, frame ID, EOF, 검토 ROI,
픽셀 판독과 교차로 실제 상태를 따로 기록했다.
판독 불가 프레임은 단일 영상 색상 학습의 확정 정답에서 제외한다.
차량 속도나 기존 모델의 green 판정을 정답으로 사용하지 않았다.

기존 색상 ONNX를 가중치 변경 없이 새 영상의 수동 지정 ROI에 PC에서 실행했다.
기존 선택 기준인 색상 점수 0.8 이상을 적용하면 일반 카메라의 색이 보이는 18장 중
16장, 광각 44장 중 3장이 맞았다. 광각은 적색 0/34, 녹색 3/10이었다.
최댓값 클래스만 사용하면 각각 17/18, 10/44다.
ROI 크기/신호 크기/색감이 다르므로 이 숫자는 카메라 자체의 우열을 뜻하지 않는다.
수동 ROI와 압축 영상의 시험이며 실시간 blind detection이나 NV12 비트 동일 재현이 아니다.

이 자료로 추가 학습 시험은 가능하다. 특히 광각의 작은 신호와 색감에 대한 학습,
신호등 위치 찾기, 시간 연속성, 두 카메라에서 판독 불가인 상태를 다루는 방법이 필요하다.
기존 색상 모델을 광각에 연결하기만 하면 해결된다는 결론은 이번 시험이 지지하지 않는다.
그리고 색상 분류기 개선은 기존 주행 모델의 x/v 가중치 개선과 별개의 결과다.

82장은 **한 조우**다. 같은 신호의 연속 프레임을 학습/검증으로 무작위 나누면
성능을 과장한다. 이 조우 전체를 한 묶음으로 보존하고 기존 다른 조우의 회귀 검증과
분리해야 한다. 더 필요한 자료는 단순 주행 시간보다 다른 교차로·날짜·주야간·역광,
정지 중 주변 차량 이동, 실제 적색→녹색 전환, 브레이크등/간판 등 혼동 대상이다.
이번 자료만으로도 다음 시험을 시작할 수 있지만 보편적 개선 판정에는 새 조우가 더 필요하다.

이번에는 새 가중치를 학습하거나 ONNX를 교체하지 않았다.
새 자료의 원인 분석·시각 정답·기존 ONNX 평가를 완료한 상태이며,
새로운 제어 효과나 오출발 해결을 주장하지 않는다.
