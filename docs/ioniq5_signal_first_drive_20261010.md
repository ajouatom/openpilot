# 내부 신호 모델 비교 시험: 첫 주행 분석 (2026-10-10)

이번 후보는 실차 제어 승격 대상으로 적합하지 않다. 적색 대기 중 잔여 미래 속도는
줄었지만, 새로 확인한 녹색 전환 지연을 해결하지 못하고 그 구간의 진행 예측을 더
낮췄다. 일부 출력은 음수 속도/거리까지 내려갔다. 신호출발 조건이나 제어 코드는
변경하지 않았다. 실제 차량은 원본 내부 모델로 주행했고 후보는 비교 로그만 남겼다.

## 자료와 확인 범위

- Ioniq 5 PE C4, route `0000108c--e6597f4447`, trial `carrot-signal-shadow`.
- 차량에서 종료된 11~21번 세그먼트를 직접 수집했다. 도로/광각 원본 영상,
  rlog, qlog 44개 파일 989,521,463 bytes를 원본 크기와 대조했다. qcamera는 별도 보조 자료다.
- 실제 이동 12~20번 전체를 2초 간격 도로 영상으로 검토하고, 문제 후보 구간의
  원본 도로/광각 영상과 신호 전환 전후 20 Hz 프레임을 확대 확인했다.
  모든 프레임을 수작업으로 정답 라벨링했다는 뜻은 아니다.
- 각 세그먼트 비교 300개, 총 3,300개. 원본 modelV2는 모두 valid이며 각 세그먼트
  내부 frame ID 누락 0. 비교 drop 누계는 설치 시의 8에서 증가하지 않았다.
  기록된 원본 모델 평균 실행 시간은 세그먼트별 약 24.8~25.2 ms였다.
- 후보와 `policy_baseline`을 비교했다. 둘은 같은 CPU 추론 경로이므로 원본 QCOM과
  CPU 사이의 산술 차이를 후보의 효과로 오인하지 않는다.
- 개인 영상, 차량 설정, 모델과 추출 자료는 로컬의
  `.analysis/archive/2026-10-10-signal-first-drive/`에만 보관한다.

## 확인한 주요 장면

세그먼트 시각은 영상 프레임 번호/20이며, 정확한 신호 전환 비교에는
`roadEncodeIdx.timestampEof`와 로그 단조 시각을 사용했다. 아래 시각은 한국 시각이다.
`trafficState`는 모델의 직접 색상 분류가 아니라 x/v 등에서 유도된 플래너 상태다.

### 1. 녹색 전환에 비교적 빠르게 반응: 16번 44초 부근

앞차 없이 기다리던 교차로의 적색은 영상 44.20초까지 켜져 있고 44.25초에
녹색 점등이 보인다. 녹색 첫 프레임은 11:43:51.152이다.
플래너는 11:43:51.409에 정지 상태에서 미결정으로, 11:43:51.660에 진행으로 바뀐다.
영상 전환 구간을 고려하면 진행 판단까지 약 **0.51~0.56초**다.
해당 구간에는 가속/브레이크 페달 입력이 없다.

원본과 후보 모두 미래 속도가 상승하지만 후보의 상승 폭이 더 작다.
44.5~48초 비교 18개에서 10초 후 예측 속도 평균은 원본 11.978 → 후보 10.474 m/s다.
이는 후보가 실제 차량을 더 늦게 출발시켰다는 결과가 아니다.

### 2. 녹색으로 바뀌어도 정지 예측 유지: 18번 39~42초

학교 주변 교차로에서 적색은 39.30초까지 켜져 있고 39.35초부터 녹색이 보인다.
이후 프레임에서도 녹색 점등을 확인했다. 녹색 첫 프레임은 11:45:46.246이다.

| 사건 | 한국 시각 | 녹색 첫 프레임 이후 |
|---|---|---:|
| 녹색 첫 프레임 | 11:45:46.246 | 0 |
| 운전자 가속페달 입력 | 11:45:48.378 | 2.13초 |
| longitudinal control 비활성화 | 11:45:48.384 | 2.14초 |
| 플래너 정지 → 미결정 | 11:45:48.604 | 2.36초 |
| 플래너 진행 판단 | 11:45:48.858 | 2.61초 |

프레임 간격을 고려한 진행 판단 지연은 **2.61~2.66초**다. 정지 상태가 유지된 시간은
약 2.36초이며, 미결정 구간까지 모두 정지 상태였다고 표현하면 부정확하다.
가속페달 개입이 먼저 있었으므로 개입 없이 언제 출발했을지는 이 로그로 알 수 없다.
페달 입력 자체가 모델 출력 변화를 일으켰다는 인과관계도 확정할 수 없다.

녹색 전환 후 페달 개입 전 39.4~41.3초의 비교 9개에서 10초 후 예측 속도 평균은
원본 **0.832 m/s**, 후보 **0.136 m/s**다. 후보도 진행으로 전환하지 못했고 오히려
정지에 가까워졌다. 기존 후보가 신호 상태를 더 잘 구분한다는 근거가 아니다.

### 3. 학교 주변 접근에서 정지/진행 상태가 세 번 짧게 반복

17번의 정지 상태 진입은 1.857, 5.413, 10.563초이며, 각각 2.208, 5.857,
11.115초에 진행 상태로 돌아온다. 이후 12.114초부터 정지 판단이 지속된다.
처음의 가속페달 입력은 1.026초에 끝나고 세 번의 반복 동안 추가 페달 입력은 없다.

원본 미래 거리/속도가 함께 흔들리는 장면이다. 실제 신호등이 이 간격으로 색을
바꿨다는 뜻은 아니다. 횡단보도, 도로 형태, 먼 신호가 함께 보이므로 특정 시각
요소를 원인으로 지목하려면 별도 입력 변화 시험이 필요하다. 후보에서도 뚜렷한
해결 효과를 확인하지 못했다.

### 4. 귀환 중 두 교차로 접근에서 강한 정지 예측

- 19번 23~29초: 25.948초에 실제 약 38.8 km/h인데 10초 후 예측 속도는
  원본 2.512 → 후보 2.205 m/s다. 당시 가속 명령은 -1.770 m/s²다.
  가속페달 입력은 28.334초에 시작된다. 이후 좌회전한다.
- 19번 47.5~53초: 49.948초에 실제 약 41.6 km/h인데 10초 후 예측 속도는
  원본 1.648 → 후보 0.860 m/s이며 가속 명령은 -2.903 m/s²다.
  51.948초에는 원본 0.142 → 후보 -0.446 m/s까지 낮아진다.
  가속페달 입력은 52.979초, 브레이크 입력은 56.397초에 시작된다. 이후 우회전한다.

영상에는 가까운 교차로 구조물과 먼 신호가 함께 있다. 도로/광각 및 연속 프레임
확인만으로 가까운 교차로에서 차량에 적용되는 신호 색을 확정하지 못했다.
따라서 이 두 건은 **정지 예측과 감속이 확인된 검토 대상**이며, 녹색을 적색으로
오인했다고 정답 처리하지 않는다. 특히 후보는 두 번째 구간의 정지 편향을 강화한다.

### 5. 앞차 뒤 정지/출발은 별도 분리

13~14번의 녹색 망을 씌운 트럭 뒤 대기/출발에서는 앞차가 신호를 가린다.
앞차 움직임에 따른 예측과 신호 색에 따른 예측을 분리할 수 없으므로,
이를 독립적인 적색/녹색 인식 성공 사례로 세지 않았다.

## 후보의 적색 대기 개선과 한계

차량이 정지했고 이후 10초 동안에도 적색이 유지되는 구간만 골랐다.
전환 직전 10초는 제외했다. 여기서만 10초 후 속도 목표 0을 사용했다.

| 구간 | 비교 수 | 원본 v10 절대오차 | 후보 v10 절대오차 | 후보 v10 음수 비율 |
|---|---:|---:|---:|---:|
| 15번 45~60초 + 16번 0~34초 | 245 | 0.444 m/s | 0.222 m/s | 95.1% |
| 17번 30~60초 + 18번 0~29초 | 285 | 0.600 m/s | 0.117 m/s | 68.1% |

겉으로는 0에 가까워졌지만 과도하게 낮추는 현상이 동반된다. 첫 구간 중
15번만 보면 오히려 절대오차가 0.233 → 0.290 m/s로 증가한다.
적색 대기 오차 감소만으로 개선을 판정하면 녹색 진행 억제를 놓친다.
이 표는 선택 구간의 개방 루프 출력 비교이며, 전체 신호 인식 정확도나 사고율,
후보 제어 시 정지 거리/출발 시간을 뜻하지 않는다.

## 원인에 대해 말할 수 있는 범위와 다음 시험

모델은 신호 색을 직접 출력하지 않고 영상/시간 이력에서 미래 x/v/a를 예측한다.
이번에는 녹색이 보이는 동안에도 모델의 미래 이동 예측이 낮게 유지되는 현상을
확인했다. 파일 기록 누락이나 모델 frame ID 단절로 설명되는 장면은 아니다.
어떤 픽셀/특징 때문에 이런 예측을 했는지는 ONNX 구조나 출력 로그만으로 확정되지 않는다.

현재 후보는 앞선 적색 대기의 소수 라벨을 이용해 최종 종방향 출력층만 조정했다.
이번 새로운 녹색 사례는 그 방식이 충분하지 않음을 보여준다. 다음 시험은
이번 주행을 우선 고정 검증 세트로 남기고 다음을 확인해야 한다.

1. 적색 대기, 녹색 직후, 정상 진행, 앞차 출발, 회전을 사건 단위로 나눠 라벨링한다.
   적용 신호가 불확실한 두 교차로에는 색상 정답을 강제로 부여하지 않는다.
2. 기존 카메라 특징으로 적색과 녹색을 구별할 수 있는지 별도 진단한다.
   특징에 정보가 남아 있으면 출력층/시간 처리 개선을 시험하고, 부족하면 더 앞단의
   시각 특징 학습이나 별도 신호 인식 모듈까지 검토한다. 아직 결과는 없다.
3. 적색 오차뿐 아니라 녹색 반응 지연, 정상 진행 억제, 음수 출력, 반복 정지 판단을
   함께 평가한다. 출력을 단순히 0으로 잘라내도 녹색 전환 지연은 해결되지 않는다.
4. 이번 사건을 학습에 쓰게 되면 더 이상 독립 검증으로 세지 않고, 다른 날짜/교차로
   주행을 검증용으로 확보한다. 연속 프레임의 무작위 분할은 사건 누수를 만든다.

이번 분석에서는 모델 재학습, 제어 활성화, 출발 조건 수정 또는 차량 재설치를 하지 않았다.
현재 후보는 비교용으로 유지한다. 원본/후보 출력과 실제 동작을 구분하는 구조는
[시험 구성 문서](signal_shadow_trial_20261010.md)에 기록되어 있다.
