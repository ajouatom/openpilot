# 교량 이음새 구간의 SCC 보조 리드 오승인

`HYUNDAI_SANTA_FE_2022`, `00000092--d1a1129c12--69/rlog.zst`의
35.60초 급감속은 가까운 정지 반사점을 SCC 보조 L2로 승인한 데서 발생했다.
실제 앞차는 비전과 프런트 35번이 약 17m에서 계속 추적하고 있었다.

원본의 `initData`는 `carrot-wip / ce3d76301c`, `EnableRadarTracks=3`,
`EnableCornerRadar=0`이다. 사건 전후 설정 업로드에서도 두 값은 같았다.
전체 cereal 스키마로 `can`, `carState`, `liveTracks`, `modelV2`, `radarState`,
`longitudinalPlan`, `carControl`을 확인했다. CUT-IN 후보나 예비감속 승인이
이번 급감속의 진입 경로는 아니었다.

| 재생 시점/항목 | 확인된 기록 |
| --- | --- |
| 약 35.30초 | SCC 물체 거리가 약 16.3m에서 6.0m로 전환 |
| 35.55초 | 프런트 39번이 4.25m에서 L2로 승인 |
| 35.60초 | 정상 L1 16.97m, 비전 16.40m / 확률 0.9999, 잘못된 L2 4.14m, SCC 3.7m |
| 35.55–36.05초 | 잘못된 L2가 11개 모델 프레임 동안 유지, 거리는 4.25m에서 0.72m로 감소 |
| 감속 계획 | `longitudinalPlanSource=lead1`로 전환. 여기서 `lead1`은 두 번째 리드 L2를 뜻함 |
| 감속 크기 | 계획 `aTarget` 최저 −4.14m/s², 액추에이터 가속 명령 최저 −4.0m/s², 실측 `aEgo` 최저 −2.91m/s² |
| 정상 앞차 | 해당 구간 내내 L1 프런트 35번 유지 |

프런트 39번의 절대 속도는 거의 0이고, 자차 접근 속도만큼 거리가 줄어든다.
`qRoadEncodeIdx`의 노출 시각과 순차 디코딩 프레임을 맞춰 확인한 영상에도
해당 근거리에는 차량이 없고 노면 이음새가 접근해 통과한다.
이음새 반사라는 해석과 일치하지만, 로그에는 반사체의 높이·재질을 확정할
정보가 없다. 잘못된 근거리 리드 승인과 그에 따른 감속은 제어 기록으로 확인된다.
순정 FCW는 켜졌으나 `stockAeb=false`, SCC 버스 2의 `aReqRaw=0`이었고,
openpilot의 종방향 제어는 활성 상태였다.

기존 `DPathSccLeadTwoTracker`는 저속 SCC 물체의 거리·속도가 0.15초 동안
연속되면 별도 L2 후보로 반환했다. `_scc_physical_support`가 같은 위치의
프런트 39번을 찾으면 그 프런트 거리·속도로 출력했다. 이 과정에는 같은
물체의 비전 또는 독립 코너 확인이 없었다. 해당 차량의 SCC 물체와 프런트
트랙 목록은 같은 전방 레이더에서 나온다. 두 출력의 일치는 같은 반사점을
잡았다는 뜻일 수 있으며, 차량임을 독립적으로 확인한 결과가 아니다.

수정은 모드 2·3의 저속 SCC 보조 L2 승인에 적용한다.

- 현재 비전의 위치·속도 매칭 또는 같은 물체의 실측 코너 확인이 있어야
  0.15초 확인 시간을 쌓는다. 프런트와 SCC만 일치하는 경우는 승인하지 않는다.
- 다른 이동 프런트에 이미 매칭된 비전을 정지 SCC 반사점에 다시 빌려주지 않는다.
- 코너 대응은 SCC 및 프런트와의 실제 거리·횡위치·속도로 확인한다.
  프런트/코너 쌍은 최대 5m 거리차, 1.25m 횡위치차, 2.5m/s 속도차를 사용하며,
  각각 SCC와도 기존 거리·속도 매칭 조건을 충족해야 한다.
- 먼 차량의 같은 프런트/코너 쌍이 계속 관측될 때는 모델 경로 흔들림만으로
  두 센서의 대응을 지우지 않는다. 프런트 또는 코너 값을 제어 출력으로
  선택할 때의 기존 경로 조건은 유지한다.
- 확인 완료 후 근거의 짧은 공백은 연속된 실측 SCC에 한해 최대 0.10초만
  허용한다. 거리·속도의 불연속이나 근거 시간 초과는 확인 상태를 초기화한다.

검증에는 이음새 구간의 잘못된 39번/0번 L1·L2 금지와 정상 35번 L1의 연속
유지를 함께 등록했다. SCC/프런트가 같은 반사점을 잡는 경우, 다른 차량의
비전을 빌리는 경우, 코너 대상·속도·횡위치 불일치, 실측이 아닌 코너, 확인
근거 공백과 물체 변경을 자동 테스트로 검사한다. 정상 정지차의 비전 확인과
먼 프런트/코너 쌍의 경로 흔들림도 함께 검사한다.

검증 결과와 재생 한계:

- 관련 자동 테스트 485개와 변경 Python 파일 Ruff 검사를 통과했다.
- 이음새 전후 32–39초의 140개 프레임에서 L1 출력은 수정 전과 동일하다.
  모드 2·3의 잘못된 L2 11개 프레임은 0개로 줄었다. 모드 1도 L1이 동일하다.
- 모드 2에서 `ioniq9-234-6-scc-corroborated-early-l2`의 먼 차량을 기존과 같은
  11.555초에 검출한다. 모델 경로 흔들림이 같은 차량의 센서 대응을 끊지
  않는지도 확인했다.
- 88개 로그의 477개 항목을 모드 2·3에서 각각 비교했다. 입력이 확인된 항목은
  269개, 대상 입력이 없어 미검증으로 남긴 항목은 208개다. 두 모드 모두
  실패가 12건에서 11건으로 줄었으며, 줄어든 한 건은 이번 이음새 사례다.
  기존 통과 항목의 새 실패, 새 예비감속 실패, 검출 시점의 20ms 초과 지연은
  없었다. 기존 11건의 실패는 해결됐다고 처리하지 않았다.
- 작업용 PC에서 1,198개 프레임을 수정 전후 교차로 각각 6회 실행했다.
  회당 프레임 평균 처리 시간의 중앙값은 1.569ms에서 1.563ms였다.
  차량 기기에서 측정한 처리 시간은 아니다.
- 전체 검증의 기존 미해결 실패와 대상 입력이 없는 라벨은 통과로 처리하지
  않는다. 아래 재현 명령의 JSON에서 `input_valid`, `shadow_pass`,
  `shadow_forbidden_lead_two`, 연속성 결과를 함께 확인해야 한다.
- 재생은 기록된 모델·센서 입력에 대한 리드 선택 비교다. 수정 후 실제 차량의
  감속 궤적을 재현한 폐루프 시험은 아니므로, 기록된 가속도 그래프를
  수정 후 감속 결과로 해석하지 않는다.

```powershell
.venv\Scripts\python.exe -X utf8 openpilot/selfdrive/carrot/radar/tools/validate_radar_lead_model.py --shadow-only --enable-radar-tracks 3 --report .tmp_radar_review/bridge_92_69/full-final-mode3.json
```

설정값이나 모드 선택을 변경하는 수정은 아니다. 사용자 가이드에 이미 명시된
새 정지 물체의 독립 확인 조건을 우회하던 보조 L2 경로를 보완한다.
모드 −1 및 모드 3의 명시적인 강제 SCC **L1** 정책은 이 수정에서 변경하지
않았다. 이 사건에는 정상 L1이 계속 존재했고, 문제가 된 경로는 별도 SCC L2였다.
