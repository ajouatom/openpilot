# S3 1.1.0 release and shutdown correction — 2026-10-15

The user's TURZX panel stayed on its manufacturer splash while C4 was offroad.
UART still answered: this was not evidence of a completely dead S3. Resetting the
S3 and receiving successful sync (10) and brightness-zero (14) replies restored
shutdown; the user confirmed the screen went off. The original missed command's
physical cause is not established.

The firmware marked itself dark even when local shutdown failed, suppressing
further attempts. It now synchronizes, waits 200 ms, checks the brightness reply,
retries failed shutdowns at 1/2/4/8/16 s, and reasserts idle-off every 30 s. Old
session commands cannot change current power state. Setup remains visible; a new
image wakes the display. This is backlight shutdown, not power removal.

C4 close synchronizes and checks shutdown; offroad periodic dimming now includes
the registered S3 even when no local USB display exists. Direct USB behavior is
preserved. The firmware watchdog also works when C4/network disappears.

## Distribution

- [NAS installer/guide](https://upload.shind0.synology.me/models/carrot-s3/index.html)
- [Firmware ZIP](https://upload.shind0.synology.me/models/carrot-s3/carrot-s3-1.1.0.zip)
- [Korean installation guide](../tools/esp32s3_display/INSTALL_KO.md)
- Supported hardware: ESP32-S3 N16R8 with 8 MB octal PSRAM, powered compatible hub,
  TURZX 9.2-inch 1cbe:0092, 1920×462. No generic USB-C/HDMI monitor support.
- Installer uses pinned Espressif esptool-js 0.5.6 with licenses; downloads are
  SHA-256 checked before writing and flash contents are MD5 checked afterward.
- Existing-install mode verifies partitions and writes only 0x10000 application.
  Initial-install mode writes bootloader/partition/app separately; neither erases
  NVS. Before/after NVS digest checks protect registration. There is no whole-flash
  image, private pairing, Wi-Fi password or device NVS in the distribution.
- `--auto` selects one supported USB UART without probing other devices, then
  verifies S3 identity. Cable insertion alone is not automatic registration.
- Public NAS route uses an explicit file allowlist and rejects symlink components;
  model and recording access policies are unchanged.

## Validation and limits

ESP-IDF 5.4.0 builds the final 874048-byte app. It was UART-flashed to the user's
N16R8; saved device identity and pairing key matched before/after. Each of normal
close, abrupt TCP loss and reconnect sent 50 acknowledged images over 5 s, with
zero USB failures. A longer visual repeat sent 150 images per phase over 15 s;
the user confirmed “켜졌다가 꺼짐.” The final stale-session guard was then rebuilt,
flashed and passed another three-phase 150-image check.

This validates the bench hardware and displayed wake/off behavior, not every USB
hub or vehicle shutdown scenario. Artificial USB ACK failure/backoff and panel-only
power-cycle fault injection are not physical test claims. The C4 host changes have
focused regression coverage; they do not alter models, driving control or eGPU.
Web Serial page rendering and cancellation are checked in Chrome; actual flash
verification above uses esptool UART. No claim of a completed browser-native flash
is implied by the page check. See release metadata for binary/source hashes.

Focused checks: 26 Wi-Fi/provision/close/offroad tests; 38 autorun/performance tests
with one Linux-only skip; 12 NAS viewer tests with eight Windows symlink-permission
skips; five JS installer/manifest tests. The latter reject corrupted downloads,
wrong chip/partition, NVS mismatch and writes outside allowed firmware sectors.

C4 shell validation found UART dependencies under the existing `pydeps` directory,
not the bare system/venv search path. Provisioning adds that bundled directory
when present; the guide uses `python3`, also available in a plain SSH shell.
The three matching-source S3 host files were backed up and installed on C4 after
56 fresh offroad/ignition-OFF/control-inactive checks. Only `carrot_cluster` was
restarted; model/DM were already stopped offroad. The installed native offroad
function discovered the registered S3 and successfully sent brightness zero.
Provisioning imports also pass with the ordinary `/usr/bin/python3` and no
inherited `PYTHONPATH`/`VIRTUAL_ENV`.
