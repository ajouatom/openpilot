# 정차 중 적색 출발 차단과 경고음

사용자는 적색을 표시하는 데서 끝내지 말고 자동 출발을 차단하고 경고음을
내도록 명시적으로 요청했다. 별도 `start_guard_enabled=1`을 선택한 장치에만
적용한다. 기존 `assist_enabled`는 OFF를 유지한다. 기존 주행 ONNX의 x/v를
재학습하거나 바꾸는 작업은 아니다.

## 동작

- 활성 종방향 제어, Drive, 유효한 차량 상태, 속도 절댓값 0.3 m/s 이하에서만
  적색 차단에 진입한다. 주행 중 새로운 감속/정지 요청을 만들지 않는다.
- 전방 영상 범위의 같은 위치에서 최신 적색 두 번, 최소 150 ms를 확인한다.
  관측 간격 상한은 700 ms. 신경망 색상 점수는 0.8 이상이며, 혼합 적색/화살표는
  적색, 순수 녹색만 녹색이다. CPU 경로는 현재 raw 색상과 세 번 이상 관측을 쓴다.
- 화면의 이전 색상 유지와 별도의 tmpfs 관측 파일을 사용한다. 캡처부터 650 ms
  이내 결과만 새 판단에 사용한다. 이는 실측 QCOM 결과 나이 평균 335 ms/최대
  400 ms를 위한 **정차 차단 전용** 값이며 기존 이동 중 보조의 200 ms를 바꾸지 않는다.
- 적색 차단 후 검출 누락·unknown·오래된 관측·일시적인 서비스 무효는 해제가 아니다.
  같은 적색 위치와 IoU 0.6 이상인 하나의 녹색 후보를 세 번, 최소 700 ms 확인해야
  해제한다. 다른 전방 적색이 함께 있으면 녹색 해제를 허용하지 않는다.
  최신 적색으로만 기준 위치를 갱신/재획득한다. 녹색으로 기준을 옮기지 않는다.
  관찰기 재시작 시 적색부터 재획득해야 하므로 신호가 이미 녹색이면 정지가 남을 수 있다.
- 차단은 앞차 출발, 원래 모델의 green 판단, 사용자 정지거리, blended 모드를
  우회하지 못하게 한다. 플래너 정지거리/목표속도 0, 최종 shouldStop=true,
  최종 vTargetNow=0, aTarget<=0을 사용하며 더 강한 기존 제동은 보존한다.
- 원래 모델이 green을 판단하거나 앞차/주행 상태가 출발 경로를 선택하려 하면
  `audioRefuse`를 정차 차단당 한 번 낸다. 기존 `refuse.wav`의 재생 횟수는 1이다.
  기존 경고 우선순위와 음량을 보존하며 다른 경고가 더 우선할 수 있다.
- 녹색은 이 추가 제약만 해제한다. 기존 모델이 계속 정지를 판단하면 출발하지 않는다.
  가속페달은 직접 조작으로 해제하고 10초 동안 재진입을 막는다. 제어 해제와
  Drive 이탈은 초기화한다. 브레이크만으로 녹색을 만들어내지 않는다.

## 검증

생산 CarrotPlanner 상태기계, 생산 종방향 플래너 최종 출력 코드, 관측 전달을
포함한 관련 검사 264개 통과, Linux 전용 검사 1개 생략. 기존 음성 이벤트 경로를
재사용하며 실제 스피커 청취와 주행 제동은 이 데스크톱 검증에 포함되지 않는다.

저장된 v4 관찰 결과 37개 세그먼트를 실제 과거 차량 상태/도착 시각과 함께
43,090회 플래너에 재생했다. 과거 야간 일부 도착 시각은 기존 분석의 150 ms
가정이다. 추가 지연 0 ms와 20 ms를 각각 검사했다.

| 구간 | 원래 출발 상태 횟수 | 차단 추가 후 | 비고 |
|---|---:|---:|---|
| 1091--12 | 49 | 0 | 정차 출발 차단 |
| 1091--16 | 59 | 0 | 정차 출발 차단 |
| 1095--65 | 51 | 0 | 실제 적색 오출발 신고 구간 |
| 1095--66 | 28 | 0 | 실제 적색 오출발 신고 구간 |
| 1091--20, 40–43 s | 4 | 4 | 속도 약 4.7 m/s로 정차 진입 대상 아님 |

두 지연 조건 모두 표의 출발 횟수는 같다. 검토된 적색에서 녹색 해제 0회.
검토된 녹색 848개 플래너 시점 중 정지 유지 141/143회가 남는다. 확인 대기와
검출 불확실성을 포함하며, 녹색 반응이 모두 정상이라는 뜻이 아니다.
1093--6/8의 해제는 각각 세그먼트 2.055/56.713초이다.

이 재생은 CPU 관찰 기록에 대한 제어 규칙 검사이며 새 신경망의 정확도 검증이나
차량 운동을 바꾼 폐루프 시뮬레이션이 아니다. 새 신경망 운용 속도/수치 동등성은
[GPU 실측 기록](signal_gpu_dual_model_20261011.md)에 별도로 정리했다.
적색 검출 실패, 잘못된 차로 신호 선택, 신호 가림/화살표 구분은 남아 있다.
전방 사각형 위치는 자차 신호라는 증거가 아니며 이 기능은 적색 오출발 방지를
보장하지 않는다. 원본 기록은 비공개 분석 폴더에 보관한다.

## 차량 설치와 실행 확인

Ioniq 5 PE, 192.168.0.178의 `carrot-signal-shadow`에 코드 `64b2a63c38`을
설치했다. 새 MDM 8d736683 선택은 유지한다. 공통 기능은 carrot-wip의
`d068dc2f25`와 `3c15d3322f`에 푸시했으며 wip 모델은 Cinque v3 그대로이다.
차량 Python 검사 124개, 최종 비정상 점수/직접 조작 보완 후 관련 120개도 통과했다.
pytest는 별도 비공개 폴더에만 설치했다.

최초 프로세스 재시작 검사는 차단 실행 로그를 확인하지 못했다. manager가
plannerd를 미리 import하는 경로를 확인하고 정상 P단 재부팅을 수행했다.
재부팅 후 실제 plannerd PID의 `signalStartGuard` 로그에서 enabled=true를
확인했다. 관찰 파일은 두 모드 모두 최신 카메라 timestamp로 갱신됐다.

| 최종 구성 | 검사 시간 | 유효 modelV2 / 누락 | 모델 평균 | 차단 플래너 로그 |
|---|---:|---:|---:|---:|
| eGPU + QCOM | 15초 | 300 / 0 | 36.58 ms | 15개 |
| 내부 모델 + CPU | 15초 | 300 / 0 | 25.02 ms | 15개 |
| eGPU 복귀 후 재확인 | 20초 | 401 / 0 | 36.64 ms | 20개 |

각 구간 약 20 Hz였다. 첫 복귀 대기 중 차량 상태 메시지의 생존 조건이 잠시
실패하여 해당 스크립트는 중단됐다. 이를 통과로 기록하지 않았다. P단·속도 0·
제어 비활성을 다시 확인한 후 별도의 읽기 검사를 실행하여 위 마지막 행을 확인했다.
최종 UsbGpuActive=true, UsbGpuStartupFailed=false, neural_backend=auto,
start_guard_enabled=1, assist_enabled=0이다. Park에서는 hold=false가 유지됐다.

실차에서 실제 적색에 대한 제동/녹색 출발 및 스피커 청취를 확인한 것은 아니다.
도로 검출 누락과 녹색 지연은 계속 기록해서 검토해야 한다.
