# 추가 주행을 이용한 신호 전환 학습과 재생 검증 — 2026-10-11

사용자는 최신 주행까지 학습·검증하고, 같은 신호등의 밝기·색상·점등 위치 변화와
기존 ONNX의 x·v를 함께 이용할 수 있는지 확인해 달라고 요청했다. 자료는 이미 PC에
수집·무결성 확인되어 시동을 꺼도 오프라인 작업을 진행할 수 있다고 안내했다.

이번에는 보조 색상 판독 모델의 **실제 가중치 학습**과, 녹색 확인을 잃던 **코드 수정**을
각각 수행했다. 원래 주행 ONNX는 재학습·교체하지 않았고 x·v를 수정하지 않는다.
학습한 모델은 분석용이며 차량 제어 경로에 연결하지 않았다. 차량 파일·설정·프로세스도
변경하지 않았다. 기존 차량 설치 상태는 이전 조사 문서를 참조한다.

## 학습한 내용과 결과

고정된 신호 영역에서 현재 적색/녹색 점수, 좌우 밝기, 이전 관측 대비 변화,
과거 적색 관측 대비 변화를 추출했다. 추가 입력은 **카메라 시각 이전에 게시된**
유효한 모델의 x[-1], v[0], v[-1] 및 변화량이다. 모델 정답을 재사용하지 않고
직접 영상으로 판독한 적색/녹색을 학습 목표로 사용했다.

- 5개 정차/전환 encounter, 총 679개 관측. 2개 encounter 280개는 학습,
  나머지 3개 399개는 가중치 학습·정규화에서 제외했다. 최신 야간 1093의 5/6 구간이
  학습에 포함되며, 8 구간과 아침 1094의 3/4 구간은 평가에 사용했다.
- 3/4 및 5/6처럼 이어지는 같은 정차는 하나의 encounter로 묶었다.
  같은 도로 재방문이 있을 수 있고 이미 검토한 영상이므로 새로운 장소·블라인드 검증은 아니다.
- 세 모델 모두 L2=0.01의 로지스틱 회귀. encounter/색상별 동일 가중치,
  학습률 0.08, 2,500회 전체 배치 경사하강. 학습에서만 정규화 평균/분산을 산출했다.
  녹색 점수 ≥0.90, 적색 점수 ≤0.10을 채택하고 나머지는 보류했다.
  이 점수는 실제 도로에서 보정된 확률이 아니다.

| 입력 | 평가 적색 370개 중 적색 확정 | 평가 녹색 29개 중 녹색 확정 | 반대 색상 확정 |
|---|---:|---:|---:|
| 현재 색상·밝기 | 270 | 21 | 0 |
| 현재 + 과거 변화 | 311 | 21 | 0 |
| 현재 + 과거 변화 + x·v | 370 | 21 | 0 |

나머지는 보류다. 야간 평가 녹색 21개는 모두 맞았지만, **아침 녹색 8개는 세 모델 모두
보류했다.** x·v를 더해 적색 보류가 줄어드는 사례는 있었으나 이번 시험에서 녹색 추가
이득은 확인하지 못했다. 상관된 연속 프레임의 개수이며 독립 교차로 수나 일반 정확도가 아니다.

이는 **정답 신호 위치를 제공한 색상 분류 시험**이다. 자동 위치 검출, 자신의 차로에 적용되는
신호의 선택, 실제 출발 성능을 검증하지 않는다. 학습 모델로 기존 x·v가 개선되었다거나
차량 제어용 신규 ONNX가 만들어졌다고 해석하면 안 된다. 재현 CLI는
`tools/signal_analysis/train_transition_probe.py`; 세 JSON 가중치와 데이터는 비공개 보관한다.

초기 정답 영역 QA에서 예전 1091-12의 접근 중 위치 변화를 발견했다. 해당 잘못된 ROI의
초기 데이터/결과는 `annotation_qa_rejected/`로 분리했다. 정차 구간과 올바른 상자로
수정한 뒤 같은 학습 방식·분할·기준으로 다시 학습한 위 결과만 유효한 결과로 사용한다.
평가 영상은 이미 확인했으므로 이를 튜닝과 무관한 미공개 시험으로 표현하지 않는다.

## 녹색 미출발 코드 수정

1. 관측 연속성 허용 간격을 기존 객체 만료 상한인 250ms와 일치시켰다.
   150~200ms 관측마다 색상 확인이 다시 시작되던 125ms 조건을 제거했다.
   현재 색상의 **연속 관측 횟수**를 별도로 세어, 오래된 전체 관측 횟수로 세 프레임
   확인 조건을 통과하지 못하게 했다. unknown/반대 색은 연속 근거를 끊는다.
2. 계산 결과 하나가 200ms를 초과했다는 이유만으로 객체와 worker session을 버리지 않는다.
   소비자의 200ms 입력 나이 제한은 그대로다. 카메라 간격 250ms 초과, 역순 시각,
   재연결, 잘못된 입력 등은 기존대로 추적을 초기화한다. 늦은 결과로 출발하지 않는다.
3. 같은 객체의 색상 지지 시작 시각·연속 횟수를 전달한다. 이미 선택한 적색 객체가
   raw/확정 green이고 적색 이력이 있으며, 최종 관측이 fresh/age=0이고
   400ms 이상·3개 이상 연속 녹색 근거를 갖추면, 소비자가 다시 별도의 400ms 확인을
   완주할 필요 없이 기존 차단을 해제한다. 정보가 없는 구버전은 기존 확인 경로를 쓴다.
4. 템플릿 추적도 같은 간격을 사용하되, 템플릿은 직전 이미지에서 실제로 본 객체에만
   적용한다. 이전에 놓친 객체의 상자를 새 이미지 템플릿으로 잘못 사용하지 않는다.

새 객체의 녹색이나 worker 재시작 후 녹색으로 기존 정지를 풀지 않는다.
원래 모델·플래너가 출발을 판단해야 하며, 보조기는 가속을 명령하지 않는다.
기존 실험 opt-in 기본 OFF, 적색 진입 조건, CPU duty 정책은 유지된다.

## 실제 간격·전달 지연을 사용한 재생

최신 야간 11개·아침 12개 구간의 전체 road 영상을 순서대로 디코드하고,
실제로 관측기가 처리했던 10,631개 카메라 프레임만 새 추적기에 입력했다.
정답 영역은 이 자동 검출·추적 경로에 제공하지 않았다. 로그의 실제 결과 게시 시각을
사용해 소비 시점의 200ms 제한까지 적용했다. 구간 사이에도 객체 상태를 유지했다.

Carrot 상태 머신은 기록된 입력으로 26,441개 모델 갱신을 실행했다.
모드/차량 입력은 기록값, 저장 Params 일부는 기존 재생 도구 기본값이며 내비게이션과
모드 추론 등은 대체했다. 실제 MPC·액추에이터·차량 반응·변경된 후속 카메라 영상은
재현하지 않는다. worker 누락/재연결 이벤트 전체를 모사한 실제 장치 실행도 아니다.
따라서 아래는 같은 입력에서의 소프트웨어 상태 변화이며 물리적인 출발 시간 보장은 아니다.

| 알려진 실패 | 도우미 차단 해제 | 이후 기존 출발 상태(e2eCruise) | 그 시점 가속페달 |
|---|---:|---:|---|
| 1093-6, 약 1초에 녹색 | 구간 1.803초 | 2.300초 | 누르지 않음 |
| 1093-8, 약 56초에 녹색 | 구간 56.414초 | 56.913초 | 누르지 않음 |

직접 확인한 활성 적색 1,552개 플래너 프레임에서는 녹색 해제가 0개였다.
직접 확인한 활성 녹색 159개 중 helper hold는 기록상 128개에서 재생 20개로 줄었다.
해제 순간에도 기존 플래너의 정지 상태가 잠시 남으며, 이후 원래 전환 절차를 따른다.
모든 교차로의 적색 오출발 0회나 전체 주행 성공을 의미하지 않는다.

과거 1091의 12/14/16/17/20/21 구간 영상도 다시 실행했다. 150/200ms 교대 관측 간격과
150ms 가정 전달 지연에서, 기존 적색 오출발 세 창의 **활성 프레임** 중 비정지 상태가
각각 49/59/4개에서 0/0/0개로 줄었다. 전체 재생 14,242 프레임의 도우미 OFF 출력은
원본 참조 플래너와 일치했다. 이전 검토 영상의 회귀 시험이며 새로운 일반화 검증이 아니다.

### 통과하지 못한 조건

- 과거 시험의 전달 지연을 180ms로 바꾸면 카메라 시각과 소비 주기의 위상 때문에 일부
  결과가 200ms를 넘는다. 세 창의 활성 비정지 상태는 49/0/4개로 남는다.
  helper가 아예 적색 차단을 걸지 못한 경우도 있어, hold가 적다는 이유로 개선이라 볼 수 없다.
- 최신 재생에 50ms를 추가하면 1093-8 해제가 59.260초로 늦어진다.
  1093-6은 차단 자체를 획득하지 않아 녹색 hold가 없어진다. 이는 성공적인 해제가 아니다.
- 따라서 처리/전달 지연의 여유는 아직 부족하다. PC 관측 계산 p50/p95/p99는
  약 6.96/10.70/12.94ms이지만 C4 처리 성능을 입증하지 않는다.
  실제 장치에서 같은 부하의 처리 시간·관측 간격을 별도로 측정해야 한다.

## 아침 신호 미검출

1094-3 frame600의 실제 신호 위치를 포함한 dark contour는 threshold45에서
1036×249px, 나머지 threshold에서는 장면 전체에 가까운 크기로 합쳐졌다.
나무/구조물과 연결된 외곽선이 크기·비율 조건에서 탈락하며 실제 신호 후보가 없다.
이는 해당 프레임의 구체적인 후보 생성 실패 증거이며, 모든 주간 누락 원인의 단정은 아니다.
새 학습 모델을 붙여도 후보에 없는 신호를 분류할 수 없다. 주간 신호 위치 검출과
점등 배치 차이를 다루는 후보 생성 개선이 남는다. 이번 코드에서 검출 임계값을 무작정
완화하거나 다른 밝은 물체를 신호로 강제 채택하지 않았다.

결론은 두 가지다. 알려진 야간 미출발은 코드 수정으로 재생상 개선했다.
밝기·색상 변화와 x·v를 함께 학습하는 시험도 수행했으나, 주간 녹색 개선과 충분한
지연 여유는 확인하지 못했다. 이번 수정과 학습판은 **차량 미반영**이며, 바로 주행해도
된다는 판정이 아니다. 다음 검증은 추가 주행 수집보다 주간 후보 개선과 주차 상태의
장치 처리 지연 확인이 우선이다.
