## Memory warning with HUD

MemTotal is 3607.11 MiB. Segment 3 begins with 527.54 MiB available (85% used)
and ends with 366.44 MiB (about 90%). Segment 4 remains at 90%, with available
memory 364.97 -> 359.64 MiB. Segment 7 begins at 347.54 MiB; carrot_cluster
starts at +20.839 s and lowMemory/softDisable appears at +24.783 s. Usage
oscillates between 90% and 91%, ending with 339.04 MiB available. The warning
is the existing low-memory threshold, not a recorded MemoryError or OOM kill.

The experiment's warm internal-model worker remains resident after Jetson
activation: approximately 576 MiB RSS / 553 MiB sampled PSS. It is retained
for fallback, not freed on connection. Jetlink also starts display, navigation,
Wi-Fi and camera-preview helper processes. By segment 7 their sampled PSS is
about 35.05, 31.02, 30.65 and 35.43 MiB respectively. These PSS values refresh
periodically, not at every two-second procLog snapshot. RSS must not be summed
as private memory. The local HUD waiter has approximately 10 MiB PSS, rather
than the roughly 91 MiB suggested by its shared-page-inclusive RSS.

Two common resource corrections:

1. Freeze jetlinkd's startup GC graph once, before creating USB-session state.
   The existing full collection before each connection otherwise traverses
   objects inherited from the forked manager and can create private copies of
   their pages. Session-created cycles remain collectible. Recorded jetlinkd
   PSS rises from about 5 to 45 MiB around attachment, consistent with this
   mechanism, but the log does not attribute individual pages. The principle
   is described in [Python's GC documentation](https://docs.python.org/3/library/gc.html#gc.freeze).
2. Create the camera-preview helper only while the host HUD's existing display
   gates permit output. Stop it when those gates close. Vehicle/settings
   snapshots continue, so enabling the HUD still reaches the host. This avoids
   preparing JPEG previews for a hidden display; it does not remove the memory
   cost of previews while the HUD is actually enabled.

No memory threshold, alert, DM policy, camera/pose validity criterion, model
artifact, control behavior or HUD frame rate is relaxed. Actual memory savings
and sufficient headroom with the experiment plus an enabled HUD need device
validation; these changes are not a demonstrated cure for all lowMemory alerts.

## Additional experiment-only fallback defect

Source review found that JoiningModel's native-history reset assumed `.npy`
and `.input_queues`, which the separate carrot-test worker adapter does not
provide. A Jetson failure after activation could therefore fail while restoring
the internal model. This failure is not observed in the supplied segments.

The common wrapper accepts an explicit native `reset()` hook. Only carrot-test
implements it using an acknowledged worker command that zeros existing JIT
history buffers, hidden features and parent desire history. The warm worker,
weights and captured buffer identities remain; timeout/bad acknowledgement
still fails explicitly. The ordinary carrot-wip queue-reset path is unchanged.
