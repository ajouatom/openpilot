## Compatibility and recovery

The PR does not itself modify tinygrad, but its baseline pins a newer runtime than
our previous d3f09c9 package. Keep that upstream-matched runtime isolated from the
internal driving model and DM. Existing byte-addressed input adapters and persistent
buffer loading remain applicable.

Source inspection of 02e69816 confirms USBIface.sleep is still a no-op,
AMDDevice.sleep_timeout_ms remains 200, usb_reap still polls with zero timeout and
copies the asynchronous status through usb_fail, and usb_setup binds AMD.error_state
to the USB link error word. Therefore add only this exact runtime hash to the existing
1 ms spin / 200 us sleep adaptation and exact +/-1 transport-error classification.
Unknown runtimes and other codes remain blocked. Retry limits, reboot/identity and
artifact/smoke checks, response deadlines, worker disposal, fallback, validity and
control policies are unchanged. Existing diagnostic events are retained. One existing
fallback-handler test needed its log_event stub updated for the earlier diagnostic change.
