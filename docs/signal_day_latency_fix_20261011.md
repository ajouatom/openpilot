# 아침 신호 검출·처리 지연 수정 시도와 검증 — 2026-10-11

사용자는 검증을 요청했는데 계속 남아 있다고 설명하는 이유와, 수정할 의미가 없어 시도하지 않는 것인지 물었다.
이전 작업의 재생 검증은 이미 수행했으며 아침 검출 실패와 지연 취약성을 확인했다.
이번에는 그 실패를 대상으로 실제 수정안을 만들고 영상 재생과 차량의 격리된 P단 계산 시험을 수행했다.

**결과는 부분 개선이며, 주행용 채택은 보류한다.** 아침 지하차도 앞 적색→녹색 사례는 개선됐지만,
다른 아침 구간에서 녹색으로 바뀐 뒤에도 보조 정지 요구가 남는 실패를 발견했다.
새 검출기는 `SignalTracker(daytime_cores=True)`로 명시적으로 선택하는 분석용 시험 경로에만 남긴다.
실제 worker의 기존 `SignalTracker()` 호출은 기존 검출 방식을 유지한다. 공개 차량 설정은 추가하지 않았다.
원래 주행 ONNX, x·v, 소비자의 200ms 신선도 제한, 정지·출발 조건은 변경하지 않았다.

## 무엇을 수정하고 시험했는가

기존 주간 검출은 어두운 신호등 외곽을 찾는다. 1094-3의 신호등은 배경과 어두운 영역이 붙어
하나의 큰 외곽으로 잡혀 실제 신호등 후보를 놓쳤다. 시험안은 전방 영역의 작은 밝은 적색·녹색 점을
먼저 찾고, 옆의 꺼진 등 부분이 어둡고 주변과 대비되는지 확인해 가로 신호등 상자를 추정한다.
단순 색상 점, 큰 색상 면, 혼합 색상은 제외한다. 정답 위치를 입력하지 않고 전체 카메라 영상에서 찾는다.
이 상자는 추정치이며 신호등 종류나 자차에 적용되는 차로를 증명하지 않는다.

처음 만든 주간 후보는 차량에서 계산 시간이 늘어 폐기했다. 전방 영역 제한, 작은 밝은 성분 선별,
적색·녹색 연결 성분 계산 공유로 다시 구현했다. 중복 흑백 변환과 일반 percentile 준비 작업도 줄였다.
수학적으로 같은 percentile/threshold 계산 최적화만 기본 경로에 적용한다.
새로운 가중치 학습은 이번 작업에 없으며, 앞선 세 분류기 학습 결과는
[이전 학습 기록](signal_transition_training_20261011.md)에 별도로 보존한다.

## 실제 영상과 플래너 재생 결과

최신 야간 1093의 11개 구간과 아침 1094의 12개 구간, 총 23개 영상을 다시 처리했다.
관측기가 실제 처리했던 10,631개 카메라 프레임과 기록된 전달 시각을 사용했고,
구간 사이의 추적 상태를 유지했다. 정답 영역을 검출기에 주지 않았다.
Carrot 상태 머신에는 실제 기록 입력을 사용해 26,441개 모델 갱신을 재생했다.
물리 차량·MPC의 반응이나 감속으로 달라지는 후속 카메라 영상은 재현하지 않는 고정 입력 재생이다.

| 확인 항목 | 결과 |
|---|---|
| 아침 1094-3의 놓쳤던 적색 | frame 600에서 실제 적색 후보를 검출 |
| 같은 정차의 녹색 전환, 1094-4 | frame 474, 구간 23.788초에 같은 추적 대상의 녹색으로 보조 제한 해제; 가속페달 입력 없음 |
| 앞서 고친 야간 두 녹색 정차 | 1093-6의 1.803초, 1093-8의 56.414초 해제 결과 유지 |
| 기존 야간 영상 추적 결과 | 5,190개 관측의 state/tracks가 앞선 수정본과 정확히 일치 |
| 직접 판독한 기존 적색 창 | 활성 플래너 1,552프레임에서 녹색 해제 0회; 전체 신호의 정확도를 뜻하지 않음 |
| 새 아침 정지 요구 진입 | 5회; 각 진입 프레임의 선택 대상은 영상에서 실제 켜진 적색 계열 신호등으로 확인 |
| 새 아침 녹색 해제 | 1회, 실제 녹색을 영상으로 확인 |

**채택을 막은 실패:** 1094-8은 frame 631에서 주행 중 적색과 모델 정지 거리를 근거로 보조 정지 요구를
설정했지만, 이후 추적 대상이 사라져 `selected_track_missing`이 됐다. frame 1000의 영상은 녹색인데
`red_sign=True`, 원래 플래너 상태 2 대비 시험 상태 3이었다. frame 1000–1059의 활성 60갱신 동안
정지 요구가 유지됐고, frame 1060의 비활성/무효 상태에서 초기화됐다. 해당 60갱신 전체를 별도의
수작업 색상 정답으로 집계하지는 않았다. 이 결과는 실제 차가 그 방식으로 감속했다는 뜻이 아니라,
수정안을 넣었을 때 기록 입력 재생에서 불필요한 정지 요구가 남았다는 뜻이다.

따라서 적색 후보가 늘었다는 것만으로 성공이라고 할 수 없다. 현재 정책은 추적을 잃었다는 이유로
이미 설정한 정지를 풀지 않으며, 다른 새 녹색 대상으로 해제하지 않는다. 이를 무조건 풀도록 바꾸면
적색 오출발 방지 목적을 훼손하므로 이번 검출 개선을 실차 경로로 승격하지 않았다.

나머지 새 정지 요구 중 1094-0은 녹색 해제 이전에 비활성/운전자 입력이 겹쳤고,
1094-9·10도 비활성/무효 상태로 끝났다. 네 사례를 자동 출발 성공으로 세지 않는다.
진입·해제 장면 외에도 종료 주변 영상을 확인했으며, 그 자료와 플래너 출력은 비공개 증거에 보관했다.

## 차량에서 실행한 처리 지연 시험

차량은 Park, 속도 0, 제어 비활성을 확인한 뒤 별도 `/data/signal-replay-20261011-day-latency` 폴더에서만
시험했다. 생산 코드·ONNX·설정·실제 관측 결과 파일을 바꾸지 않았다. nice19, 코어 0–3,
OpenCV 한 스레드, CPU duty 제한을 사용했고 매 반복에 차량 상태를 확인했다.

첫 주간 구현은 detect 벽시계 p50/p95가 약 126.8/178.3ms로, 기존 69.6/114.0ms보다 느려 폐기했다.
최종 후보의 detect 시험은 기존 69.0/95.4ms 대비 61.4/87.4ms였다. 작은 표본이며 큰 단발 지연도 있었다.

더 직접적인 시험에서는 실제 카메라 프레임을 받아 NV12→RGB 복사까지 수행한 뒤,
미리 저장한 세 장의 이미지로 바꾸어 알려진 검출 부하를 실행했다. 결과는 **시험 폴더**에만 게시하고,
그 이후 첫 실제 `longitudinalPlan` 발행 시각까지의 카메라 EOF 나이를 계산했다.
이는 소비 시점의 보수적인 근사이며, 실제 플래너가 시험 출력을 소비한 것은 아니다.
실시간 신호 인식 정확도 시험도 아니다. 기존/후보/기존 순서로 각 10초씩 실행했다.

| 카메라 EOF → 다음 플래너 발행 | 기존 방식 | 주간 시험안 |
|---|---:|---:|
| 관측 수 | 150 | 107 |
| 중앙값 | 156.2ms | 113.0ms |
| 95백분위 | 207.1ms | 162.8ms |
| 200ms 초과 | 12/150 | 0/107 |

처리 지연을 줄일 여지는 실측으로 확인했다. 그러나 **이 수치는 채택하지 않은 주간 시험안의 결과**이며,
기본 경로의 최적화만으로 같은 개선을 얻었다고 주장하지 않는다. 별도 시험이 생산 관측기와 함께 실행됐고
저장된 세 이미지·짧은 P단 부하이므로 모든 도로 장면의 지연 상한을 보장하지 않는다.

기존 기록 전달 시각을 그대로 고정한 재생에 50ms를 더하면 이전 야간 취약성이 여전히 나타난다.
1093-8의 녹색 해제는 59.260초로 늦어지고 1093-6은 해제 이벤트가 없다.
그 사례의 hold가 적다는 것은 성공이 아니라 적색 진입을 놓쳤을 수 있다는 의미다.
계산 최적화를 했다고 고정 입력의 전달 시각까지 개선됐다고 가정하지 않았다.

## 코드 검증·보관·적용 상태

관련 코드 테스트 **324개 통과**. 이는 추적, 실시간 전달, 플래너 연계, 기존 정지 조건 및 관련 회귀 테스트의
통과이지 324개 신호등을 정상 인식했다는 뜻이 아니다. 배경과 붙은 작은 신호등, 단독 색상 점 배제,
큰 색상 면 배제, 같은 신호의 적색→녹색과 초기 녹색 금지, percentile 동등성,
실제 worker 기본 호출에서 주간 시험을 선택하지 않는 조건을 추가했다.

시험 프로토타입과 정리된 구현의 10,631개 관측 출력은 계산 시간 필드를 제외하고 정확히 일치했다.
이후 명시적 분석 전용 선택 인자를 추가했으며, 최종 기본/시험 경로는 동결된 기존/후보 구현과
23개 구간의 459개 영상 표본에서 비교해 모두 일치함을 확인했다. 재현 결과와 코드 해시는
비공개 `guard_parity.json`, `summary.json`에 기록한다.

비공개 증거: `.analysis/archive/2026-10-11-signal-day-latency/`.
원본 영상은 기존 `2026-10-11-signal-followup`과 `2026-10-10-signal-night` 보관본을 참조한다.
차량 생산 브랜치의 주행 코드에는 이번 수정안을 설치하지 않았고, 격리 시험 프로세스는 종료됐다.
이번 검증은 끝냈으며 결과는 **지연과 한 아침 전환은 개선, 전체 주간 보조 제어 채택은 실패**다.
