# Tesla 차량 연동

carrotpilot은 지원되는 Tesla Model 3와 Model Y에서 차량 속도, 조향 상태, 가속 페달 및 브레이크 입력을 CAN으로 확인합니다. 차종·연식·차량 하드웨어에 맞는 하네스를 사용해야 하며, 필수 CAN 메시지가 유효하지 않으면 안전을 위해 제어를 시작하지 않습니다.

## 브레이크 입력 호환성

일부 기존 차량은 iBooster 상태 메시지 `0x39D`를 전송하지만, 신형 Model Y를 포함한 일부 차량에는 이 메시지가 없습니다. carrotpilot은 지원 차량에 공통으로 존재하는 `0x145 ESP_status`의 운전자 브레이크 상태를 사용합니다.

이 신호는 다음 두 계층에서 동일하게 사용됩니다.

- 차량 상태는 브레이크 페달이 눌렸는지 판단합니다.
- Panda 안전 계층은 브레이크 입력을 독립적으로 확인하고, 주행 중 운전자가 브레이크를 밟으면 제어 허용 상태를 해제합니다.

`0x39D IBST_status not valid`가 반복되면서 `canValid`가 거짓이 되는 이전 동작은 신형 차량에 없는 메시지를 필수로 요구한 호환성 문제입니다. `0x145`도 수신되지 않거나 카운터·체크섬·주기가 유효하지 않다면 하네스 연결과 CAN 배선을 확인하고, 브레이크를 누른 구간이 포함된 주행 로그를 제공해야 합니다.

> 이 변경은 브레이크를 직접 제어하는 방식이 아니라 운전자의 브레이크 입력을 감지하는 CAN 소스를 통일한 것입니다.

## 크루즈 설정속도 자동 조절

지원되는 Tesla 차량에서 추가 차량 CAN 버스가 연결·감지된 상태로 **alpha longitudinal**(`AlphaLongitudinalEnabled`)을 켜면 크루즈 설정속도 자동 조절도 함께 활성화됩니다. 크루즈와 carrotpilot이 작동 중일 때 차량 DAS가 전달하는 제한속도에 맞춰 설정속도를 조절합니다. 별도의 Carrot Web 토글은 없으며, 순정 가감속 제어를 사용하는 차량에서는 작동하지 않습니다.

내비게이션·Carrot 속도 제어가 활성 상태이면 이를 우선하고 DAS 기반 설정속도 조절을 일시 중지합니다. 해당 제어가 끝나면 DAS 제한속도가 다시 안정적으로 유지되는지 확인한 뒤 재개하며, 수동 휠 조작에 따른 중지는 그대로 유지합니다. 속도 제어 없이 내비게이션만 연결된 상태에서는 이 기능을 중지하지 않습니다.

제한속도가 안정적으로 유지되면 차량 표시 단위에 따라 1km/h 또는 1mph씩 조절합니다. 조절 사이에는 최소 0.5초를 두고, 차량의 설정속도 변경을 확인한 뒤 다음 조작을 보냅니다. 제한속도 정보가 없거나 오래되었을 때, 브레이크를 밟을 때, 취소하거나 제어를 해제했을 때는 자동 출력을 멈춥니다.

- 오른쪽 속도 휠을 직접 돌리면 자동 조절을 일시 중지합니다. 제한속도 정보가 잠시 끊긴 동안의 수동 조작도 유지하며, 새 제한속도가 들어와도 이 중지를 해제하지 않습니다.
- 다시 자동 조절하려면 휠을 한 방향으로 돌린 뒤 1초 안에 반대 방향으로 돌립니다. 제어를 해제했다가 다시 켜도 수동 조작에 따른 중지가 해제됩니다.
- 차량이 속도 변경에 응답하지 않으면 동일한 목표·설정속도에 대해 계속 재시도하지 않습니다.

## 자동 방향지시등

`TeslaAutoTurnSignals`는 기본 꺼짐이며 재부팅 후 적용됩니다. 추가 차량 버스와 유효한 실제 스토크 입력이 있는 Model 3/Y에서 기존 ATC 회전·차로변경 판단에 따라 회전 준비 단계부터 방향지시등을 요청합니다. 내비게이션을 켜거나 차로변경 조건·조향·출발 권한을 변경하지 않습니다. 스토크가 없거나 신호 구성이 다른 차량은 설정만으로 지원되지 않습니다.

확장선 감지는 자동 크루즈 속도 휠과 공유하며 CAN1의 `0x3DF` 수신이 필요합니다. 속도 휠이 동작하더라도 램프 제어용 `0x3E9` 유휴 템플릿과 UI·실제 램프 피드백은 별도로 필요합니다. 스토크는 수신된 CAN1을 우선하고 CAN1에서 해당 신호를 한 번도 받지 않은 경우 CAN0과 호환됩니다. 오래되거나 서로 충돌하는 입력은 자동 출력을 차단합니다. 짧은 App 차로변경 명령의 램프 요청도 기존 동작이 끝날 때까지 유지합니다.

원본 CAN의 다른 필드를 보존하며 동작 완료나 제어 상실 시 자동 요청을 명시적으로 취소합니다. 운전자 조작을 우선하고 자동 램프 피드백과 취소 잔여 신호를 운전자 확인으로 사용하지 않습니다. 신선한 UI·실제 램프 OFF 확인이 필요하며 고장·수신 불가를 성공으로 간주하지 않습니다. 상태는 `carState.autoTurnSignalStatus`와 `tesla_auto_turn_signal` 이벤트에 기록됩니다. 취소를 확인하지 못하면 다음 주행 시작까지 자동 출력을 중지합니다. CAN 단절이나 장치 전원 상실 시 실제 소등을 보장할 수 없습니다.

동작 중 반복 요청마다 새 유휴 템플릿과 TX 에코 확인이 필요하며, 템플릿이나 램프 피드백을 잃으면 계속 정상 동작한다고 표시하지 않고 자동 세션을 종료합니다. 회전 램프는 조향 판단의 조기 회전 종료 플래그와 별개로 실제 회전 시작과 안정적인 직진 복귀를 확인합니다. 실제 스토크·비상등 조작이나 예상하지 않은 반대쪽 램프가 감지되면 자동 출력을 즉시 멈추고, 운전자 램프를 끄지 않도록 신선한 스토크 중립과 양쪽 램프의 안정된 OFF 이후로 취소를 미룹니다. 출처를 모르는 램프만으로 차로변경을 확인하지 않습니다.

`blocked:vehicle_bus_unavailable`는 확장선 미감지, `blocked:driver_input_unavailable`는 실제 입력 누락·시간 초과·충돌을 뜻합니다. `waiting:body_template`, `waiting:ui_feedback`, `waiting:front_feedback`는 램프 제어에 필요한 수신 상태를 구분합니다. `blocked:restart_required`는 현재 CarParams에 켜진 설정이 반영되지 않았음을 뜻합니다. 화면 경고가 아닌 기록용 진단이며, 일치하는 Panda 펌웨어는 여전히 필요합니다.

일반 도로 사용 전 해당 차량의 폐쇄된 시험장에서 좌우 램프, 운전자 개입, 비상등, 완료 및 고장 처리를 확인해야 합니다. 다른 Tesla 제어와 신호등 출발 제한은 그대로 유지됩니다.

## 협조 조향과 타이어 공기압

협조 조향은 운전자가 가한 조향 토크를 계획 조향각에 반영하고, 제어를 켤 때 조향을 점진적으로 적용하며, 조향각 제한에 도달하면 과도하게 쌓인 보정량을 줄입니다. 기존 EPS 개입 조건과 조향각 제한은 계속 적용됩니다.

차량 버스에서 공기압 정보가 수신되면 네 바퀴의 공기압을 화면에 제공합니다. 센서의 수신 불가 값은 공기압 수치로 표시하지 않습니다.

## 제어 진입과 정차 조향

Tesla의 정차 여부는 순정 크루즈 상태와 별개인 차량 ESP 신호로 확인합니다. 지원 Tesla 차량에서는 주행 제어가 활성 상태이거나, 전진 기어에서 `AlwaysLateral`을 사용하고 조향 상태가 켜져 있으면 실제 정차 중에도 조향할 수 있습니다. 조향 고장이나 조향 OFF 상태에서는 동작하지 않으며, 이동 중에는 최소 조향 속도 제한을 계속 적용합니다.

정상적인 순정 TACC 작동은 Autosteer 충돌로 판단하지 않습니다. 차량에서 Autosteer 설정을 제공하는 경우 Autosteer·FSD 설정은 꺼져 있어야 하며, 기존 조향 충돌 검사도 계속 적용됩니다. 순정 ACC의 유휴 상태가 계속 수신되어도 새 스토크 조작에 의한 제어 진입을 반복 취소하지 않고, 실제 ACC 작동·정차 유지 상태에서 취소 상태로 바뀔 때는 취소를 짧게 전달합니다.

## 깨우기와 주차 상태

유효한 Tesla 전원 신호가 수신되면 액세서리·컨디셔닝 상태에서도 장치를 깨워 둘 수 있으며, 이 신호만으로 주행 화면에 진입하지는 않습니다. R·N·D에서는 주행용 시동 상태를 켜고, P에서 안전벨트가 풀려 있거나 문이 열리면 주행 화면을 종료합니다. 벨트를 착용하고 문을 닫은 P 상태에서는 이전 시동 상태를 유지하므로 P 전환만으로 항상 주행 화면이 종료되는 것은 아닙니다.

깨우기 신호와 시동 신호는 해당 CAN 메시지가 끊기면 각각 만료됩니다. 이 상태는 장치 전원과 주행 화면을 결정하며, 그 자체로 차량 제어를 켜지는 않습니다.
