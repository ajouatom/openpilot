# Tesla 차량 연동

carrotpilot은 지원되는 Tesla Model 3와 Model Y에서 차량 속도, 조향 상태, 가속 페달 및 브레이크 입력을 CAN으로 확인합니다. 차종·연식·차량 하드웨어에 맞는 하네스를 사용해야 하며, 필수 CAN 메시지가 유효하지 않으면 안전을 위해 제어를 시작하지 않습니다.

## 브레이크 입력 호환성

일부 기존 차량은 iBooster 상태 메시지 `0x39D`를 전송하지만, 신형 Model Y를 포함한 일부 차량에는 이 메시지가 없습니다. carrotpilot은 지원 차량에 공통으로 존재하는 `0x145 ESP_status`의 운전자 브레이크 상태를 사용합니다.

이 신호는 다음 두 계층에서 동일하게 사용됩니다.

- 차량 상태는 브레이크 페달이 눌렸는지 판단합니다.
- Panda 안전 계층은 브레이크 입력을 독립적으로 확인하고, 주행 중 운전자가 브레이크를 밟으면 제어 허용 상태를 해제합니다.

`0x39D IBST_status not valid`가 반복되면서 `canValid`가 거짓이 되는 이전 동작은 신형 차량에 없는 메시지를 필수로 요구한 호환성 문제입니다. `0x145`도 수신되지 않거나 카운터·체크섬·주기가 유효하지 않다면 하네스 연결과 CAN 배선을 확인하고, 브레이크를 누른 구간이 포함된 주행 로그를 제공해야 합니다.

> 이 변경은 브레이크를 직접 제어하는 방식이 아니라 운전자의 브레이크 입력을 감지하는 CAN 소스를 통일한 것입니다.

## 크루즈 설정속도 자동 조절

지원되는 Tesla 차량에서 추가 차량 CAN 버스가 연결·감지된 상태로 **alpha longitudinal**(`AlphaLongitudinalEnabled`)을 켜면 크루즈 설정속도 자동 조절도 함께 활성화됩니다. 크루즈와 carrotpilot이 작동 중일 때 차량 DAS가 전달하는 제한속도에 맞춰 설정속도를 조절합니다. 별도의 Carrot Web 토글은 없으며, 순정 가감속 제어를 사용하는 차량에서는 작동하지 않습니다.

내비게이션·Carrot 속도 제어가 활성 상태이면 이를 우선하고 DAS 기반 설정속도 조절을 일시 중지합니다. 해당 제어가 끝나면 DAS 제한속도가 다시 안정적으로 유지되는지 확인한 뒤 재개하며, 수동 휠 조작에 따른 중지는 그대로 유지합니다. 속도 제어 없이 내비게이션만 연결된 상태에서는 이 기능을 중지하지 않습니다.

제한속도가 안정적으로 유지되면 차량 표시 단위에 따라 1km/h 또는 1mph씩 조절합니다. 조절 사이에는 최소 0.5초를 두고, 차량의 설정속도 변경을 확인한 뒤 다음 조작을 보냅니다. 제한속도 정보가 없거나 오래되었을 때, 브레이크를 밟을 때, 취소하거나 제어를 해제했을 때는 자동 출력을 멈춥니다.

- 오른쪽 속도 휠을 직접 돌리면 자동 조절을 일시 중지합니다. 제한속도 정보가 잠시 끊긴 동안의 수동 조작도 유지하며, 새 제한속도가 들어와도 이 중지를 해제하지 않습니다.
- 다시 자동 조절하려면 휠을 한 방향으로 돌린 뒤 1초 안에 반대 방향으로 돌립니다. 제어를 해제했다가 다시 켜도 수동 조작에 따른 중지가 해제됩니다.
- 차량이 속도 변경에 응답하지 않으면 동일한 목표·설정속도에 대해 계속 재시도하지 않습니다.

## CAN 빨간불 정지

`TeslaCanTrafficStop`는 독립적인 기본 꺼짐 설정이며 변경 후 재시작합니다. Model 3/Y에서 **openpilot 종제어가 실제 활성일 때만** 작동하며 순정 TACC나 `AlwaysLateral`만으로는 작동하지 않습니다. 자동 방향지시등·데이터 공유·ONNX 차선 분류·신호 보조와 별개이고 다른 차종은 저장값이 켜져 있어도 무시합니다.

입력은 버스 2의 `0x25D`, 정확히 8바이트인 미터 단위 `APP_trafficControl`입니다. 기능 available/active, 비전 출처·신호등 플래그, 억제·사용 불가 사유 없음, 알려진 색이 필요합니다. 6바이트 `DAS_road`는 거리 배율이 달라 차단하며 주소나 연식만으로 지원을 추정하지 않습니다. `carState.teslaTrafficControl`에 유효성·원본 수신 시각·거리·색·상태를 기록하고 선택형 메시지 누락은 CAN 고장으로 만들지 않습니다.

서로 다른 빨간불 최소 3회가 0.2초 이상 이어지고 양의 정지선 거리가 126m 미만이면 정지 제약을 추가합니다. 임시 목표는 보고된 선 2m 전이므로 실차 거리 기준을 먼저 확인해야 합니다. ACC·blended 모두 다른 장애물·모델·수동 정지를 유지하고 모델 예측이나 레이더 선행차를 위조하지 않습니다. CAN 정지 중 blended는 더 강한 모델 제동을 유지하면서 임시로 ACC 정지 계산을 사용하고 해제 후 선택 모드로 돌아갑니다. 제동 한계·Panda 권한은 늘리지 않으며 앞차 출발만으로 해제하지 않습니다.

같은 목표의 연속 초록불 최소 3회·0.5초로 이 제약만 해제합니다. 획득 후 거리가 0이어도 정차 유지를 계속하지만 0만으로 새 정지를 시작하지 않습니다. 노랑·불명은 초록이 아닙니다. 제약 유지 중 0.5초 수신 만료·목표 거리 불일치·시계 불연속이면 기존 soft-disable로 인계를 요청하고 인계 중 기존 정지 목표를 유지합니다. 결국 제어가 해제되므로 운전자가 제동·인계해야 하며 무기한 자동 유지를 기대하지 마세요. 선을 5m 넘게 지난 이전 목표는 교차로 안에서 재사용하지 않습니다.

페달 조작 후에는 현재 제어 세션에서 억제되며 해제·재진입과 새 표본이 필요합니다. 가까운 빨간불은 제동 능력을 넘을 수 있고 화면·소리 경고도 정지를 보장하지 않습니다. 원인·진행은 `tesla_can_traffic_stop`에 제한된 주기로 기록하며 새 HUD 배지는 없습니다. 미지원·누락 입력에서는 이 기능으로 정지할 수 없습니다.

**실험 기능이며 실차·도로 검증이 아닙니다.** 해당 차량의 원시 CAN·거리 기준·현재 진행 방향 관련성·제동 권한을 확인하고 폐쇄 시험장에서 신호 전환·앞차 출발·수신 단절·운전자 인계·근거리 변화를 검증하세요. 소프트웨어 테스트만으로 일반 도로에서 켜지 마세요.

## 자동 방향지시등

`TeslaAutoTurnSignals`는 기본 꺼짐이며 재부팅 후 적용됩니다. 추가 차량 버스와 유효한 실제 스토크 입력이 있는 Model 3/Y에서 회전 램프는 내비게이션 준비나 거리 조건만으로 켜지지 않고 기존 회전 desire가 시작될 때 요청합니다. 자동 차로변경은 준비 중 램프를 요청하고 해당 송신·점등을 확인한 뒤 시작합니다. 내비게이션을 켜거나 다른 차로변경 조건·조향·출발 권한을 변경하지 않습니다. 스토크가 없거나 신호 구성이 다른 차량은 설정만으로 지원되지 않습니다.

확장선 감지는 자동 크루즈 속도 휠과 공유하며 CAN1의 `0x3DF` 수신이 필요합니다. 속도 휠이 동작하더라도 램프 제어용 `0x3E9` 유휴 템플릿과 UI·실제 램프 피드백은 별도로 필요합니다. 스토크는 수신된 CAN1을 우선하고 CAN1에서 해당 신호를 한 번도 받지 않은 경우 CAN0과 호환됩니다. 오래되거나 서로 충돌하는 입력은 자동 출력을 차단합니다. 짧은 App 차로변경 명령의 램프 요청도 기존 동작이 끝날 때까지 유지합니다.

원본 CAN의 다른 필드를 보존하며 ATC/App 동작 완료나 제어 상실 시 해당 요청을 명시적으로 취소합니다. 아래의 이동 중 램프 전용 허용은 크루즈와 별개입니다. 운전자 조작을 우선하고 자동 램프 피드백과 취소 잔여 신호를 운전자 확인으로 사용하지 않습니다. 신선한 UI·실제 램프 OFF 확인이 필요하며 고장·수신 불가를 성공으로 간주하지 않습니다. 상태는 `carState.autoTurnSignalStatus`와 `tesla_auto_turn_signal` 이벤트에 기록됩니다. 취소를 확인하지 못하면 다음 주행 시작까지 자동 출력을 중지합니다. CAN 단절이나 장치 전원 상실 시 실제 소등을 보장할 수 없습니다.

동작 중 반복 요청마다 새 유휴 템플릿과 TX 에코 확인이 필요하며, 템플릿이나 램프 피드백을 잃으면 자동 세션을 종료합니다. 완료는 모델 예측이나 조향 판단의 조기 종료 플래그가 아닌 신선한 `livePose` 실측 방위를 사용합니다. 해당 방향 조향 30도와 방위 회전 20도에 도달하고 최대 조향이 30도를 초과한 뒤, 1km/h 이상 이동 중 핸들이 15도 이내로 돌아오면 램프 요청을 종료합니다. 정차 중 방위 변화·반복 자세·불연속·누락은 완료 근거가 아닙니다.

송신·점등을 이미 확인한 회전만 실제 정차 중 횡방향 출력이 꺼져도 유지할 수 있습니다. 신선한 횡방향 허용 스위치와 활성 제어 또는 `AlwaysLateral`, 정상 자세, 조향 고장 없음, D 및 기존 램프 조건이 계속 필요합니다. 새 정차 요청이나 차로변경에는 적용하지 않습니다. 다음 회전은 현재 완료와 유효한 회전 desire를 기다리며 대기 cue는 3초 안에만 인계합니다. 같은 방향은 요청 ID를 유지하고 반대 방향은 기존 취소·OFF 확인을 거칩니다. 거리 증가로 판단한 다음 cue는 경로 식별의 진실값이 아니며, 기존 60초 상한은 늘리지 않습니다.

실제 스토크·비상등 또는 예상 밖 반대 램프는 자동 출력을 즉시 멈추며 신선한 스토크 중립·양쪽 램프의 안정된 OFF 이후 취소합니다. 운전자가 해당 방향 조향 30도 이후 반대 토크로 이동 중 핸들을 0도 너머로 넘기면 회전 램프 요청을 중단합니다. 출처 불명 램프는 차로변경 확인이 아닙니다. PC 검증만으로 실제 차량의 세 번 점멸 이후 지속 점등을 보장하지 않습니다.

`blocked:vehicle_bus_unavailable`는 확장선 미감지, `blocked:driver_input_unavailable`는 실제 입력 누락·시간 초과·충돌을 뜻합니다. `waiting:body_template`, `waiting:ui_feedback`, `waiting:front_feedback`는 램프 제어에 필요한 수신 상태를 구분합니다. `blocked:restart_required`는 현재 CarParams에 켜진 설정이 반영되지 않았음을 뜻합니다. 화면 경고가 아닌 기록용 진단이며, 일치하는 Panda 펌웨어는 여전히 필요합니다.

일반 도로 사용 전 해당 차량의 폐쇄된 시험장에서 좌우 램프, 운전자 개입, 비상등, 완료 및 고장 처리를 확인해야 합니다. 다른 Tesla 제어와 신호등 출발 제한은 그대로 유지됩니다.

### 선택형 차로변경 램프 관찰

세 Tesla 전용 옵션은 서로 독립적이며 기본 꺼짐, 변경 후 재부팅이 필요합니다. 모두 `TeslaAutoTurnSignals`와 기존 차량 CAN·실제 스토크·램프 피드백, ONNX 차선 분류를 실행하는 **데이터 공유**(`ShareData`), 30km/h 이상이 필요합니다. 시각 BSD의 `OnnxBsdEnabled`는 별개이며 켤 필요가 없습니다. ONNX 모델·추론 주기·임계값은 바뀌지 않습니다.

- `TeslaManualLaneSignals`: 지속된 운전자 토크와 양쪽 경계의 일관된 접근을 확인하면 스토크 없이 좌우 램프만 요청합니다. 크루즈·횡제어 비활성도 허용하나 단순 보정이나 의도·접근 근거 없는 일반 곡선은 대상이 아닙니다.
- `TeslaModelDesireSignals`: 횡제어 활성 상태에서 우세한 차로변경 예측이 서로 다른 모델 프레임 최소 4개·0.2초 이상 유지되면 램프를 요청합니다.
- `TeslaModelPathSignals`: 독립적으로 횡제어 활성 상태에서 차선 곡률 대비 경로의 반복된 경계 통과 예측으로 요청합니다. 두 예측 옵션은 내비 회전 안내를 사용하지 않으며 회전·유턴 예측을 추가하지 않습니다.

좌우 모두 서로 다른 ONNX 점선 갱신 최소 2회·0.2초 간격, 완료 시각 기준 0.8초 이내 결과와 신뢰 가능한 안팎 차선·도로 경계 여유가 필요합니다. 기본 400ms 추론 주기는 유지합니다. 실선·불명·무효·미래·오래된 결과는 새 자동 요청을 차단하나 실제 스토크 동작은 막지 않습니다. **실선/점선은 흰색/노란색이나 같은 진행 방향의 증거가 아닙니다.** 형상으로 합법적인 차로 진입·빈 공간·안전한 통과를 입증하지 못합니다.

ONNX 시각은 **카메라 촬영이 아닌 추론 완료 시각**이므로 전체 영상 나이 상한은 아닙니다. 신선하고 유효한 모델도 필요하며 같은 원본 시각을 반복해 확인 횟수를 늘리지 않습니다. 모델 단절은 확인을 초기화합니다. 예측은 미리 또는 잘못 점등할 수 있으며 모든 차로변경 감지·타이어 경계 통과 전 점등을 보장하지 않습니다.

조향 desire나 횡제어 활성 상태를 변경하지 않으며 별도 요청 ID로 ATC/App 조향 확인을 대신하지 않습니다. 기존 ATC/App 요청·수명 주기가 우선하며 내비 회전 사전점등·거리 추가 기능은 없습니다. 자동 램프 피드백은 실제 스토크 입력으로 처리하지 않습니다. 운전자·비상등·무효 상태·차선 근거 상실·경계에서 복귀·통과 완료 시 관찰을 종료하며 상한은 12초입니다. 기존 실행기의 60초 상한과 TX/OFF 취소 확인·실패 세션 재시도 금지는 유지됩니다. PC 검증은 실제 램프·도로 검증이 아닙니다.

## 협조 조향과 타이어 공기압

협조 조향은 운전자가 가한 조향 토크를 계획 조향각에 반영하고, 제어를 켤 때 조향을 점진적으로 적용하며, 조향각 제한에 도달하면 과도하게 쌓인 보정량을 줄입니다. 기존 EPS 개입 조건과 조향각 제한은 계속 적용됩니다.

차량 버스에서 공기압 정보가 수신되면 네 바퀴의 공기압을 화면에 제공합니다. 센서의 수신 불가 값은 공기압 수치로 표시하지 않습니다.

## 제어 진입과 정차 조향

차량 CAN 확장이 있으면 순정 화면의 세 손가락 접촉으로 `AlwaysLateral`을 0과 1 사이에서 전환하며 다음 제어 주기에 바로 반영됩니다. 다음 접촉 전 손을 떼어야 하며 유지·중복 눌림은 반복 전환하지 않습니다. 실험/Chill 모드는 바꾸지 않고 `ExperimentalModeConfirmed`도 필요하지 않습니다. 기존 초기값과 저장값을 유지합니다.

끄면 크루즈와 독립적인 횡방향 허용만 해제하며, 주행 제어가 활성 상태이면 조향은 계속 작동할 수 있습니다. 비상 해제나 종방향 제어 전환용 조작이 아닙니다.

Tesla의 정차 여부는 순정 크루즈 상태와 별개인 차량 ESP 신호로 확인합니다. 지원 Tesla 차량에서는 주행 제어가 활성 상태이거나, 전진 기어에서 `AlwaysLateral`을 사용하고 조향 상태가 켜져 있으면 실제 정차 중에도 조향할 수 있습니다. 조향 고장이나 조향 OFF 상태에서는 동작하지 않으며, 이동 중에는 최소 조향 속도 제한을 계속 적용합니다.

정상적인 순정 TACC 작동은 Autosteer 충돌로 판단하지 않습니다. 차량에서 Autosteer 설정을 제공하는 경우 Autosteer·FSD 설정은 꺼져 있어야 하며, 기존 조향 충돌 검사도 계속 적용됩니다. 순정 ACC의 유휴 상태가 계속 수신되어도 새 스토크 조작에 의한 제어 진입을 반복 취소하지 않고, 실제 ACC 작동·정차 유지 상태에서 취소 상태로 바뀔 때는 취소를 짧게 전달합니다.

## 깨우기와 주차 상태

유효한 Tesla 전원 신호가 수신되면 액세서리·컨디셔닝 상태에서도 장치를 깨워 둘 수 있으며, 이 신호만으로 주행 화면에 진입하지는 않습니다. R·N·D에서는 주행용 시동 상태를 켜고, P에서 안전벨트가 풀려 있거나 문이 열리면 주행 화면을 종료합니다. 벨트를 착용하고 문을 닫은 P 상태에서는 이전 시동 상태를 유지하므로 P 전환만으로 항상 주행 화면이 종료되는 것은 아닙니다.

깨우기 신호와 시동 신호는 해당 CAN 메시지가 끊기면 각각 만료됩니다. 이 상태는 장치 전원과 주행 화면을 결정하며, 그 자체로 차량 제어를 켜지는 않습니다.
