# 레이더트랙·코너레이더

[English](../en/radar.md)

> [!NOTE]
> 이 문서는 `carrot-wip` 코드와 함께 관리하는 사용자 설명서 원본입니다. 사용자 동작이 바뀌면 관련 코드·테스트와 같은 변경에서 이 문서도 갱신합니다.

레이더가 차량에 장착되어 있어도 carrotpilot이 필요한 CAN 메시지를 읽을 수 있다는 뜻은 아닙니다. 같은 차종도 연식, 옵션, 레이더 부품, 펌웨어, 메시지 그룹과 하네스 연결 위치에 따라 결과가 달라집니다.

> [!WARNING]
> 검증되지 않은 레이더 설정은 경고등, CAN 오류, 선행차 오인식 또는 잘못된 끼어들기 판단을 일으킬 수 있습니다. 변경 전 원래 값을 기록하고 정확히 같은 차량 구성이 검증됐을 때만 한 단계씩 시험하세요.

<a id="front-radar"></a>
## 전방 레이더 트랙

`EnableRadarTracks`는 전방 선행차 정보의 원본과 추가 처리를 선택합니다.

| 값 | 현재 코드의 의미 | 사용 판단 |
|---:|---|---|
| `-2` | VOACC 비전 전용 시험 | 개발 시험용 |
| `-1` | SCC를 항상 사용 | 차량 구성 확인 필요 |
| `0` | 순정 SCC 레이더 사용 | 기본값 |
| `1` | 전방 레이더의 원시 트랙 사용 | 차량별 레이더 활성화와 메시지 지원 필요 |
| `2` | 레이더 트랙과 저속 SCC 병행 | 검증된 동일 구성에서만 시험 |
| `3` | 위 기능에 끼어들기·스텔스 차량 처리를 추가 | 오검출 가능성이 있는 실험 기능 |

비-CAN FD 현대·기아 차량에서 양수 값을 사용하면 시작 과정에서 레이더 트랙 활성화를 시도하고 결과를 `EnableRadarTracksResult`에 저장합니다. 물리적인 레이더가 있어도 활성화 결과와 실제 트랙 수신을 함께 확인해야 합니다.

<a id="corner-radar"></a>
## 코너 레이더

| `EnableCornerRadar` | 의미 |
|---:|---|
| `0` | 사용하지 않음 |
| `1` | 지원되는 코너 레이더 트랙 사용 |
| `2` | 코너 레이더를 이용한 끼어드는 차량 검출 추가 |

코너 레이더 객체는 차량 코드가 인식한 지원 메시지 그룹이 있을 때만 생성됩니다. 지원되는 0x430 메시지군도 전방 레이더가 아닌 코너 레이더 입력으로 구분됩니다. 현재 `2`의 끼어들기 처리는 현대 계열을 중심으로 동작하므로 다른 제조사에 같은 값을 일반화하면 안 됩니다.

<a id="lead-fusion"></a>
## 센서 분리 레이더 모델

| `RadarLeadModelMode` | 의미 |
|---:|---|
| `0` | 기존 선행차 선택 방식 |
| `1` | 전방·코너 레이더를 독립적으로 판정하는 센서 분리 모델 방식 |

`RadarLeadModelMode=1`은 차량 또는 장치를 다시 시작한 뒤 적용됩니다. 레이더 트랙 수신 여부와 별개로 모델의 선행차 선택 방식이 달라지므로 동시에 여러 설정을 바꾸지 마세요.

모델 방식에서도 `EnableRadarTracks`가 전방 모델 입력을 결정합니다. `-1`과 `0`은 SCC만, `1`은 전방 레이더 트랙만, `2`와 `3`은 전방 레이더 트랙과 저속 SCC를 사용합니다. SCC와 전방 레이더 입력은 코너 레이더 모델에 섞이지 않습니다.

전방 모델과 코너 모델은 이력과 판정 상태를 서로 공유하지 않습니다. 코너 레이더가 있는 차량은 전방 모델로 `leadOne`을 찾고 코너 모델로 끼어들기·보조 리드를 찾으며, 코너 레이더가 없으면 전방 모델이 보조 판정까지 담당합니다. 코너 후보와 같은 전방 포인트가 확인되면 거리·속도·가속도는 전방 포인트를 사용하되, 5 m 이내 측면 후보는 노이즈가 큰 전방 횡위치 대신 코너 측정값을 유지합니다. 다만 동일 차량이 두 번 보고되지 않도록 객체 식별 연결은 유지합니다.

전방과 코너 모델 파일은 서로 분리해 학습하고 검증합니다. PC 검증기에서 `--front-only`를 지정하면 코너 포인트를 제거하고, 코너 레이더가 없는 디바이스와 같은 전방 단독 경로로 검증합니다.

비전의 거리 불확실성이 커도 현재 주행 경로에서 벗어난 최신 레이더 포인트는 `leadOne`으로 연결하지 않습니다. 같은 위치의 후보가 이미 `leadOne`이면 보조 리드에서 중복 제거합니다. 전방 레이더와 연결되지 않은 원거리 코너 후보는 차량 차체가 차로 경계에 닿기 전에는 잠정 끼어들기로도 보고하지 않아 평행 주행 차량과 옆 차로 차량의 오검출을 줄입니다.

센서 분리 모델 방식은 전방 레이더 단독 끼어들기 후보의 횡이동이 여러 이력 구간에서 일관될 때만 확정합니다. 전방·코너 레이더가 함께 확인한 작은 표적은 비전 횡위치가 짧게 흔들려도 기존 매칭을 유지하여 선행차 끊김을 줄입니다.

정지차는 비전 확률이 충분하고 전방·코너 레이더가 거리 3 m, 횡위치 1.2 m 이내의 같은 경로상 물체를 함께 확인할 때 센서 간 속도 오차를 허용합니다. 옆 차량이나 멀리 떨어진 이동 포인트는 정지차 근거로 합치지 않으며, 전방 매칭이 있으면 제어용 거리·속도·가속도는 전방 레이더 값을 유지하여 터널 입구와 구조물 반사에 의한 급감속을 억제합니다.

코너 레이더 끼어들기 판정은 일반적으로 시간 모델의 확률과 차선·차체 진입 형상이 함께 조건을 만족해야 확정됩니다. 다만 6 m 이내의 코너 전용 차량이 여러 이력 구간에서 의미 있는 속도로 계속 차로 안쪽으로 움직이고 기본 모델도 강하게 동의하면 2프레임 조기 확정을 사용합니다. 이력 구간이 여러 개라는 사실이나 약한 차선 상대 흔들림만으로는 조기 확정하지 않습니다. 기본 모델의 한 프레임 점수만으로도 확정하지 않으며, 이 제한은 커브와 평행 주행 차량의 순간 오검출을 줄입니다.

전방 레이더가 순간 횡속도를 제공하지 않는 차량에서는 0.4초와 0.6초의 차선 상대 이동이 모두 진입 방향으로 일치할 때 차선을 완전히 밟기 전 끼어들기 후보로 확인합니다. 횡속도가 정상 수신되는 표적에는 이 보강 조건을 적용하지 않아 평행 주행 차량의 오검출을 억제합니다.

모델 방식은 전방 레이더와 아직 연결되지 않은 코너 레이더 후보를 `잠정(TENTATIVE)` 끼어들기로 구분할 수 있습니다. 5 m 이상의 원거리 후보뿐 아니라, 모델 확률은 낮아도 5 m 이내에서 여러 이력의 차로 안쪽 이동과 차체의 차로 경계 진입이 함께 확인된 초근접 후보도 잠정 상태로 먼저 보고합니다. 잠정 상태에서는 실제 거리는 유지하되 자차와 같은 속도, 0 가속도로 종방향 제어에 전달하여 저속 대기 중 측면 차량이나 불확실한 후보로 인한 급감속을 줄입니다. 전방 레이더 매칭 또는 충분한 모델 근거로 확정된 후보는 `확정(CONFIRMED)` 상태로 실제 레이더 속도와 가속도를 사용합니다.

PC 검증기 `radar_lead_validation_review.py`는 잠정 및 확정 끼어들기 모두에서 일시정지하며, 우측 결과와 일시정지 사유에 `TENTATIVE` 또는 `CONFIRMED`를 표시합니다.

### PC 궤적 검증 화면

PC 검증기는 같은 로그에 여러 검증 구간이 있어도 로그 창을 한 번만 열고 모든 구간을 타임라인에 표시합니다. 레이더 그래프의 횡방향은 실제 비율보다 4배 확대됩니다. `POINTS`는 현재 실측 레이더 포인트를, `PATH`는 최근 궤적과 0.25초 간격의 미래 예상 위치를 표시합니다. 포인트의 `IN`은 현재 경로 밖 차량이 0.5/1.0/1.5/2.0초 뒤 경로를 점유할 최대 확률이고, `OUT`은 현재 경로 안 차량이 같은 시점들에 경로를 벗어날 최대 확률입니다. 자차가 차선을 바꾸어 앞차가 새 자차 경로에서 벗어나는 경우도 `OUT`에 포함되므로 “PATH-EXIT”으로 해석합니다. 상세 패널에는 네 시점의 원시 경로 점유 확률이 모두 표시되며, `H`는 선택한 표시 시간의 별도 기하학적 점유 추정입니다. `IN`이 `PROB` 슬라이더 설정값 이상이면 포인트를 초록색 이중 원과 `!` 접두사로 강조하고 자동 검증 재생도 그 포인트에서 소리와 함께 일시정지합니다. `leadOne`이 있으면 그보다 먼 포인트는 원시 확률과 이력은 계속 표시하지만 `L` 상태로 구분하여 강조·소리·일시정지·끼어들기 후보에서 제외합니다. `X`는 PATH-EXIT 임계값을 넘은 상태입니다. `PROB`를 바꾸면 현재 로그의 자동 정지 이벤트를 즉시 다시 계산하며, 타임라인이나 왼쪽 키로 과거로 이동하면 이후 이벤트를 다시 판정하여 같은 지점에서도 다시 정지합니다.

마지막 `PROB` 값은 PC 사용자 설정에 저장되어 다음 로그와 다음 실행에서 그대로 사용됩니다. 매번 지정할 필요는 없으며, 명령행에서 처음부터 지정하려면 `radar_lead_validation_review.py --prob 0.70`처럼 사용합니다. 이 값은 PC 검증 화면의 강조와 자동 정지 기준만 바꾸며 실제 디바이스의 제어 임계값은 바꾸지 않습니다.

전방과 코너 모델은 별도 파일로 학습됩니다. 입력은 현재 포인트와 과거 실측 이력뿐입니다. 정답은 물리적으로 연속된 같은 track의 0.5/1.0/1.5/2.0초 뒤 실제 위치가 그때의 자차 경로를 점유하는지로 만들며, 현재 경로 밖인 샘플만 골라 강제하는 방식이 아닙니다. 미래 실측값은 정답 생성에만 쓰고 추론 입력으로 사용하지 않습니다. `measured=false`인 전방 레이더 빈 슬롯과 물리적으로 끊긴 재사용 ID는 제외합니다. 사람이 지정한 `CUT-IN`/`CLEAR`와 그 로그 전체는 학습에서 제외하고 검증에만 사용합니다.

현재 전체 로그 검증에서는 고정밀 CUT-IN 임계값의 재현율이 너무 낮아 새 모델의 자동 `leadTwo` 승격을 front/corner 모두 비활성화했습니다. 모델은 디바이스와 PC에서 같은 특징·가중치·후처리로 계속 추론하고 화면에 표시합니다. 고정밀 검증을 통과한 전방/SCC `OUT`만 비전이 이미 `leadOne` 매칭을 잃은 뒤의 짧은 stale hold를 해제하는 데 사용합니다. 현재 `leadOne`을 직접 제거하거나 TF를 줄이지 않으며, 코너 `OUT`은 표시와 평가에만 사용합니다.

`radar_lead_validation_review.py --trajectory-table-only`는 수동 라벨 평가와 함께 분기점 `carrot-wip` 기존 판정 대 새 path-occupancy 최종 shadow 판정을 표시합니다. 사람이 넓게 지정한 구간의 영향을 확인할 수 있도록, 동일 구간에서 로그의 실제 미래 경로 진입을 정답으로 바꾼 비교표도 이어서 출력합니다.

`PREDICT` 슬라이더는 별도 기하학 표시의 예측 시간을 0.25초에서 2.0초까지 바꿉니다. 이 투영은 포인트의 과거 횡이동, 자차 `position.x/y`, `position.yStd`, `laneLines`, `laneLineProbs`, `laneLineStds`를 함께 사용합니다. `yawRate`, 조향각, 조향각속도도 기록하며 `yawRate x 거리`로 자차 회전이 만들 수 있는 겉보기 횡속도를 표시합니다. 차선 신뢰도가 낮으면 자차 예상 경로를 기준으로 전환하며, 불확실성이 크면 미래 위치의 가로 막대가 넓어집니다.

유지 중인 검증 구간에서 `CUT-IN`, `CLEAR`, `STATIONARY`를 선택하면 기존 검증 항목이 갱신됩니다. 검증 구간 밖에서 발견한 후보는 별도 `radar_trajectory_labels.json`에 저장되므로 기존 정답을 덮어쓰지 않습니다.

## 하네스 프리셋과의 관계

현재 최초 설정 프리셋은 다음처럼 시작합니다.

| 구성 | `EnableRadarTracks` | `EnableCornerRadar` |
|---|---:|---:|
| ADAS 모듈 하네스 | `0` | `1` |
| 카메라 하네스 | `0` | `0` |
| 순정 SCC 유지 | `0` | `0` |

ADAS 프리셋이 코너 레이더를 켠다는 것은 하네스에서 접근 가능한 구성을 뜻할 뿐, 모든 ADAS 차량의 코너 레이더 메시지가 검증됐다는 뜻은 아닙니다.

## 확인 순서

1. 차종, 연식, 트림, HDA 세대와 정확한 하네스 위치를 확인합니다.
2. 현재 값을 기록하고 기본값 `0`에서 정상 동작을 먼저 확인합니다.
3. 동일 차량 구성의 검증 기록에서 지원되는 레이더 메시지를 확인합니다.
4. 한 번에 한 설정만 변경하고 차량을 다시 시작합니다.
5. 정차 상태에서 경고등과 CAN 오류를 확인합니다.
6. 안전한 시험 환경에서 선행차 거리·상대속도와 끼어들기 오검출을 확인합니다.
7. 이상이 있으면 즉시 원래 값으로 복원합니다.

## 레이더 감지음

openpilot이 활성화된 상태에서 새로운 끼어들기 차량이 확정되면 2단계 알림음이 재생됩니다. 같은 객체가 계속 추적되는 동안에는 한 번만 울립니다. 스피커가 없는 C3X Lite에서는 같은 이벤트를 GPIO 부저 패턴으로 알립니다. 이 알림음은 선택된 레이더 결과를 알려줄 뿐 선행차 선택이나 종방향 제어를 변경하지 않습니다. 더 높은 우선순위의 안전 경고가 발생하면 해당 경고음이 우선할 수 있습니다.
