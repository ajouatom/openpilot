# 레이더트랙·코너레이더

[English](../en/radar.md)

> [!NOTE]
> 이 문서는 `carrot-wip` 코드와 함께 관리하는 사용자 설명서 원본입니다. 사용자 동작이 바뀌면 관련 코드·테스트와 같은 변경에서 이 문서도 갱신합니다.

레이더가 차량에 장착되어 있어도 carrotpilot이 필요한 CAN 메시지를 읽을 수 있다는 뜻은 아닙니다. 같은 차종도 연식, 옵션, 레이더 부품, 펌웨어, 메시지 그룹과 하네스 연결 위치에 따라 결과가 달라집니다.

> [!WARNING]
> 검증되지 않은 레이더 설정은 경고등, CAN 오류, 선행차 오인식 또는 잘못된 끼어들기 판단을 일으킬 수 있습니다. 변경 전 원래 값을 기록하고 정확히 같은 차량 구성이 검증됐을 때만 한 단계씩 시험하세요.

<a id="front-radar"></a>
## 전방 레이더 트랙

`EnableRadarTracks`는 전방 선행차 정보의 원본과 추가 처리를 선택합니다.

| 값 | 현재 코드의 의미 | 사용 판단 |
|---:|---|---|
| `-2` | VOACC 비전 전용 시험 | 개발 시험용 |
| `-1` | SCC를 항상 사용 | 차량 구성 확인 필요 |
| `0` | 순정 SCC 레이더 사용 | 기본값 |
| `1` | 전방 레이더의 원시 트랙 사용 | 차량별 레이더 활성화와 메시지 지원 필요 |
| `2` | 레이더 트랙과 저속 SCC 병행 | 검증된 동일 구성에서만 시험 |
| `3` | 위 기능에 끼어들기·스텔스 차량 처리를 추가 | 오검출 가능성이 있는 실험 기능 |

비-CAN FD 현대·기아 차량에서 양수 값을 사용하면 시작 과정에서 레이더 트랙 활성화를 시도하고 결과를 `EnableRadarTracksResult`에 저장합니다. 물리적인 레이더가 있어도 활성화 결과와 실제 트랙 수신을 함께 확인해야 합니다.

<a id="corner-radar"></a>
## 코너 레이더

| `EnableCornerRadar` | 의미 |
|---:|---|
| `0` | 사용하지 않음 |
| `1` | 지원되는 코너 레이더 트랙 사용 |
| `2` | 코너 레이더를 이용한 끼어드는 차량 검출 추가 |

코너 레이더 객체는 차량 코드가 인식한 지원 메시지 그룹이 있을 때만 생성됩니다. 지원되는 0x430 메시지군도 전방 레이더가 아닌 코너 레이더 입력으로 구분됩니다. 현재 `2`의 끼어들기 처리는 현대 계열을 중심으로 동작하므로 다른 제조사에 같은 값을 일반화하면 안 됩니다.

<a id="lead-fusion"></a>
## 센서 분리 레이더 모델

| `RadarLeadModelMode` | 의미 |
|---:|---|
| `0` | 기존 선행차 선택 방식 |
| `1` | 전방·코너 레이더를 독립적으로 판정하는 센서 분리 모델 방식 |

`RadarLeadModelMode=1`은 차량 또는 장치를 다시 시작한 뒤 적용됩니다. 레이더 트랙 수신 여부와 별개로 모델의 선행차 선택 방식이 달라지므로 동시에 여러 설정을 바꾸지 마세요.

모델 방식에서도 `EnableRadarTracks`가 전방 모델 입력을 결정합니다. `-1`과 `0`은 SCC만, `1`은 전방 레이더 트랙만, `2`와 `3`은 전방 레이더 트랙과 저속 SCC를 사용합니다. SCC와 전방 레이더 입력은 코너 레이더 모델에 섞이지 않습니다.

전방 모델과 코너 모델은 이력과 판정 상태를 서로 공유하지 않습니다. 코너 레이더가 있는 차량은 전방 모델로 `leadOne`을 찾고 코너 모델로 끼어들기·보조 리드를 찾으며, 코너 레이더가 없으면 전방 모델이 보조 판정까지 담당합니다. 코너 후보와 같은 전방 포인트가 확인되면 거리·속도·가속도는 전방 포인트를 사용하되, 5 m 이내 측면 후보는 노이즈가 큰 전방 횡위치 대신 코너 측정값을 유지합니다. 다만 동일 차량이 두 번 보고되지 않도록 객체 식별 연결은 유지합니다.

전방과 코너 모델 파일은 서로 분리해 학습하고 검증합니다. PC 검증기에서 `--front-only`를 지정하면 코너 포인트를 제거하고, 코너 레이더가 없는 디바이스와 같은 전방 단독 경로로 검증합니다.

비전-레이더 `leadOne` 매칭과 새 끼어들기 확률은 서로 독립적입니다. 끼어들기 모델은 현재 포인트와 과거 레이더 이력만 사용하여 0.5/1.0/1.5/2.0초 뒤 같은 차량이 자차 경로 안에 있을 확률 `P(h)`를 냅니다. 장면별 거리, 저속, 정지차, 커브 보정으로 이 확률을 다시 만들지 않습니다.

현재 실측 경로 상태는 `P0`입니다. 차량이 경로 안이면 `P0=1`, 밖이면 `P0=0`입니다. 화면의 `IN`은 `P0`와 자차가 통과하기 전의 미래 `P(h)` 중 최댓값이고, `OUT`은 `1-P0`와 미래 `1-P(h)` 중 최댓값입니다. 한 시점에서는 경로 밖 확률이 정확히 `1-P(h)`이므로 숫자 하나로 표현할 수 있지만, 여러 시점을 합친 `IN`과 `OUT`은 차량이 경계를 통과할 때 둘 다 높을 수 있습니다.

CUT-IN은 현재 경로 밖 차량의 `IN`이 모델 기준 이상일 때 활성화되고, CUT-OUT은 현재 경로 안 차량의 `OUT`이 기준 이상일 때 활성화됩니다. 활성 후 해제 기준은 시작 기준보다 0.05 낮은 단순 히스테리시스입니다. 같은 물리적 차량이 실측으로 밖→안 또는 안→밖을 통과하면 확률 1.00의 전이로 확정하고 1초 동안 유지합니다. 처음부터 경로 안에서 관측된 일반 선행차는 CUT-IN 전이로 만들지 않습니다.

`leadOne`이 있으면 그보다 먼 CUT-IN 후보는 원시 확률만 유지하고 `leadTwo`로 사용하지 않습니다. 같은 차량이 이미 `leadOne`이면 중복 제거합니다. 그 밖에는 새 확률에 거리·속도·차선별 예외를 덧붙이지 않습니다. 선택된 CUT-IN은 실제 레이더 거리·속도·가속도로 `leadTwo`에 전달됩니다.

PC 검증기 `radar_lead_validation_review.py`는 실제 디바이스와 같은 모델·특징·후처리를 실행하며 CUT-IN이 최종 `leadTwo`가 된 때만 일시정지합니다.

### PC 궤적 검증 화면

PC 검증기는 같은 로그에 여러 검증 구간이 있어도 로그 창을 한 번만 열고 모든 구간을 타임라인에 표시합니다. 레이더 그래프의 횡방향은 실제 비율보다 4배 확대됩니다. `POINTS`는 현재 실측 레이더 포인트를, `PATH`는 최근 이력과 별도 기하학적 미래 위치를 표시합니다. 포인트와 우측 상세에는 `P0`, `IN`, `OUT`, 선택한 표시 시점의 `P(h)`가 나오며, 상세 두 번째 줄에는 모델의 원시 `P0.5/P1.0/P1.5/P2.0` 네 값을 그대로 표시합니다. 자차가 이미 물체를 지나간 뒤의 시점은 CUT-IN 최댓값에서만 제외되고 원시값은 남습니다.

포인트 채움색은 센서입니다. 전방 레이더는 청록, 코너 레이더는 보라, SCC는 노랑입니다. 포인트 둘레 원은 하나만 사용합니다. 보라는 높은 IN/CUT-IN, 주황은 CUT-OUT, 빨강은 `leadOne`보다 먼 후보, 초록은 최종 `leadTwo`입니다. 주황·노랑 네모는 최종 `leadOne`·`leadTwo`입니다. 45 m보다 먼 포인트는 위치와 궤적만 그리고 텍스트는 생략합니다. 지도 라벨은 최대 5개, 우측 상세는 최대 3개만 표시합니다.

확률 옵션을 지정하지 않으면 front/corner 모델 파일에 저장된 실제 디바이스 기준으로 원을 표시합니다. 재생은 CUT-IN이 최종 `leadTwo`가 됐을 때만 멈추며, 선택되지 않은 높은 확률만으로는 멈추지 않습니다. `radar_lead_validation_review.py --prob 0.70`은 원의 표시 기준만 바꾸고 `--manual-prob`는 마지막 표시값을 불러옵니다. 두 옵션 모두 정지 이벤트, 모델 출력, 실제 디바이스 임계값을 바꾸지 않습니다. 과거로 이동하면 이후의 실제 `leadTwo` 정지 이벤트가 다시 활성화됩니다. 앞으로 이동하거나 Space로 수동 정지하면 과거 자동 정지 문구 대신 `MANUAL SEEK` 또는 `MANUAL PAUSE`가 표시됩니다.

전방과 코너 모델은 별도 파일로 학습됩니다. 입력은 현재 포인트와 과거 실측 이력뿐입니다. 정답은 물리적으로 연속된 같은 track의 0.5/1.0/1.5/2.0초 뒤 실제 위치가 그때의 자차 경로를 점유하는지로 만들며, 현재 경로 밖인 샘플만 골라 강제하는 방식이 아닙니다. 미래 실측값은 정답 생성에만 쓰고 추론 입력으로 사용하지 않습니다. `measured=false`인 전방 레이더 빈 슬롯과 물리적으로 끊긴 재사용 ID는 제외합니다. 사람이 지정한 `CUT-IN`/`CLEAR`와 그 로그 전체는 학습에서 제외하고 검증에만 사용합니다.

새 경로 점유 모델의 CUT-IN은 front/corner 모두 실제 `leadTwo` 선택에 사용됩니다. 코너 레이더가 있으면 corner 결정이, 없으면 front 결정이 사용됩니다. CUT-OUT은 현재 `leadOne`을 직접 제거하거나 TF를 줄이지 않고, 비전이 이미 매칭을 잃은 뒤의 짧은 stale hold만 해제합니다.

`radar_lead_validation_review.py --trajectory-table-only`는 수동 라벨 평가와 함께 분기점 `carrot-wip` 기존 판정 대 새 path-occupancy 최종 실기 판정을 표시합니다. 사람이 넓게 지정한 구간의 영향을 확인할 수 있도록, 동일 구간에서 로그의 실제 미래 경로 진입을 정답으로 바꾼 비교표도 이어서 출력합니다.

`DISPLAY FUTURE` 슬라이더는 지도에 그리는 미래 포인트와 라벨의 `P(h)`만 즉시 바꿉니다. 표시 전용이므로 모델 추론, IN/OUT, 컨트롤러 기준이나 `leadTwo` 판정은 바꾸지 않습니다. 모델은 항상 고정된 0.5/1.0/1.5/2.0초 출력을 모두 계산합니다. 기하학적 투영은 포인트의 과거 횡이동, 자차 `position.x/y`, `position.yStd`, `laneLines`, `laneLineProbs`, `laneLineStds`, `yawRate`, 조향각과 조향각속도를 사용합니다.

유지 중인 검증 구간에서 `CUT-IN`, `CLEAR`, `STATIONARY`를 선택하면 기존 검증 항목이 갱신됩니다. 검증 구간 밖에서 발견한 후보는 별도 `radar_trajectory_labels.json`에 저장되므로 기존 정답을 덮어쓰지 않습니다.

## 하네스 프리셋과의 관계

현재 최초 설정 프리셋은 다음처럼 시작합니다.

| 구성 | `EnableRadarTracks` | `EnableCornerRadar` |
|---|---:|---:|
| ADAS 모듈 하네스 | `0` | `1` |
| 카메라 하네스 | `0` | `0` |
| 순정 SCC 유지 | `0` | `0` |

ADAS 프리셋이 코너 레이더를 켠다는 것은 하네스에서 접근 가능한 구성을 뜻할 뿐, 모든 ADAS 차량의 코너 레이더 메시지가 검증됐다는 뜻은 아닙니다.

## 확인 순서

1. 차종, 연식, 트림, HDA 세대와 정확한 하네스 위치를 확인합니다.
2. 현재 값을 기록하고 기본값 `0`에서 정상 동작을 먼저 확인합니다.
3. 동일 차량 구성의 검증 기록에서 지원되는 레이더 메시지를 확인합니다.
4. 한 번에 한 설정만 변경하고 차량을 다시 시작합니다.
5. 정차 상태에서 경고등과 CAN 오류를 확인합니다.
6. 안전한 시험 환경에서 선행차 거리·상대속도와 끼어들기 오검출을 확인합니다.
7. 이상이 있으면 즉시 원래 값으로 복원합니다.

## 코드 분석 기준

- 설정 범위와 설명: `openpilot/selfdrive/carrot_settings.json`
- 전방·코너 트랙 결합: `openpilot/selfdrive/controls/radard.py`
- 현대·기아 레이더 메시지 파싱: `opendbc_repo/opendbc/car/hyundai/radar_interface.py`
- 비-CAN FD 레이더 활성화: `opendbc_repo/opendbc/car/hyundai/interface.py`
- 최초 설정 프리셋: `openpilot/selfdrive/carrot/server/features/intro/presets.py`

## 레이더 감지음

openpilot이 활성화된 상태에서 새로운 끼어들기 차량이 확정되면 2단계 알림음이 재생됩니다. 같은 객체가 계속 추적되는 동안에는 한 번만 울립니다. 스피커가 없는 C3X Lite에서는 같은 이벤트를 GPIO 부저 패턴으로 알립니다. 이 알림음은 선택된 레이더 결과를 알려줄 뿐 선행차 선택이나 종방향 제어를 변경하지 않습니다. 더 높은 우선순위의 안전 경고가 발생하면 해당 경고음이 우선할 수 있습니다.
