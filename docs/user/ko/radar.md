# 레이더트랙·코너레이더

[English](../en/radar.md)

> [!NOTE]
> 이 문서는 `carrot-wip` 코드와 함께 관리하는 사용자 설명서 원본입니다. 사용자 동작이 바뀌면 관련 코드·테스트와 같은 변경에서 이 문서도 갱신합니다.

레이더가 차량에 장착되어 있어도 carrotpilot이 필요한 CAN 메시지를 읽을 수 있다는 뜻은 아닙니다. 같은 차종도 연식, 옵션, 레이더 부품, 펌웨어, 메시지 그룹과 하네스 연결 위치에 따라 결과가 달라집니다.

> [!WARNING]
> 검증되지 않은 레이더 설정은 경고등, CAN 오류, 선행차 오인식 또는 잘못된 끼어들기 판단을 일으킬 수 있습니다. 변경 전 원래 값을 기록하고 정확히 같은 차량 구성이 검증됐을 때만 한 단계씩 시험하세요.

<a id="front-radar"></a>
## 전방 레이더 트랙

`EnableRadarTracks`는 전방 선행차 정보의 원본과 추가 처리를 선택합니다.

| 값 | 현재 코드의 의미 | 사용 판단 |
|---:|---|---|
| `-2` | VOACC 비전 전용 시험 | 개발 시험용 |
| `-1` | 비전 매칭 없이 SCC 종거리·상대속도를 항상 사용하고, SCC가 없으면 비전 사용 | 차량 구성 확인 필요 |
| `0` | SCC를 비전과 매칭하고, 매칭 실패 시 비전 사용 | 기본값 |
| `1` | SCC 없이 전방 레이더 트랙을 비전과 매칭하고, 매칭 실패 시 비전 사용 | 차량별 레이더 활성화와 메시지 지원 필요 |
| `2` | 전방 레이더 트랙과 저속 SCC를 비전과 매칭하고, 매칭 실패 시 비전 사용 | 검증된 동일 구성에서만 시험 |
| `3` | 전방 레이더를 비전과 먼저 매칭하고, 실패하면 SCC를 항상 사용하며 SCC도 없으면 비전 사용 | 오검출 가능성이 있는 실험 기능 |

비-CAN FD 현대·기아 차량에서 양수 값을 사용하면 시작 과정에서 레이더 트랙 활성화를 시도하고 결과를 `EnableRadarTracksResult`에 저장합니다. 물리적인 레이더가 있어도 활성화 결과와 실제 트랙 수신을 함께 확인해야 합니다.

레거시 Mando 전방 레이더는 `0x500~0x51F`의 기본 32개 슬롯을 주기·CAN 유효성 기준으로 사용하고, 차량이 전송하면 `0x520~0x53F`의 추가 32개 슬롯도 자동으로 읽습니다. 추가 슬롯은 선택 입력이므로 32슬롯 차량의 발행 주기나 CAN 유효성에는 영향을 주지 않으며, 수신이 끊긴 추가 슬롯은 다음 레이더 주기에 즉시 제거합니다.

<a id="corner-radar"></a>
## 코너 레이더

| `EnableCornerRadar` | 의미 |
|---:|---|
| `0` | 사용하지 않음 |
| `1` | 지원되는 코너 레이더 트랙 사용 |
| `2` | 코너 레이더를 이용한 끼어드는 차량 검출 추가 |

코너 레이더 객체는 차량 코드가 인식한 지원 메시지 그룹이 있을 때만 생성됩니다. 지원되는 0x430 메시지군도 전방 레이더가 아닌 코너 레이더 입력으로 구분됩니다. 현재 `2`의 끼어들기 처리는 현대 계열을 중심으로 동작하므로 다른 제조사에 같은 값을 일반화하면 안 됩니다.

### 당근레이더모드

| `CarrotRadarMode` | 의미 |
|---:|---|
| `0` | 기존 `radard` 선행차·끼어들기 처리 유지(기본값) |
| `1` | 독립 dPath RadarD가 프런트 우선의 레이더·비전 leadOne을 먼저 계산하고, 물리 dPath CUT-IN만 leadTwo로 사용 |

SCC는 `EnableRadarTracks`가 허용하는 모드에서만 최종 레이더 후보로 사용합니다. `-2`는 레이더를 쓰지 않는 비전 전용 시험 모드입니다. `-1`은 비전 매칭을 하지 않고 measured SCC의 종거리·상대속도를 즉시 사용하며, SCC가 없을 때 중앙 비전으로 전환합니다. `0`은 SCC를 비전과 매칭합니다. `1`은 SCC를 제외한 프런트 레이더만 비전과 매칭하고, `2`는 프런트 레이더와 `vLead < 5.0m/s`인 저속 SCC를 비전과 매칭합니다. `3`은 프런트 레이더를 먼저 비전과 매칭하고, 그 매칭이 실패하면 SCC 종거리·상대속도를 무조건 사용하며, SCC도 없을 때 중앙 비전으로 전환합니다. `-1`과 `3`에서 강제 선택한 SCC는 차종별로 부호나 신뢰도가 다른 `yRel`을 경로 판정에 쓰지 않고 발행값 `yRel`·`dPath`도 0으로 둡니다. `0`~`2`에서 허용 레이더와 비전의 매칭이 실패하거나 선택된 레이더가 중앙 비전보다 8m 넘게 멀면, 비전 확률 `0.40` 이상이고 `|dPath| ≤ 1.0m`인 중앙 비전을 안전 폴백으로 사용합니다. 측면 비전 대상은 최소 0.25초 동안 dPath 안쪽으로 계속 진입한 경우에만 별도 비전-only L1 보호를 받을 수 있습니다.

| `CarrotRadarCutInSensitivity` | 의미 |
|---:|---|
| `0` | 당근레이더의 새 CUT-IN leadTwo 승격 사용 안 함 |
| `1` | 둔감 |
| `2` | 약간 둔감 |
| `3` | 보통, 현재 기준(기본값) |
| `4` | 민감 |
| `5` | 아주 민감 |

이 민감도는 `CarrotRadarMode=1`에서만 CUT-IN 확률 문턱, 측정 방향 연속성 문턱과 실제 움직임 확정 대기 시간을 함께 조절합니다. 단계 `1`부터 `5`까지 확정 시간은 각각 `0.50`, `0.40`, `0.35`, `0.25`, `0.20초`입니다. 단계 `3`은 보통이며 코너/프런트 확률 문턱 `0.30/0.67`과 프런트 방향 연속성 문턱 `0.75`를 유지합니다. 단계가 높을수록 더 낮은 확률과 방향 연속성을 허용하고 더 짧게 확인하며, 단계가 낮을수록 반대로 동작합니다. 전방 레이더의 최근 0.8초 이력에서 0.50m 이상 강한 단방향 실측 진입이 확인되면 timestamp 양자화 때문에 확정 시간을 간발의 차로 놓치지 않도록 최대 20Hz 레이더 한 프레임만 반영합니다. 작은 인접 차로 흔들림에는 이 보정을 적용하지 않습니다. 미래 corridor 연속 침범, 거리 범위, leadOne보다 가까워야 하는 조건과 정지 노이즈 차단 같은 물리 안전 조건은 민감도와 관계없이 유지합니다. `0`에서도 leadOne 계산과 레이더 상태 발행은 계속하지만 새 물리 CUT-IN을 leadTwo로 선택하지 않습니다. 이 설정은 기존 `radard`와 `EnableCornerRadar` 동작을 바꾸지 않습니다.

두 설정값은 오프로드에서 갱신하고 다음 OnRoad가 시작될 때 해당 주행 동안 고정합니다. 변경 후에는 현재 주행을 끝내고 차량을 재시동하거나 기기를 재부팅해야 적용됩니다. 실행 중 설정값만 바꿔 레이더 프로세스와 CUT-IN 정책을 즉시 교체하지 않습니다.

`1`은 학습 모델을 사용하지 않으며 기존 `controls/radard.py`를 호출하거나 그 결과를 섞지 않습니다. model lead zero가 `0.40` 이상의 확률로 검출되면 독립 프로세스가 프런트 레이더를 먼저 매칭하고, `EnableRadarTracks`가 SCC를 허용하는 모드에서는 적합한 프런트가 없을 때 SCC를 일반 이동 leadOne 후보로 사용합니다. 새 이동 leadOne 매칭은 기존 radard와 같은 거리·횡위치·속도 결합 likelihood 최소값 `1e-4`도 넘어야 하며, 비전 종거리 불확실성이 크면 `2.5 * xStd`만큼 최대 15m까지 종거리 문턱을 넓힙니다. 이미 연결된 동일 리드는 확률이 `0.35`보다 큰 동안 최대 10 model 프레임을 더 유지해 순간적인 확률 흔들림을 완화합니다.

일반 매칭이 실패한 정지·저속 차량에는 별도 fallback을 적용합니다. 현재 경로의 `measured=true` 객체가 `|vLead| ≤ 4.0m/s`이고 model lead zero와 절대 종거리 15m 이내로 대응해야 합니다. 정지 프런트 레이더는 model과 속도 차이를 최대 12m/s까지만 허용하고, 신뢰도가 높은 중앙 코너 레이더와 설정상 허용된 SCC는 최대 20m/s까지 허용합니다. 비전이 지지하는 대상은 **프런트 레이더 → 코너 레이더 → SCC** 순으로 선택합니다. 전방 레이더 정지차의 최초 시드는 보통 비전 지원 3프레임과 0.25초의 물리 연속성이 필요합니다. 단, 60m 이상에서 `trackState ≥ 2`인 전방 레이더가 0.50초 이상 계속 측정됐고 `|vLead| ≤ 1.5m/s`, model·radar 거리 차 5m 이하, raw 횡위치 차 1.25m 이하, `|dPath| ≤ 1.0m`, `|yawRate| < 0.02rad/s`를 모두 만족하면 model과 속도 차이를 18m/s까지 허용합니다. 이 경우에도 기존의 비전 지원 3프레임과 0.25초 정지차 확인은 그대로 거칩니다. 이는 먼 정지차의 위치는 정확히 찾았지만 속도 추정만 늦는 model을 위한 제한적인 위치 고정 조건이며, 일반 속도 문턱을 넓히지는 않습니다. 같은 구역의 코너 포인트는 더 강한 증거가 되어 물리적으로 이어지는 프런트↔코너 전환을 보강합니다. 비전 확률이 `0.40` 미만이면 path 중심 0.50m 이내의 코너 포인트 또는 설정상 허용된 중앙 SCC가 해당 중앙 근거를 매 프레임 유지한 채 0.50초 연속 확인돼야 새 정지 lead가 됩니다. 프런트와 코너의 상호 확인은 물체의 실재성과 후보 순위만 보강하며 중앙 경로 조건을 우회하지 않습니다. 반대로 비전도 중앙 코너/SCC 확인도 없는 프런트 단독 정지 반사점은 승격하지 않습니다. 비전 지원 없이 확정된 radar-only 정지 객체는 위치가 이어져도 `|dPath| ≤ 1.2m` 안에서만 leadOne으로 유지하고, 비전으로 확인된 객체는 기존의 넓은 sticky 범위를 사용합니다. 확률 `0.40` 이상의 비전이 종방향으로 15m 넘게 분리되면 sticky를 즉시 해제합니다. 이 fallback으로 새 정지 포인트를 leadTwo로 승격하지는 않습니다.

확률 기반 matcher가 놓쳤더라도 설정상 허용된 measured 포인트가 model lead zero와 기본 종거리 15m 이내·경로 횡오차 2m 이내로 대응하면 해당 레이더 포인트를 발행합니다. 이동 대상은 프런트, 코너, 설정상 허용된 SCC 순으로 회수하고, 정지 대상을 즉시 회수하는 경로는 중앙 코너로 제한하며 정지 프런트는 위 확인 절차를 거칩니다. 확률 `0.90` 이상의 원거리 비전과 중앙 이동 레이더는 최대 30m까지 연속적으로 커지는 종거리 gate, 속도 차 10m/s 이내, `|dPath| ≤ 1.5m`, 동일 identity 0.25초 조건을 모두 통과해야 보강 매치됩니다. 단, 레이더 매치가 중앙 비전보다 8m 넘게 멀면 더 가까운 실제 선행차를 가릴 수 있으므로 그 매치를 폐기합니다. 이후 `-1`은 SCC를 무조건 사용하고, `3`은 남아 있는 SCC를 무조건 사용합니다. 그 밖의 모드와 SCC가 없는 `-1`·`3`은 확률 `0.40` 이상, `|dPath| ≤ 1.0m`인 중앙 비전을 leadOne으로 사용합니다. 따라서 `0`의 SCC, `1`의 프런트 레이더, `2`의 프런트 레이더·저속 SCC가 비전과 맞지 않아도 중앙 비전 선행차를 삭제하지 않습니다. 이미 검출된 비전 리드는 확률이 `0.35`보다 큰 동안 최대 10 model 프레임 유지하며, 0에 가까운 새 비전 가설은 leadOne으로 만들지 않습니다.

반대로 현재 model path 중심의 이동 레이더 객체는 독립적인 확인 절차를 거쳐 radar-backed leadOne이 될 수 있습니다. 야간에 등화가 보이지 않는 차량이나 비전 검출이 약한 오토바이뿐 아니라, 비전 확률은 높지만 종거리만 크게 틀린 경우도 이 경로로 처리합니다. 현재 경로 이동 fallback은 **프런트 레이더 → 코너 레이더 → SCC** 순으로 선택하며 SCC는 `EnableRadarTracks`가 허용할 때만 후보가 됩니다. 새 객체는 정지차 분류와 겹치지 않는 `vLead > 4.0m/s`, 전방 100m 이내, `measured=true`, 0.25초의 거리·횡위치 연속성을 모두 만족해야 합니다. 비전 없이 코너 이동 포인트를 승격할 때는 같은 확인 구간의 실제 종거리 변화와 적분한 보고 `vRel`의 오차율이 3.0m/s 이하여야 합니다. 이 값을 넘긴 코너 identity는 같은 물리 연속성 동안 다시 승격하지 않고, 실제 단절 뒤 ID가 재사용되면 새로 확인합니다. `|vLead| ≤ 4.0m/s`인 포인트는 정지차 경로에서만 처리하므로 프런트 단독 저속 반사점이 순간적인 속도 노이즈로 이동 fallback을 우회할 수 없습니다. 일반 매칭이 성립한 동안에도 fallback의 물리 이력을 계속 갱신하므로 이미 확인된 객체는 비전 거리만 갑자기 튀어도 추가 확인 공백 없이 즉시 이어받습니다. 또한 비전 거리에 더 잘 맞는 먼 이동 포인트가 일반 매칭되더라도, 이 확인을 마친 더 가까운 현재 경로 이동 포인트가 있으면 가까운 포인트를 leadOne으로 우선합니다. 허용 `|dPath|`는 60m 이내 1.1m, 60~80m 0.9m, 80~100m 0.75m로 멀수록 엄격해지고, 곡선에서 인접 차로 반사점을 중심 차량으로 오인하지 않도록 raw `yRel`과 `dPath` 차이도 1.5m 미만이어야 합니다. 45m 밖에서 자차보다 0.5m/s 넘게 더 빠르게 멀어지는 포인트는 제어 lead로 승격하지 않습니다. 이 fallback은 항상 물리 레이더 거리를 발행하며 대응에 실패한 비전 거리를 섞지 않습니다.

현재 model path corridor 안에서 처음 생긴 미확정 이동 레이더 포인트는 단순히 움직인다는 이유만으로 leadTwo가 되지 않습니다. 확실한 비전이 없을 때 중앙의 이동 코너·프런트·설정상 허용된 SCC 객체는 확인 절차가 있는 radar-only leadOne 경로에서 담당합니다. 새 leadTwo는 물리적으로 추적된 OUT→IN 경계 통과와 CUT-IN 확정을 모두 만족해야 하며, 이미 선택된 leadTwo만 계속 경로를 점유하는 동안 sticky하게 유지할 수 있습니다. 예측 CUT-IN과 sticky 유지 후보를 포함한 모든 leadTwo 후보는 실제 leadOne이 있으면 반드시 leadOne보다 가까워야 합니다. 예측 CUT-OUT은 leadOne을 제거하거나 물리 identity를 latch하여 제외하지 않으며, 어느 제어 lead 후보도 CUT-OUT 값만으로 제외하지 않습니다. CUT-OUT은 진단 출력으로만 유지합니다. leadOne은 프런트 우선 레이더 매칭, 정지 fallback, radar-only 확인, 최종 비전-only fallback의 순서 안에서만 전환합니다. 이로써 path 중심에서 짧게 새로 생긴 코너 포인트가 여러 track ID로 leadTwo를 번갈아 차지하지 않으며, 실제 중앙 차량이라면 leadOne 확인 경로가 담당합니다. 중복 방지는 leadOne이 실제 존재하는 동안 적용하므로 같은 차량을 L1과 L2로 동시에 내보내지는 않습니다. OUT→IN 차량은 고정 5초 물리 예측 안에서 차체와 corridor가 최소 0.5초 연속으로 겹칠 때만 같은 거리 우선 조건의 후보가 됩니다. 보통 단계에서는 그 뒤에도 실제 움직임 근거가 0.35초 동안 계속돼야 하며, 먼 미래 침범이 길다는 이유로 이 시간을 줄이지 않습니다. 5m 안의 코너 레이더 차량은 차체 폭을 포함한 path corridor에서 0.45m 이내이고, 짧은·긴 dPath 이력과 현재 레이더 횡속도가 모두 안쪽 방향으로 일치할 때만 확인 시간을 0.10초로 줄입니다. 이는 단순 근거리 점을 허용하는 규칙이 아니라, 이미 경계에 매우 가까운 차량이 빠르게 진입하는 상황에만 적용합니다. 프런트와 상호 확인된 2m 이내 코너 객체도 차체가 이미 corridor에 겹친 경우가 아니면, 현재·경로 추정·최근 상대속도 중 가장 보수적인 값으로 예측한 첫 겹침 시점에 자차보다 0.5m 이상 앞에 남아야 합니다. 즉, 다른 센서가 물체의 실재를 확인했더라도 겹치기 전에 자차 뒤로 빠지는 범퍼 근처 측면 반사점은 조기 CUT-IN으로 승격하지 않습니다. 또한 15m 밖의 비전 미확인 코너 객체가 상대속도 -0.1~+2.0m/s로 나란히 가거나 약하게 멀어지고 `|dPath| > 2.30m`이면, 0.60m 이상의 순진입량과 0.90 이상의 방향성을 실제 측정으로 보이기 전에는 약한 외삽만으로 승격하지 않습니다. 더 빠르게 멀어지는 차량은 실제 횡진입일 수 있으므로 후보 자격을 유지하며 종방향 감속 필요성은 별도 조건으로 판단합니다. 25m 경계나 거리별 확정 시간은 없으므로, 25m 안의 유효 후보도 선택한 감도 정책으로 동일하게 검출합니다. 또한 leadOne과 종방향 거리가 ±8m 이내인 같은 거리대의 바깥 차량은 불확실도나 한 시점의 경로 근접 점수만으로 승격하지 않습니다. 따라서 같은 거리에 나란히 있는 차량을 전부 버리지는 않으며 실제로 계속 진입하는 물리 궤적이 생기면 허용합니다. 선택된 leadTwo는 같은 센서·track ID·물리 연속성 ID와 위치 연속성이 유효한 동안 sticky하게 유지합니다. 같은 인접 방향에 더 가까운 포인트가 새로 생기면 미선택 포인트는 가릴 수 있지만, 이미 선택되어 계속 측정되는 leadTwo에는 이 가림 필터를 적용하지 않습니다. 선택 뒤 보고 속도가 0에 가까워져도 유지할 수 있지만, 새 정지 포인트가 leadTwo로 승격되지는 않습니다. 비전·전방 레이더 매칭이 같은 객체를 leadOne으로 확인하면 L1과 L2에 동시에 내보내지 않고 L2에서 L1으로 인계합니다. 이 leadOne 인계, 명확한 바깥 방향 이동, 거리 범위 이탈, 물리적 단절이나 ID 재사용 때 해제하며, 순간 단절은 예측한 종·횡 위치와 일치할 때만 최대 0.75초까지 재연결합니다. 모든 leadTwo 후보에는 요청한 고정 80m 전방 상한을 적용합니다.

코너 레이더 포인트가 한 번이라도 확인되면 해당 실행 동안 코너 motion만 사용하고, 코너 포인트가 없는 구성에서는 `frontRadar` raw track만 사용합니다. 프레임마다 front와 corner를 교체하지 않으며 SCC는 dPath motion 입력으로 사용하지 않습니다. 전방 레이더는 코너 레이더와 객체 품질이 다르므로, 프런트 전용의 새 예측 CUT-IN은 감도와 별개로 긴 구간에서 안쪽 방향 `dPath` 이동 속도가 기본적으로 최소 `0.75m/s`여야 합니다. 다만 최근 0.8초 이력에서 순진입량이 0.20m 이상이고, 순진입량을 전체 왕복 이동량으로 나눈 방향성이 0.75 이상이며, 측정 간 이동의 65% 이상과 짧은·긴 dPath 변화율이 모두 안쪽 방향이고 미래 연속 corridor 침범이 1.0초 이상이면 더 낮은 긴 구간 속도도 허용합니다. 이때 원본 위치를 median 평활하지 않고, 방향이 명확한 경우에만 긴·짧은 구간 속도를 절반씩 섞어 미래 궤적을 더 빠르게 반영합니다. 현재 corridor에 이미 걸친 5~10m 전방 포인트는 짧은 구간·긴 구간·현재 레이더 보고 횡속도가 각각 같은 안쪽 방향을 지지할 때도 더 낮은 긴 구간 속도를 허용합니다. 비전이나 코너 레이더가 확인하지 않은 8m 이내 프런트 객체는 근거리 차체 여유 경계 `2.15m`만으로 leadTwo가 되지 않으며, 측정 중심이 실제 차체 중첩 corridor인 `1.90m` 안에 들어와야 합니다. 비전·코너 확인이 있는 객체는 기존 여유 경계를 유지하고, 더 먼 프런트 전용 진입도 기존 규칙을 그대로 사용합니다. 코너 motion track과 전방 레이더 포인트가 고정된 거리·횡위치·속도 범위 안에서 서로 가장 가까운 대상으로 일치하면 motion과 CUT-IN 상태는 계속 코너 이력으로 판단하되, 발행하는 `dRel`, `vLead`, `aLead`, `jLead`는 전방 레이더 측정값을 사용합니다. 한 번 성립한 상호 센서 연결은 두 track identity와 위치·속도 연속성이 맞는 동안 더 넓은 hysteresis로 유지합니다. 이로써 긴 차량에서 앞·뒤 반사 기준점이 이동해도 같은 객체로 유지하되, 처음부터 넓은 범위 안에 들어온 모든 새 포인트 쌍을 같은 객체로 합치지는 않습니다. 상호 매칭된 전방 레이더 거리가 불확실한 비전 거리보다 가깝고 그 비전 거리가 leadOne보다 가까우며, 레이더·비전 속도가 일치하고 1초 이상의 짧은·긴 dPath 이력이 모두 안쪽으로 움직일 때는 해당 코너 객체에 비전의 차량 존재 근거를 보강할 수 있습니다. 단, 물리 예측에 이미 필요한 연속 corridor 침범이 있을 때만 보강하므로 비전만으로 CUT-IN을 만들지는 않습니다. 이때 비전 거리를 제어값에 평균내지 않고 종방향 제어값은 계속 전방 레이더, dPath motion은 계속 코너 레이더에서 가져옵니다. 그 전방 포인트가 leadOne이면 일반 중복 방지로 같은 차량을 leadTwo에도 내보내지 않습니다. 잘못된 leadTwo는 실제 감속에 영향을 줄 수 있으므로 전체 shadow 검증을 마친 동일 차량 구성에서만 켜세요.

코너 레이더의 객체 ID는 전체 슬롯에서 유일하다고 가정하지 않습니다. 동시에 들어온 두 CAN 슬롯의 객체 ID가 같아도 거리·횡위치·속도가 물리적으로 이어질 수 없으면 서로 다른 track으로 유지하고, 슬롯 이동 과정에서 생긴 물리적으로 가까운 복제만 합칩니다. 따라서 멀리 있는 동일 ID 반사점 때문에 가까운 측정 차량이 누락되지 않습니다.

차로 변경 보조가 사용하는 `leadLeft`, `leadRight`와 측면 목록도 같은 motion 센서에서 보이는 좌·우 인접 차량 위치로 발행합니다. 기존 정지차 기준과 동일하게 `|vLead| ≤ 2.5m/s`인 포인트는 이 현재 위치에는 사용할 수 있지만 새 dPath 이력을 만들거나 leadTwo로 예측하지 않습니다. 이미 선택된 leadTwo가 이후 이 속도 이하로 감속한 경우에는 동일 물체의 위치 연속성이 유지되는 동안 sticky 동작을 유지합니다.

레이더 측정이 있는 모든 발행 lead는 측정된 `jLead`를 그대로 유지합니다. track별 `aLeadTau`는 기존 `radard`와 동일하게 `RadarReactionFactor` 설정, 작은 가속도 기준, jerk 기준과 0.45초 감쇠 필터를 사용하며 Radar Motion 모드라고 고정값으로 바뀌지 않습니다. 이 동작은 leadOne, leadTwo, 좌우 lead와 모든 좌·중앙·CUT-IN 목록에 동일하게 적용됩니다.

이미 확정된 먼 nonzero 이동 leadOne이 계속 측정되더라도 더 가까운 중앙 프런트 레이더를 영구히 가리지 않습니다. `trackId=0`이 아닌 새 프런트 포인트가 기존 nonzero lead보다 최소 3m 가깝고 `|dPath| ≤ 0.5m`에서 0.25초 동안 거리·횡위치 연속성을 유지하면, 비전이 먼 객체와 정상 매치된 상태에서도 가까운 포인트로 leadOne을 교체합니다. 이 좁은 중앙 교체 규칙은 leadTwo/CUT-IN 후보와 track 0/SCC 선택 설정을 변경하지 않습니다.

긴 차량의 측면·후방 반사점은 차량 중심보다 먼저 자차 뒤로 빠질 수 있어 미래 `dRel > 0` 교차만으로 차로 경계 침범을 놓칠 수 있습니다. 이를 위해 0.8~5m 전방의 코너 포인트가 기본 차체 경계에서 0.85m 이내이고, 최근 0.8초 순진입량 0.20m 이상, 방향성 0.90 이상, 안쪽 측정 비율 75% 이상, 짧은·긴 안쪽 속도 각각 0.25/0.15m/s 이상이며 레이더 횡속도와 최근 움직임 일치도가 모두 0.90 이상일 때는 `근접 단방향 진입`으로 허용합니다. 이 조건 자체가 이미 연속 측정 이력을 요구하므로 추가 프레임 대기 없이 확정합니다. 이는 차종을 추정하거나 단순 근거리 점을 허용하는 규칙이 아니라, 경계에 가까운 실측 포인트가 강하고 일관되게 안쪽으로 움직이는 물리 조건입니다.

대상 차량 중심이 model path에서 2.7m 이내이면 대상 차체 반폭 0.9m를 포함해 자차선의 공칭 1.8m 경계를 이미 밟은 상태입니다. 이때 코너레이더의 최근 0.8초 순진입량·방향성·안쪽 표본 비율·짧은/긴 dPath 속도와 레이더 보고 횡속도가 모두 안쪽으로 일치하면 `차선 경계 단방향 진입`으로 판정합니다. 이는 아직 자차와 대상 차체가 직접 겹치는 1.8m corridor에 도달하지 않았더라도 실제 차선 침범을 놓치지 않기 위한 현재 상태 판정입니다. 단순 경계 근접이나 model path 이동만으로는 성립하지 않으며, 지속 측정한 위치 변화와 코너레이더 횡속도의 방향 일치가 모두 필요합니다.

## 선행차 선택과 검증

manager는 두 레이더 구현을 동시에 실행하지 않습니다. `CarrotRadarMode=0`에서는 기존 `openpilot.selfdrive.controls.radard`만 실행하고 기존 leadOne/leadTwo 선택을 그대로 유지합니다. `CarrotRadarMode=1`에서는 기존 프로세스를 중지하고 독립 `openpilot.selfdrive.carrot.radar.radard_dpath`만 실행합니다. 이 프로세스는 leadOne을 먼저 계산한 뒤 물리 predictor로 leadTwo를 계산해 `radarState`를 직접 발행합니다. 비전이 있으면 leadOne은 설정별 프런트/SCC 레이더를 우선 매칭하고 대응하는 raw 포인트를 회수하며, 정지 대상은 코너와 설정상 허용된 SCC를 fallback으로 사용합니다. 확실한 비전이 없어도 중앙 정지 코너/SCC 또는 프런트와 서로 확인된 코너를 확정할 수 있습니다. 허용 레이더가 비전과 대응하지 않으면 중앙 비전을 최종 안전 폴백으로 유지합니다. 다만 `-1`은 SCC를 처음부터 무조건 사용하고, `3`은 일반 매칭 실패 뒤 SCC를 무조건 사용하므로 이 두 모드에서는 SCC가 없을 때만 비전으로 전환합니다. 전방 레이더, SCC, 코너 레이더의 소스 구분을 유지하며 학습형 레이더 리드 모델은 사용하지 않습니다.

headless 검증기는 기존 radard와 실험 중인 단순 물리 predictor를 별도로 보고할 수 있습니다. 화면 리플레이는 새 독립 controller와 물리 predictor만 실행합니다. leadOne/leadTwo는 로그의 model·radar 입력으로 다시 계산하며 기록된 기존 radard의 lead 역할과 CUT-IN 마커를 가져오지 않습니다. 지도에는 이동 예측 대상이 아닌 정지 포인트를 포함해 현재 프레임의 모든 measured 코너 레이더를 보라색으로 표시하며, 프런트 raw 포인트 표시는 `F` 키로 전환합니다. 리플레이는 종방향 제어를 바꾸지 않습니다.

shadow predictor는 다음 원칙으로 동작합니다.

- `measured=true` 레이더 포인트만 사용합니다.
- 자차 뒤 5m부터 전방 100m까지의 포인트만 motion 예측에 사용합니다.
- 리플레이 레이더 포인트를 실측 상대속도로 model path 시점에 먼저 맞춘 뒤, 잡음이 있는 끝 구간을 연장하지 않고 같은 시점에 실제 측정된 model path polyline 안에만 수직 투영합니다. 중심선을 따라간 호 길이가 `S`, 중심선 법선 방향의 부호 있는 거리가 `dPath`입니다. 처리 범위도 이 유한한 polyline까지의 실제 거리로 검사하므로 정차 때 짧거나 역전된 경로 끝이 멀리 있는 측면 포인트를 가짜 중심선 위로 당기지 않습니다.
- 이 시각 정렬에는 카메라 측정시각인 `modelV2.timestampEof`, 차량에 설정된 전방 레이더 지연값, 코너 객체의 레이더 한 주기인 50ms 측정 지연값을 사용합니다.
- model path 기준 고정 범위 `|dPath| ≤ 5.4 m`를 사용해 ego lane과 바로 좌·우 인접 차로만 처리합니다.
- `|dPath| ≤ 5.4 m` 안의 실측 이력은 계속 보존하지만, 새 예측 CUT-IN은 현재 위치가 차체 경로 중첩 경계에서 1.2 m 이내인 `|dPath| ≤ 3.0 m`에 도달한 뒤에만 시작합니다. 따라서 옆차로의 바깥쪽 또는 옆옆차로에서 먼 미래에 자차 경로를 향하는 점은 미리 승격되지 않으며, 실제로 가까워졌을 때는 이미 보존한 이력을 사용해 즉시 판단합니다.
- 좌·우 각 인접 차로에서는 5m 이내 포인트와 5m 이상에서 가장 가까운 차량을 유지합니다. 같은 쪽에서 더 먼 차량도 현재 leadOne보다 가까우면 유지하고, 그 밖의 가려진 차량만 검출 대상에서 제외합니다. 단, 범위 안의 실측 이력은 유지하며, 현재 `|dPath| < 3.0m`에서 최근 0.8초 순진입량 0.45m 이상·방향성 0.95 이상·안쪽 표본 90% 이상이고 raw 횡속도도 같은 방향을 지지하면 앞쪽의 가까운 측면 반사점 뒤에 있어도 즉시 검출 대상으로 복귀합니다. 따라서 실제로 진입 중인 차량을 단순 거리 가림으로 잃지 않으면서 모든 먼 측면 포인트의 비싼 미래 예측을 실행하지 않습니다. 이미 선택되어 물리적으로 연속된 leadTwo는 이 표시·검출 가림보다 우선하며, leadOne으로 인계되거나 물리적 유효성이 깨질 때까지 유지합니다.
- 로그에 실측 코너레이더 데이터가 있으면 코너 motion만 사용하고, 없으면 `frontRadar` raw track만 사용합니다. SCC는 기존 radard 표시에는 남지만 motion predictor 입력으로 사용하지 않으며, 개별 프레임마다 소스를 바꾸지 않습니다.
- 전방 레이더의 CUT-IN 후보는 원칙적으로 자차 전방 5m 이상에서만 확정하며, 5m 안에서 새로 관측된 전방 포인트는 현재 경로에 겹쳐도 그것만으로 leadTwo를 시작하지 않습니다. 다만 2~5m에서 경로 밖부터 충분한 실측 이력이 이어진 동일 포인트가 실제로 `OUT → IN` 경계를 통과하고, 최근 순진입량 0.40m 이상·방향성 0.90 이상·안쪽 측정 비율 70% 이상이며 짧은/긴 dPath 속도와 레이더 보고 횡속도가 모두 강하게 안쪽으로 일치하면 추적된 근접 진입으로 허용합니다. 이는 5m 안에서 갑자기 생긴 반사점에는 적용되지 않습니다. 센서별 최소 실측 motion 이력이 쌓이지 않은 새 현재경로 포인트도 즉시 leadTwo를 시작하지 않습니다. 이미 선택된 동일 객체의 물리·위치 연속성이 유지되면 5m 안으로 들어온 뒤에도 sticky leadTwo를 유지할 수 있습니다.
- 코너 객체가 전방 레이더 포인트와 상호 일치하면 두 센서의 dPath 이력을 섞지 않고 발행할 종방향 운동값만 전방 레이더 값으로 사용합니다. 코너 객체가 이미 motion 이력을 쌓은 뒤 처음 전방 레이더와 결합되면, 물리적으로 연속된 raw 코너 이력을 안정된 cross-sensor ID로 승계해 센서 결합 때문에 관측된 `OUT → IN` 통과가 사라지지 않게 합니다. 거리·횡위치·속도가 불연속으로 뛴 경우에는 이력을 승계하지 않고 새로 시작합니다.
- `|vLead| ≤ 2.5m/s` 포인트는 현재 위치만 표시하고 새 motion 이력을 만들거나 미래로 외삽하지 않습니다. 이미 선택된 leadTwo의 감속은 sticky 연속성으로 별도 유지합니다.
- 프레임마다 차선 중심과 model path를 바꿔 사용하지 않습니다.
- 레이더 포인트와 경로를 같은 시점·자차 좌표계로 맞춘 뒤에는 yawRate를 `dPath`에 다시 보정하지 않습니다. 다만 코너 레이더가 보고한 `vLead`·`yvRel`은 회전하는 자차 좌표계의 속도이므로, model path 법선 속도와 비교하기 전에 yaw 회전 성분만 제거합니다. 이 속도 좌표 변환은 측정 `dPath` 위치나 이력을 움직이지 않습니다.
- 재사용된 track ID와 짧은 단절은 물리적인 위치·속도 연속성으로 검사합니다.
- front와 corner의 이력과 파라미터를 분리합니다.
- raw `dRel`을 그대로 경로 거리로 보지 않고, 중심선에 투영한 `S`와 누적 자차 이동거리, 법선 방향 `dPath`로 2차원 경로좌표 이력을 만듭니다.
- 시간에 따른 횡이동이 아니라 대상의 실제 `S` 진행량에 대한 `dPath` 기울기를 사용하므로, 종방향으로 거의 진행하지 않은 포인트의 흔들림을 미래 CUT-IN으로 연장하지 않습니다.
- 긴 구간 `(S, dPath)` 이동 벡터와 model path 접선에 대한 각도 오차를 예측 평균으로 사용하고, 미래 외삽 거리가 관측한 공간 이력보다 길면 신뢰도를 낮추며, 짧은 구간과의 차이는 기본적으로 곡률과 불확실도를 키우는 데 사용합니다. 프런트 이력의 최근 0.8초 순진입량·방향성·안쪽 측정 비율이 모두 기준을 넘을 때만 짧은 구간 속도를 절반 반영해 명확한 한 방향 진입을 미래 궤적에 더 빨리 반영합니다.
- 경로 근접 근거에는 예측한 안쪽 이동량이 측정된 경로 불확실도를 얼마나 넘는지도 반영하므로, 단순히 가까이 있거나 불확실도보다 작은 인접 차로 흔들림만으로 CUT-IN을 확정하지 않습니다.
- 코너 레이더는 위치 이력으로 계산한 법선 방향 움직임과 최근 0.1초 동안 레이더가 보고한 횡속도를 비교합니다. 같은 방향의 더 큰 보고 속도는 위치 추세를 지지하는 것으로 보고, 현재 측정이나 짧은 dPath 추세가 오래된 안쪽 이동 추세를 더 이상 지지하지 않거나 차량 표면에서 반사 기준점이 옮겨간 경우처럼 두 값이 같은 물리 움직임을 설명하지 않으면 CUT-IN/CUT-OUT 신뢰도를 즉시 낮춥니다. 다만 위의 엄격한 0.8초 단방향 dPath 이력과 raw 횡속도가 함께 안쪽 이동을 지지하면, 커브의 경로 접선 때문에 한 시점의 변환된 법선 속도 부호만 반대가 된 경우에는 측정 위치 이력을 우선합니다.
- 0.5초 간격으로 5.0초까지의 미래 `dRel`과 `dPath`를 같은 시점으로 예측합니다.
- leadOne이 있으면 후보가 corridor에 처음 겹치는 같은 미래 시점의 종방향 위치도 비교합니다. 현재 상대속도로 예측한 후보가 leadOne보다 최소 2m 이상 확실히 가깝지 않으면, 그 차량은 자차와 leadOne 사이로 끼어드는 것이 아니므로 leadTwo CUT-IN에서 제외합니다.
- CUT-IN과 CUT-OUT 확률을 별도로 표시합니다.

현재 경로 겹침 판정에는 자차와 대상 차량의 반폭을 포함하며 기본 경계는 model path 중심에서 좌우 1.8m입니다. 경계 부근의 한 프레임 출렁임을 막기 위해 기존 경로 상태 hysteresis 0.12m를 예측 침범에도 동일하게 적용합니다. 예측 CUT-IN은 미래 차체가 이 경계 안에 0.5초 간격의 두 시점 이상 연속으로 들어와야 하므로 최소 0.5초의 연속 corridor 침범이 필요합니다. 불확실도와 근접도는 이 연속 침범 안에서 점수를 조절하지만 그 자체만으로 corridor 바깥의 진입을 만들지는 못합니다. 코너 레이더 객체의 첫 예측 침범이 3.5초 이후에야 시작되면 최근 실측 방향 이력에서 순진입량 0.30m 이상, 방향성 0.80 이상, 안쪽 측정 비율 75% 이상도 만족해야 합니다. 따라서 인접 차로의 작은 편향이 긴 외삽만으로 CUT-IN이 되는 것을 막으며, 더 엄격한 현재 차선 경계 진입과 근접 단방향 진입 규칙은 그대로 유지합니다. 처음 관측될 때부터 경로에 걸친 차량은 현재 `IN`으로 표시하며 새로운 shadow CUT-IN으로 취급하지 않습니다. 단, 5m 안에서 새로 생긴 전방 포인트는 제어 부적격 `NEAR-IN`으로 표시합니다. 위의 엄격한 실측 방향성과 실제 경계 통과를 모두 만족한 근접 전방 포인트만 `TRACKED-IN`으로 표시합니다. 물리 이력으로 추적하던 차량의 `OUT → IN` 전이는 경계를 지난 뒤에도 진입 근거를 유지하므로, 겹침이 시작된 뒤 확인을 마칠 수 있습니다. 보통 확인 시간은 실제 움직임 근거 0.35초이고 민감도 단계에 따라 0.50~0.20초를 사용하며, 이미 충분한 단방향 이력을 포함한 근접 경계 통과는 엄격한 짧은 확인을 사용할 수 있습니다. 경로 상태와 확정에 작은 hysteresis만 사용하며 경로·차종·장면별 예외는 추가하지 않습니다.

한 시점의 근접도만으로는 corridor 바깥의 진입을 만들지 않습니다. 유일한 보완은 위의 엄격한 0.8초 `근접 단방향 진입` 실측 이력이며, 추가 확인 대기를 생략하는 것도 그 전에 이미 연속된 이력을 요구하기 때문입니다.

### PC 리플레이

카메라 영역은 더 축소하고 가운데 거리 그래프는 위로 넓혀 -30~130m를 표시합니다. 하단 전체 로그 그래프는 이전 높이의 두 배이며, L1/L2와 함께 첫 번째 모델 비전 lead를 `V`로 표시합니다. `V`는 확률이 0.4 이상인 프레임에서만 파란색으로 그리며, 범례에는 현재 거리와 확률을 함께 표시합니다.

`radar_lead_validation_review.py`는 같은 로그의 유지 중인 검증 사례를 묶어 47개 고유 로그를 순서대로 한 번씩 엽니다. 각 화면에는 동기화된 qcamera 비디오, 새 controller가 다시 계산한 lead 역할과 물리 predictor가 사용·검출한 포인트, 궤적, 확률, CUT-IN 이벤트만 표시합니다. 기록된 기존 radard의 lead 역할, CUT-IN 포인트와 이벤트 마커는 표시하지 않습니다. 한 로그가 끝나면 창을 닫고 다음 로그를 자동으로 엽니다. `T`는 저장되는 처리 모드를 일반(코너가 있으면 코너 우선, 없으면 프런트)과 프런트 전용(코너 입력 완전 무시) 사이에서 바꿉니다. `--motion-mode normal|front`로 시작 모드를 지정할 수 있고, `--front-only`는 프런트 전용 모드의 호환 별칭입니다.

기록된 코너 track이 안정적인 객체 ID를 사용하기 전의 오래된 로그는 raw 코너 CAN으로 ID를 재구성합니다. 이때 마지막 raw 측정이 100ms를 넘은 포인트는 predictor 입력에서 제외하므로 화면 표시용 장기 외삽이 가짜 CUT-IN 포인트가 되지 않습니다.

물리 predictor가 새 CUT-IN 후보를 확정하면 화면에는 계속 표시하지만, 재생은 그 후보가 실제 `leadTwo`로 처음 승격되는 프레임에서만 멈춥니다. 이는 openpilot이 활성화된 차량에서 알림음이 발생하는 시점과 같습니다. `leadTwo`로 선택되지 않은 확정 후보는 주황 마커로만 남고 정지하지 않으며, 알림음 조건을 만족한 L2 승격은 연두 마커로 구분합니다. 같은 객체가 L2로 계속 선택되는 동안에는 한 번만 자동 정지하고, 선택이 끝난 뒤 나중에 새로 승격되면 다시 정지할 수 있습니다. 화면은 한글을 지원하는 읽기 쉬운 글꼴과 한글 작업 문구를 사용합니다. 거리 그래프는 -30~130m이고 자차는 흰 점, 레이더 기반 leadOne은 주황 네모, 비전-only leadOne은 파란 네모, leadTwo는 노랑 네모로 표시합니다. 우측 패널은 현재 L1/L2, 확정 후보 ID, 알림을 발생시키는 L2 승격 ID를 따로 표시하며 후보 행에도 상태에 따라 `후보 확정(L2 미선택)`, `L2 승격·알림음`, `L2 선택 유지`를 표시합니다. 각 후보에는 `침범=1.5s@+3.0s`처럼 연속 예측 침범시간과 시작 horizon, `방향=0.28m/0.85`처럼 최근 순진입량과 방향성도 표시합니다. 지도 아래 전체 로그 연속성 그래프에는 레이더 기반 leadOne 거리를 주황색, 비전-only leadOne을 파란색, leadTwo를 노란색으로 표시합니다. lead가 사라지거나 서로 무관한 track ID로 바뀌면 선을 끊지만, 정지 lead의 거리·횡위치·속도가 물리적으로 연속된 ID 인계는 같은 선으로 이어 표시합니다. 연속성 그래프는 창 전체 폭으로 확장되며 seek bar와 가로 시간축을 정확히 공유합니다. lead 그래프의 어느 지점을 클릭해도 두 커서가 같은 시각으로 이동합니다. 수동으로 seek bar나 lead 그래프를 탐색하면 그 시점 이후의 알림음 승격 이벤트를 재활성화하므로, Space로 다시 재생할 때 뒤의 실제 L2 승격에서 다시 자동 일시정지합니다. `F`는 계산 센서를 바꾸지 않고 measured front-radar 포인트만 표시하거나 숨깁니다. bird's-eye 지도에서 회색선은 model lane line, 흰 점선은 화면 비교용 차선 중심, 파란선은 predictor가 유일한 corridor 기준으로 사용하는 model path입니다. 계산 중 차선 중심으로 바꾸지 않습니다. 기본으로 모든 track에 그려지는 소스 색의 흐려지는 채운 점·실선은 predictor가 실제로 사용하는 경로좌표 `(S, dPath)` 과거 이력입니다. 회색 빈 원은 미선택 또는 제어 부적격 미래이며 5m 안의 새 전방 포인트도 여기에 포함됩니다. 녹색은 현재 경로에서 제어 후보가 될 수 있는 motion 또는 이미 선택되어 sticky 유지 중인 lead입니다. 주황색은 확정된 predictor CUT-IN의 전체 연속 corridor 침범 구간이며, 그 안에서 먼 horizon의 확률이 불확실도로 낮아져도 회색으로 되돌리지 않습니다. `H`로 이 계산 이력과 미래선을 표시하거나 숨깁니다. `A`를 누르면 ego 이동을 보정한 raw radar `(xRel, yRel)` 과거 관측을 회색으로 별도 겹쳐 볼 수 있습니다. 이 선택적 raw 관측선은 대상 차량의 ground truth도 아니고 predictor가 외삽하는 이력도 아닙니다. ego yaw는 이 선택적 raw 관측선을 한 좌표계에 정렬할 때만 쓰며 시점 동기화된 `dPath`에 다시 적용하지 않습니다. 가로 seek bar에는 예비감속을 하늘색, 확정 CUT-IN 후보를 주황색, 알림음이 발생하는 L2 승격을 연두색으로 표시하고 유지 중인 검증 구간은 bar 위쪽에 표시합니다. 기존 radard 마커는 없습니다. 레이더 지도는 qcamera 위에 투영한 원근 화면이 아니라 자차 좌표계의 bird's-eye 화면입니다. Space는 일시정지, 좌우 키는 키보드 이동, 위아래 키는 재생 속도 변경, `M`은 세 종류의 이벤트 마커 표시/숨김, `R`은 처음부터 다시 재생하면서 처리한 L2 승격 일시정지를 재활성화합니다. `I`, `C`, `S`는 CUT-IN, CLEAR, STATIONARY 라벨을 적용합니다. 유지 중인 검증 구간 안에서는 해당 사례를 갱신하고, 그 밖에서는 `radar_trajectory_labels.json`에 저장합니다.

검증 화면의 조절바는 디바이스와 같은 6단계 `당근 레이더 CUT-IN 민감도`입니다. `0` 사용 안 함, `1` 둔감, `2` 약간 둔감, `3` 보통, `4` 민감, `5` 아주 민감으로 표시하며 production과 같은 센서별 확률 문턱·방향성 문턱·실측 움직임 확정 시간을 함께 적용합니다. 선택한 단계는 사용자 로컬 `carrotpilot/radar_validation.json`에 저장합니다. `T`로 처리 센서를 바꿔도 같은 민감도 단계를 유지하면서 해당 센서의 production 정책을 적용합니다. 미래 예측시간은 검증 화면과 디바이스 모두 5.0초로 고정하며 차체와 corridor가 최소 0.5초 연속으로 겹쳐야 합니다. 한 미래 시점만 스치는 것은 허용하지 않습니다. 조절바를 놓으면 해당 단계로 다시 계산해 캐시에 보관하고 CUT-IN 진입 횟수와 leadTwo 프레임 수를 알려줍니다. `--sensitivity 3`으로 실행 시 초기 단계를 지정할 수 있습니다. `--prob`는 고정 비교를 위한 고급 1회성 확률 문턱 옵션으로만 남으며, 화면에서 민감도를 바꾸면 다시 전체 production 정책을 적용합니다. 검증 화면은 기존 radard나 저장된 수동 라벨을 바꾸지 않습니다.

유지 목록에 없는 별도 로그도 모듈 실행으로 바로 열 수 있습니다. 같은 세그먼트 폴더의 `qcamera.ts`를 자동으로 사용합니다.

```powershell
.venv\Scripts\python.exe -m openpilot.selfdrive.carrot.radar.tools.radar_lead_simulator `
  "W:\routes\차량폴더\세그먼트\rlog.zst" --start 30 --paused
```

`validate_radar_lead_model.py` 파일명은 기존 사용 명령과의 호환을 위해 유지하지만 더 이상 학습 모델을 불러오거나 검증하지 않습니다. `cutin_validation_cases.json`과 `radar_trajectory_labels.json` 전체를 재생해 기존 radard와 물리 shadow 결과를 따로 보고합니다. 모든 수동 라벨은 검증 전용이며 계산식, 임계값 조정이나 학습에 사용하지 않습니다.

## 레이더 감지음

openpilot이 활성화된 상태에서 확정된 끼어들기 차량이 실제 `leadTwo`로 승격될 때만 2단계 알림음이 재생됩니다. 끼어들기 후보로 감지되었더라도 `leadTwo`로 선택되지 않으면 소리가 나지 않으며, 같은 객체가 계속 `leadTwo`로 추적되는 동안에는 한 번만 울립니다. 스피커가 없는 C3X Lite에서는 같은 이벤트를 GPIO 부저 패턴으로 알립니다. 이 알림음은 선택된 레이더 결과를 알려줄 뿐 선행차 선택이나 종방향 제어를 변경하지 않습니다. 더 높은 우선순위의 안전 경고가 발생하면 해당 경고음이 우선할 수 있습니다.

## 하네스 프리셋과의 관계

현재 최초 설정 프리셋은 다음처럼 시작합니다.

| 구성 | `EnableRadarTracks` | `EnableCornerRadar` |
|---|---:|---:|
| ADAS 모듈 하네스 | `0` | `1` |
| 카메라 하네스 | `0` | `0` |
| 순정 SCC 유지 | `0` | `0` |

ADAS 프리셋이 코너 레이더를 켠다는 것은 하네스에서 접근 가능한 구성을 뜻할 뿐, 모든 ADAS 차량의 코너 레이더 메시지가 검증됐다는 뜻은 아닙니다.

## 확인 순서

1. 차종, 연식, 트림, HDA 세대와 정확한 하네스 위치를 확인합니다.
2. 현재 값을 기록하고 기본값 `0`에서 정상 동작을 먼저 확인합니다.
3. 동일 차량 구성의 검증 기록에서 지원되는 레이더 메시지를 확인합니다.
4. 한 번에 한 설정만 변경하고 차량을 다시 시작합니다.
5. 정차 상태에서 경고등과 CAN 오류를 확인합니다.
6. 안전한 시험 환경에서 선행차 거리·상대속도와 끼어들기 오검출을 확인합니다.
7. 이상이 있으면 즉시 원래 값으로 복원합니다.
