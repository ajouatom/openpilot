# 차로 변경(차선변경) 이해하기

[English](../en/lane-change.md)

> [!IMPORTANT]
> 방향지시등은 주변 차량에 의사를 알리는 장치인 동시에, openpilot에는 **차로 변경 요청**이 됩니다. 먼저 거울과 사각지대를 확인하고 안전한 간격을 선택한 뒤 방향지시등을 켜세요. 방향지시등부터 켜고 안전 여부를 나중에 확인하면 설정에 따라 차로 변경이 바로 시작될 수 있습니다.

## 핵심부터 알아보기

차로 변경이 시작된 뒤의 경로, 횡이동 속도와 조향 형태는 comma 주행 모델이 만든 예측 경로가 주도합니다. 제어기는 이 경로를 차량의 조향 한계 안에서 따라갑니다. 따라서 carrotpilot에는 **차로 변경만을 위한 목표 조향각, 횡이동 속도 또는 완료 시간을 직접 지정하는 일반 설정이 없습니다.**

carrotpilot이 주로 결정하는 것은 차로 변경의 모양이 아니라 **모델에 차로 변경 요청을 언제 전달할지**입니다. 방향지시등, 지연시간, 운전자 조향토크 확인, 차선 종류, 차량 BSD와 사용 가능한 측면 레이더 정보를 시작 조건으로 사용합니다.

이 조건들은 보조 장치이며 안전 판정을 대신하지 않습니다. openpilot은 차량 뒤쪽 교통을 보는 후방 카메라 입력을 사용하지 않으며, BSD와 측면 물체 정보의 지원 범위도 차종·장착 상태·주행 환경에 따라 다릅니다. 옆 차로 뒤차의 거리와 접근 속도를 최종 판단하는 책임은 항상 운전자에게 있습니다.

## 누가 무엇을 결정하나요?

| 주체 | 담당하는 일 | 담당하지 않는 일 |
|---|---|---|
| 운전자 | 거울·사각지대·뒤차 접근 속도 확인, 안전한 간격 선택, 방향지시등 조작, 필요 시 취소·개입 | 안전 판단을 시스템에 넘기는 것 |
| carrotpilot 시작 조건 | 차로 변경 대기, 설정된 지연, 조향토크 확인, 차선·BSD·측면 물체 조건 확인 | 안전한 차간을 완전하게 보장하거나 차로 변경 경로의 각도를 설계하는 것 |
| comma 주행 모델 | 차로 변경 요청을 받은 뒤 장면에 맞는 주행 경로 생성 | 운전자 대신 사각지대와 뒤차의 안전을 보증하는 것 |
| 차량 제어기 | 모델 경로를 차량과 안전 제한이 허용하는 범위에서 추종 | 모델이 의도한 차로 변경 경로를 새로 설계하는 것 |

## 실제 동작 순서

1. 운전자가 거울과 사각지대를 확인하고 뒤차와의 거리뿐 아니라 접근 속도까지 판단합니다.
2. 안전한 간격을 선택한 뒤 원하는 방향의 방향지시등을 켭니다. ATC가 요청한 차로 변경도 이후 과정은 같으며 운전자의 감독이 필요합니다.
3. carrotpilot은 `preLaneChange` 상태에서 설정된 지연과 시작 조건을 확인합니다.
4. 조건이 만족되면 모델에 왼쪽 또는 오른쪽 차로 변경 요청을 보냅니다.
5. comma 주행 모델이 차로 변경 경로를 만들고 차량 제어기가 이를 따라갑니다.
6. 운전자는 전 과정을 계속 감독하고, 위험하면 즉시 조향하여 취소하거나 직접 제어합니다.

주행 장면과 설치된 모델 버전에 따라 같은 도로에서도 차로 변경이 더 빠르거나 느리게 느껴질 수 있습니다. 이는 모델이 생성한 경로의 차이일 수 있으며, `LaneChangeDelay`로 진행 속도를 바꾸는 것은 아닙니다.

## 차로 변경 설정이 바꾸는 것

### `LaneChangeNeedTorque` — 시작 확인 방식

| 값 | 동작 |
|---:|---|
| `-1` | 운전자 방향지시등에 의한 자동 차로 변경을 사용하지 않음 |
| `0` | 별도의 운전자 조향토크 확인 없이 조건이 만족되면 시작 |
| `1` | 운전자가 차로 변경 방향으로 핸들에 조향토크를 가해야 시작 |

방향지시등을 충분히 일찍 켜는 운전자라면 `1`이 의도하지 않은 즉시 진입을 줄이는 데 도움이 됩니다. 그러나 토크 확인은 안전 확인 버튼이 아닙니다. 핸들을 밀기 전에 운전자가 다시 확인해야 합니다.

### `LaneChangeDelay` — 시작 전 대기시간

표시값에 `0.1초`를 곱한 만큼 방향지시등 입력 후 기다립니다. 예를 들어 값 `10`은 1.0초입니다.

이 설정은 **차로 변경이 시작되기 전의 대기시간**만 바꿉니다. 차로를 넘어가는 속도, 조향각 또는 차로 변경 완료 시간은 바꾸지 않습니다. 또한 시간이 지나면 안전하다는 뜻도 아닙니다.

### `LaneChangeBsd` — 차량 BSD 신호 처리

| 값 | 동작 |
|---:|---|
| `-1` | BSD 신호를 시작 조건에서 무시 |
| `0` | BSD 감지 중 자동 시작은 막되, 운전자가 같은 방향으로 조향토크를 가하면 재정의 허용 |
| `1` | BSD 감지 중에는 운전자 조향토크로도 시작하지 않음 |

차량 BSD는 보조 신호입니다. 센서의 감지 범위 밖에 있거나 빠르게 접근하는 차량, 오토바이, 악천후와 센서 오류를 모두 책임지지 못합니다. BSD 표시가 없다는 사실을 “뒤차 없음”으로 해석하지 마세요.

### `LaneLineCheck` — 차선 종류 처리

| 값 | 동작 |
|---:|---|
| `0` | 차량이 제공하는 차선 색상 정보를 사용하며 노란선에서 차단 |
| `1` | 점선·실선 타입을 기준으로 판단 |
| `2` | 타입을 기준으로 판단하되, 실선 차단을 운전자 조향토크로 재정의할 수 있음 |

카메라나 차량이 차선을 잘못 분류할 수 있고, 설정 `2`는 실선 통과를 안전하거나 합법적으로 만들어 주지 않습니다. 도로 표시와 교통 법규를 운전자가 직접 확인해야 합니다.

## 바뀌지 않는 것과 혼동하기 쉬운 설정

- `LaneChangeDelay`는 **진입 시점**만 늦춥니다. 진행 중인 차로 변경을 천천히 만들지 않습니다.
- 일반 설정에는 차로 변경 전용 각도, 횡이동 속도, 경로 모양 조절값이 없습니다.
- `CustomSteerDeltaUpLC`, `CustomSteerDeltaDownLC`는 일부 토크 차량에서 차로 변경 중 조향토크의 변화 제한을 조정하는 고급 차량 제어값입니다. 모델의 목표 경로나 차로 변경 속도를 지정하는 값이 아니며, 잘못 조정하면 경로 추종 성능과 안전 여유를 해칠 수 있습니다.
- `SteerActuatorDelay`, `LatSmoothSec` 같은 일반 조향 설정은 전체 경로 추종의 시점과 반응에 영향을 줄 수 있지만, 차로 변경 모양을 선택하는 전용 설정은 아닙니다.
- `DynamicTFollowLC`는 차로 변경 시작 직후의 **종방향 차간거리**를 바꾸며 횡방향 차로 변경 속도나 각도를 바꾸지 않습니다.

## 안전하게 사용하는 방법

1. 방향지시등을 켜기 전에 룸미러, 사이드미러와 사각지대를 확인합니다.
2. 뒤차와의 현재 거리만 보지 말고, 뒤차가 빠르게 가까워지는지도 확인합니다.
3. 즉시 시작 모드(`LaneChangeNeedTorque=0`, 짧은 지연)를 사용한다면 방향지시등을 켜는 순간 차로 변경을 허가한다고 생각합니다.
4. 미리 방향지시등을 켜고 기다리는 운전 습관이라면 조향토크 확인(`LaneChangeNeedTorque=1`) 또는 적절한 시작 지연을 사용합니다. 그래도 출발 직전에 다시 확인합니다.
5. 차로 변경 중에는 핸들을 놓지 말고, 뒤차가 가속하거나 옆 차로 상황이 변하면 즉시 개입합니다.
6. BSD·측면 레이더 차단이 반복해서 예상과 다르면 해당 기능을 신뢰해 계속 운행하지 말고 차량 지원 상태와 로그를 점검합니다.

## “차로 변경이 너무 급해서 뒤차와 위험했다”면

이 상황에서는 두 문제를 나누어 봐야 합니다.

- **차로를 넘어가는 움직임 자체가 비정상적이었는가?** 모델·조향 추종·장착 상태·노면 등의 문제를 로그로 확인합니다.
- **차로 변경을 시작한 시점의 간격이 안전했는가?** 정상적인 모델 경로라도 빠르게 접근하는 뒤차 앞에서 시작하면 충돌 위험이 생깁니다.

특히 즉시 시작 설정에서는 “일단 방향지시등을 켜고 뒤차를 확인”하는 순서가 위험합니다. 시스템이 할 수 있는 핵심 조정은 진입 시점을 기다리게 하는 것이며, 실제로 안전한 순간을 선택하는 일은 운전자가 해야 합니다.
