# 신호 검출 GPU 실측과 주행 모델별 실행 — 2026-10-11

사용자는 eGPU와 내부 주행 모델에서 모두 신호 관찰기를 사용하고, 새 eGPU 모델의
실제 실행과 내부 모델 전환까지 차량에서 확인하도록 요청했다. 차량은 시동 ON,
P단, 속도 0, 제어 비활성 상태에서 시험했다. 아래 GPU 시험 동안은 원본 내부
ONNX와 x/v, 정지·출발 제어를 유지했다. 이후 명시적으로 요청받은 정차 적색
출발 차단은 별도 기능으로 추가했으며 아래 후속 기록을 따른다. `assist_enabled=0`은 유지한다.

## 실제 모델 설치

최초 확인 차량은 `42760b7f0a`, Cinque v3 `e758b96d`로 실행 중이었다.
새 모델은 시험 브랜치에만 있었으며 그 시점에는 차량에서 실행되지 않았다.
`carrot-signal-shadow`에 최신 차량 신호 코드를 통합한 `150720b104`를 설치하고,
Mountain Dew `8d736683`, AMD SHA256 `256f2178366479a211933701c03518621ed3970289e6a8a43e5a2bcb15e55b5f`,
격리 런타임 `d3f09c9b`의 패키지를 검증·설치했다. 정상 manager 재부팅 후
실시간 카메라 160프레임 모두 valid, 누락 0, 평균 추론 36.81 ms를 확인했다.
부팅 GPU 검증도 같은 checkpoint로 실행됐다. `carrot-wip`의 Cinque v3 선택은 유지한다.

## 같은 입력의 추론 시간과 수치 일치

최근 실제 영상에서 추출한 동일한 6개 입력을 사용했다. 전처리와 카메라는 제외하고
호스트 입력 전달부터 동기 출력 읽기까지 측정했다. 각 네트워크는 3회 준비 후
6개 입력을 3회 반복했다. CPU는 little cores 0–3의 단일 스레드이며 초기 GPU
기본/FP16 시험도 같은 CPU 마스크였다. 최종 FP32 준비·단독 측정은 offroad에서
0–7 마스크를 사용했다. 따라서 아래 비율은 순수 GPU 산술 성능 비교가 아니다.
실제 차량 worker는 아래 별도 little-core 동시 부하 측정으로 확인한다.

| 실행 방식 | 위치 검출 평균 | 색상 판독 평균 |
|---|---:|---:|
| CPU ONNX Runtime | 2,241.18 ms | 199.20 ms |
| 기본 QCOM | 2,556.14 ms | 133.48 ms |
| QCOM IMAGE, FP16 시험 | 211.42 ms | 89.73 ms |
| QCOM IMAGE, FP32 + 상수 연산 제거 | 244.85 ms | 51.67 ms |

FP16의 색상 확률 최대 차이는 0.032여서 이번 설치에 사용하지 않았다.
FP32는 `rtol=1e-3, atol=1e-4` 검사 통과, 위치 검출 최대 절대 차이
0.00010693, 색상 0.000002325였다. 선택된 anchor와 6개 색상 argmax도 같다.
이는 6개 입력의 수치 일치이며 신호 인식 정확도 전체 검증이 아니다.

처음 FP32 준비에는 검출 343.84초, 분류 75.61초가 필요했다. 준비 중에는 기존
`IsTakingSnapshot`과 `OnroadCycleRequested`로 offroad/noOutput 상태를 확인하고,
900초 제한과 finally 복구를 적용했다. 시동 신호나 Panda 상태를 조작하지 않았다.
로컬 생성 JIT를 ONNX SHA, 캐시 SHA, tinygrad tree, Python ABI, GPU 식별,
컴파일 플래그와 함께 저장한다. 새 프로세스 재읽기 출력은 전부 bit-identical이었다.
재읽기 11.60초에 최초 실행 약 4.85초가 추가됐으며, 카메라 worker에서는 낮은 CPU
우선순위와 시스템 부하 때문에 준비 시간이 더 길 수 있다. 자동 모드는 캐시가 없으면
실패를 기록하며 주행 중 수분짜리 컴파일을 시작하지 않는다.

## 같은 GPU를 공유하는 방식은 채택하지 않음

| 정차 구성 | 측정 시간 | modelV2 | 실제 frame ID 누락 | 모델 평균 / p95 |
|---|---:|---:|---:|---:|
| 새 eGPU 단독 | 20초 | 20.01 Hz | 0 | 36.56 / 37.23 ms |
| 새 eGPU + QCOM 신호 검출 | 30초 | 20.01 Hz | 0 / 600프레임 | 36.61 / 37.50 ms |
| 내부 모델 단독 | 20초 | 19.99 Hz | 0 | 24.65 / 27.21 ms |
| 내부 모델 + QCOM 신호 검출 | 30초 | 8.49 Hz | 344 | 94.19 / 243.92 ms |

eGPU 동시 실행의 신호 검출은 2.89 Hz, 처리 평균 284.31 ms,
결과 영상 나이 평균 336.00 ms, CPU 연산 평균 50.17 ms였다.
주차 장면에 검출 객체가 없었으므로 이는 전체 화면 검색 위주의 측정이며,
신호등 여러 개를 각각 색상 분류하는 상황의 처리 속도를 보장하지 않는다.
모델이 valid라는 사실만으로 정상 처리율을 주장하지 않았다.

신호 프로세스만 `QCOM_PRIORITY=15`로 낮춘 추가 25초 시험도 8.24 Hz,
297프레임 누락으로 개선되지 않았다. 이를 설치 설정으로 채택하지 않았다.
[KGSL 우선순위 구현](https://android.googlesource.com/kernel/msm/+/498524113fab9562b13902b0f3a56d2cb57d5f7e/drivers/gpu/msm/adreno.h)은
시험의 참고 자료일 뿐, 해당 차량 커널에서 선점이 보장된다는 근거로 사용하지 않는다.
검출기를 중단하면 내부 모델이 20.02 Hz, 실제 누락 0으로 회복했다.
frameDropPerc는 누적 필터 때문에 회복 후에도 잔류하므로 frame ID와 함께 확인했다.

첫 eGPU 복귀 검사는 고정 25초 대기가 짧아 실패했다. 실제 eGPU 재준비 후에는
200프레임, 19.99 Hz, 누락 0, 평균 36.83 ms로 복귀를 확인했다.
후속 시험은 준비 상태를 최대 120초까지 확인한다.

## 자동 실행 정책

`neural_backend=auto`는 다음 두 구성 사이에서 별도 자식 프로세스를 전환한다.

- `UsbGpuActive=true`: 새 YOLOX/MobileNet 신경망을 내부 QCOM GPU로 실행.
- 내부 주행 모델: 기존 가벼운 CPU 영상 추적·색상 비교 관찰기를 실행.

내부 모델에서 큰 신경망을 CPU로 그대로 옮기는 것은 2초 이상의 검출 지연 때문에
선택하지 않았다. 두 구성의 신호 인식 알고리즘이 동일하다는 뜻은 아니다.
기존 내부 CPU 관찰기의 인식 한계는 그대로 남는다. 내부 ONNX 미세조정이나
신호 검출기 재학습을 했다는 뜻도 아니다.

부모는 100 ms마다 eGPU 활성 상태를 확인하며 이전 프로세스 종료·join 후 다음
프로세스를 시작한다. 정상 종료·SIGTERM 시 자식도 정리한다. CPU 비교 모드도
강제로 제어 관찰 발행을 차단하므로 auto 경로는 둘 다 표시·로그만 제공한다.
표시에는 기존 최대 0.8초의 이전 결과 유지 규칙을 공유한다.

관련 데스크톱 검사 138 passed, 1 skipped. 통합 모델 브랜치의
[eGPU 호환성 CI](https://github.com/ajouatom/openpilot/actions/runs/38125586618)도 통과했다.
자동 전환 최종 실측과 활성화 상태는 아래 후속 결과에 기록한다.

재현 스크립트와 원본 측정 자료는 비공개 `.analysis/scratch/2026-10-11-signal-live/`에
보관하며, 완료 시 `.analysis/archive/2026-10-11-signal-gpu/`에 정리한다.


## 자동 전환 실측 완료

f7c27962ed에서 eGPU → 내부 모델 → eGPU를 실제로 전환했다. 각 30초 구간에서
주행 모델은 약 20 Hz, 모든 관측 modelV2 메시지는 valid였다.

| 구성 | 주행 모델 처리 평균 | 보조 관찰 주기 | 보조 결과 나이 평균 |
|---|---:|---:|---:|
| 새 eGPU + QCOM 신경망 | 37.07 ms | 2.88 Hz | 335.36 ms |
| 내부 모델 + CPU 관찰기 | 24.92 ms | 6.37 Hz | 135.39 ms |
| eGPU 복귀 + QCOM 신경망 | 36.81 ms | 2.89 Hz | 336.41 ms |

검사 시점의 세 30초 구간은 frame ID 누락 0을 통과했다. 이후 finally의 상태 확인
샘플 한 개가 마지막 구간에 추가되어 저장된 최종 summary에는 복귀 구간 601개와
ID 간격 1개가 기록되었다. 따라서 저장된 summary를 모두 누락 0이라고 부르지 않는다.
현재 선택은 auto이고 새 MDM은 시험 브랜치에서만 사용한다. 내부/eGPU의 보조
알고리즘과 인식 성능은 서로 다르다.

그 뒤 사용자가 **적색 출발 차단과 경고음**을 명시적으로 요청했다. 위의 표시 전용
정책은 최초 GPU 시험 당시 상태이며, 별도 기본-OFF 정차 차단의 범위와 검증은
[signal_start_guard_20261011.md](signal_start_guard_20261011.md)에 기록한다.
기존 이동 중 assist는 OFF를 유지한다.
