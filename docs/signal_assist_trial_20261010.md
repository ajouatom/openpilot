# 적색 정지 유지와 주행 중 적색 보강 시험 — 2026-10-10

사용자가 원본 ONNX 재학습 실패 이후 보조 신호 추적·정지 유지를 선택했고,
주행 중 검출한 적색을 기존 정지 로직에 전달하는 시험과 차량 반영을 명시적으로
요청했다. 원본 ONNX 및 x·v는 바꾸지 않는다. 신호 출발 속도 임계값도 그대로다.

## 동작

기존 road-camera 관측기의 신호 track 중 전방 화면 영역의 적색을 선택한다.
정규화 중심 x=0.30–0.75/y=0.08–0.55 영역은 전방 후보 선택 가정이며,
실제 내 차선 신호나 화살표 통행 권한을 보증하지 않는다. 신호등 전체 안에 들어간
작은 중복 적색등 영역은 제외한다. 작은 영역만 추적하면 오른쪽 녹색등을 보지
못하는 문제가 실제 재생에서 발견되어 수정했다.

관측기 자체 확인 이후 추가로 적색 0.3초, 녹색 0.4초의 연속 증거와 최소 3개
새 프레임을 요구한다. 결과 나이는 카메라 촬영 기준 200ms 이내, track 나이는
125ms 이내다. 중복·역순 프레임은 확인 시간을 늘리지 않는다. 신호 추적이
재시작하면 새 session을 부여하며, 다른 track의 녹색으로 정지를 해제하지 않는다.

- 속도 절댓값 0.3m/s 이하에서 적색이 확인되면 정지를 유지한다. 모델의 출발
  예측이나 앞차 출발만으로 풀지 않는다. unknown/신호 누락도 자동 해제가 아니다.
- 주행 중에는 82km/h 미만, 방향지시등 없음, 기존 조향 진입 조건, 앞차 없음,
  모델 끝 y 절댓값 5m 미만에서 적색 보강을 검토한다. 모델의 필터된 정지거리가
  `max(5m, v²/(2×기존 comfort_brake))` 이상이고 기존 120–150m 범위 안일 때만
  기존 `TrafficState.red`에 전달한다. 색에서 거리를 만들어내지 않는다.
- 보강이 성립하면 기존 e2eStop 거리·속도 제한 경로를 사용한다. 이미 시작한
  정지는 신호 누락만으로 취소하지 않으며 멈추면 정지 유지로 연결한다.
- 같은 track의 녹색 확인은 보조 제한만 해제한다. 출발 여부는 기존 모델·앞차·
  제어 조건이 결정한다. 강제 녹색/가속 명령은 만들지 않는다.
- 가속페달은 보조 정지를 해제하고 10초간 재진입을 막는다. 해제/비활성,
  차량 입력 무효, Drive 이탈도 보조 상태를 초기화한다. 기존 수동 개입과
  물리적 앞차 장애물, 제동·가속·jerk 제한은 유지한다.

차량별 `/data/signal-color-shadow/assist_enabled=1`을 명시적으로 설정하고
plannerd를 시작해야 켜진다. 기본은 OFF이며 공용 설정 기본값을 바꾸지 않는다.
ON 상태에서 파일을 0으로 바꾸면 0.5초 이내 새 개입을 중단한다. 기존 정지
상태의 후속 처리는 기존 제어 로직에 맡긴다. 다시 ON은 plannerd 재시작이 필요하다.

관측기는 최대 20개 track을 32KiB 이내 JSON으로 `/dev/shm`에 원자적으로
전달한다. 차량 상태·model·radar·selfdriveState·carControl의 seen/valid/alive와
250ms 이내 수신, CAN 유효, Drive, 종방향 활성 조건을 별도로 검사한다.
`signalAssist` 진단에는 hold/red_sign/reason/track 및 읽기 시간이 남는다.
raw 관측의 녹색은 그 자체로 가속 허가가 아니므로 관측 로그의
`control_permission=False`는 유지한다.

## 기록 재생

기존 야간 12개 구간의 14,242개 주행 계획 입력으로 실제 CarrotPlanner의
상태 전환·정지거리·속도 제한 코드를 실행했다. 후보는 자기 변경 상태를
다음 호출에 이어서 사용했다. 기능 OFF 출력은 변경 전과 14,242/14,242개가
완전히 같았다. 원본 재생과 기록의 xState는 14,233개, trafficState는 14,224개가
일치했다. 저장 Params 대신 기본값·기록 주행 모드를 사용하고 carrotMan 입력은
제외했으므로 실제 차량 전체를 완전히 재현한 것은 아니다.

카메라 전체 주기, 원래 기록 주기, 주차 시험에서 측정한 누락 패턴을 각각 사용하고
결과 도착 지연 125ms를 넣었다. 정답은 결정 이후 점수 계산에만 사용했다.

| 적색 사건 | 종방향 활성 표본 | 원본 비정지 상태 | 보조 적용 후 비정지 상태 |
|---|---:|---:|---:|
| 야간 12번 | 76 | 49 | 0 |
| 야간 16번 | 80 | 59 | 0 |
| 야간 20번 | 60 | 4 | 0 |

세 주기 조건에서 이 결과가 같았다. 비활성 표본은 보조 기능이 개입하지 않으므로
위 표에서 제외했다. 이 숫자는 실제 오출발 횟수나 차량 제동 결과가 아니다.
이번 지표는 전체 Carrot 상태이며 이전 ONNX 실험의 녹색 판정 프레임 수와 다르다.

검토된 적색에서 녹색 해제로 잘못 풀린 것은 세 조건 모두 0건이었다.
관측된 녹색 이후 보조 해제는 전체 주기 네 사건에서 0.716–0.766초,
기록 주기 다섯 사건에서 0.768–0.815초, 주차 누락 패턴에서 0.716–0.915초였다.
전체 주기의 다섯 번째 사건은 녹색 평가 구간에 유지 중인 보조 정지가 없었다.
기존 0.5초 정지 카운터 및 모델 조건이 추가되므로 실제 출발 지연은 이 값과 다르다.

전체 주기에서 움직이는 적색 보강 표본은 916개, 기존 비정지 상태에서 정지
상태로 달라진 표본은 57개였다. 정지 유지가 이미 걸린 뒤의 기록 속도 상승도
재생에는 그대로 들어온다. 실제 차를 멈췄을 때 바뀔 속도·영상은 재생하지 않았다.
200ms 도착 지연 시험에서는 실제 판정 시 이미 기한을 지나 새 개입이 전혀
시작되지 않았다. 기존 모델만으로 남는 실패를 고쳤다고 해석하면 안 된다.

70개 보조 상태/통신/계획 연결/기존 정지 거리 시험이 통과했다.
MPC/액추에이터/차량 응답의 닫힌 루프, 내 차선 신호 보증, 정지선 정확도,
원거리 적색 성능은 검증되지 않았다. 감속하면 원본 모델도 신호를 더 잘 볼 수
있다는 사용자 가설은 실제 후속 주행 자료로 확인해야 한다.

## 설치와 재현

사용자가 추가로 지정한 `b80db2c97d`도 같은 시험 브랜치에 포함했다.
현대 CAN-FD openpilot 종방향 제어에서 최종 StopReq 첫 프레임부터 두 aReq를
0으로 보내고 정지 요청 중 자동 해제/재시도를 제거한다. 이는 이 문서의 신호
보조와 별개인 CAN 정지 변경이다. 위의 액추에이터 제한 보존 설명은 신호 보조
자체에 대한 설명이며, 합친 버전의 CAN 출력까지 종전과 같다는 뜻은 아니다.
합친 코드에서 신호 관련 70개와 정지/jerk/SCC/피드백 관련 181개 시험을 통과했다.
후자는 Windows의 Params를 대체한 데스크톱 시험이며 실제 ECU 반응 검증이 아니다.

연결된 사용자 차량에 `b80db2c97d`를 fast-forward 적용했고 P단·정지·비활성을
확인한 뒤 정상 DoReboot 경로로 재부팅했다. 새 boot ID와 card/plannerd/modeld/
signalcolord 프로세스를 확인했다. 개별 프로세스 재시작만 시도한 앞선 설치는
관측 초기화 또는 플래너 재시작 확인 제한시간을 통과하지 못해 보조를 OFF로
돌렸으며, 최종 재부팅 검증이 그 상태를 대체한다.

최종 25초 정차 확인에서 assist_enabled=1, 신호 보조 진단 25개 모두 ON 및
Park에서 hold/red_sign 없음, CAN 유효를 확인했다. 모델 500프레임은 모두 유효하고
연속 ID이며 20.008Hz, 평균 계산 25.061ms였다. 계획 500개 모두 유효하며 계산
p95는 4.807ms였다. 신호 관측 245개 모두 fresh, 결과 나이 p95 133.974ms,
플래너의 관측 읽기 p95 0.379ms였다. 확인 동안 주요 프로세스 PID가 유지됐고
원본 driving_supercombo.onnx SHA-256도 종전과 같았다. 이는 설치·실행 확인이며
신호 앞 실제 제동, 정지선 위치, 녹색 출발 또는 b80의 ECU 정지 반응 검증이 아니다.

별도 opt-in 차량 시험용이다. 정지 중 확인되는 설치·처리 속도와 주행 검증을
구분한다. 신호를 잃거나 track이 교체되면 정지가 계속될 수 있고,
운전자가 가속페달 또는 제어 해제로 개입할 수 있다.
