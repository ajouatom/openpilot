# Konik A1M / Orin NX16 지도 입력 포팅과 검증

공식 기준은 ba24d23e838545a4e8c4a19bb39c93bf79c1daa9이다. 이 기준에는 N16 축약 응답과 입력/워프 겹치기가 이미 포함돼 있다. 이번 변경은 지도 입력 준비의 기본 비활성 실험 경로와 정상 전체 출력 길이의 호환성 보강이다. 새 호스트 번들·서명·모델·전력·USB 역할·차량 제어는 변경하지 않는다.

## 기여 출처와 변경

[tjdgus200의 fc02df9](https://github.com/tjdgus200/openpilot/commit/fc02df9c0d17dc3e8c2f6d53e17dd46ebf042888)를 현재 기준에 이식했다. 원 저작권과 라이선스를 유지한다. [136119c](https://github.com/tjdgus200/openpilot/commit/136119c818566586588fa9c820d2b1749bac539a)의 축약 응답과 [2e971ad](https://github.com/tjdgus200/openpilot/commit/2e971adb3ac1d542062524707ffdaef5d00dd780)의 겹치기 변경은 이미 공식 기준에 있으므로 중복 이식하지 않는다.

- CARROT_TRT_DIRECT_MAP은 기본 0이다. 명시적으로 1인 별도 실험에서만 compact 지도 데이터를 기존 엔진 입력 버퍼에 직접 넣는다. 중간 float32 지도·직렬화·문맥 연결 복사를 줄인다.
- binding의 동일성·주소·형상·자료형·정렬·쓰기 가능 여부와 모든 스칼라를 먼저 확인한다. 새 프레임과 만료된 0 지도도 매번 덮고 수신 버퍼 뷰를 보관하지 않는다.
- 음수 0·소수·범위 밖 지도는 기존 raw 전송 경로를 유지한다. 원형 유한값 검사·GPU 상태 feedback·reset·오류 응답을 유지한다.
- 현재 기준에 없던 import os를 명시해 기본 OFF를 포함한 엔진 준비의 NameError를 방지했다.
- 정상 전체 출력 크기를 먼저 구분한다. 전체 출력이 2066개인 다른 모델을 N16의 compact 응답으로 오인해 거절하지 않는다. N16 compact의 모델·레이아웃 검사와 협상은 그대로다.

## 직접 실행한 검사

- Linux PC의 관련 18개 검사 파일: **344 passed**, skip 0, warning 0, 23.79초. N16/legacy/v3, raw/compact, 실제 POSIX stream, 상태 reset/유한값, malformed IPC와 새 반례를 포함한다. 전체 저장소 CI 결과는 아니다.
- 참고 패치 그대로의 반례는 먼저 실패했다. 전체 길이 2066 모델 1개와 누락 import에 의한 기본/OFF/ON 준비 3개를 보강했다.
- 실제 Orin NX16의 **CPU 배열** 비교: FP16 600프레임, FP32 600프레임, 각 프레임 11개 binding의 모든 바이트 일치. 밀집/희소/만료 0 지도, 포인터 보존, 수신 버퍼 재사용, 잘못된 길이/NaN/Inf/교체/읽기 전용 binding 거절과 raw fallback을 확인했다. 21.02초, 최대 RSS 86,388KiB였다.
- 이 Orin 검사는 CUDA pinned 버퍼·엔진·모델 추론·실제 recurrent state 실행을 포함하지 않는다. 선택적인 native finite 컴파일러는 검증 프로세스 안에서만 대체했고 NumPy 검사 경로를 사용했다. 운영 소스는 그대로다.
- 첫 Orin 시도는 공식 CUDA 패키지의 .pth가 시작 시 cuda namespace를 자동 등록해 CPU 전용 검사에 걸렸다. 해당 두 파일의 지문을 확인하고, site 시작을 생략한 별도 프로세스에서 같은 금지 검사를 유지해 통과했다. GPU 실행 실패로 보고하지 않는다.
- 넓은 20파일 -Werror 시험에는 변경하지 않은 daemon/protocol fixture의 소켓·lock 정리 경고가 남았다. 344개 통과를 그 시험이나 전체 CI 통과로 확대하지 않는다.

## 공식 축약 응답의 별도 실제 측정

아래는 **이미 공식 배포된 축약 응답**의 효과다. 이번 기본 OFF 지도 입력 변경의 속도 향상이 아니다.

Konik A1M + Orin NX16/J4012, L4T 36.4.7용 커널, TensorRT 10.3.0, 공식 서명 런타임 e7ff007ddc5c539ec34ea83d7b9ac7de1df1a6ae, N16 모델 01effc679eb46d6036ce0302673a87fe2dcfcc95a679daeeb929679e53c3647a로 측정했다. 40W 모드와 GPU 1173MHz를 맞추고, 같은 합성 prewarped 0 입력을 전체/축약/축약/전체 순서로 각각 600프레임 실행했다.

| 지표 | 전체 응답 1200프레임 | 축약 응답 1200프레임 |
|---|---:|---:|
| 평균 | 36.759ms | 34.251ms |
| P50 | 36.184ms | 33.670ms |
| P95 | 41.507ms | 38.767ms |
| P99 | 45.659ms | 42.858ms |
| 최대 | 72.847ms | 64.755ms |
| 50ms 초과 | 10 | 4 |
| 로컬 IPC 응답 | 74340바이트 | 8284바이트 |

평균 차이는 2.508ms/6.82%였고, 같은 프레임의 2066개 driving prefix는 두 쌍 모두600/600개가 바이트 단위로 일치했다. 평균30ms/25ms 목표는 미달이다. 이 구간의 P99는50ms 미만이지만 모든 프레임의50ms 준수를 보장하지 않는다. 설정된 호출 간격은20Hz이며 sleep 오차를 포함한 실제 루프는 각30.60~30.63초였다. 엄격한20.000Hz·카메라 전체 경로·NNFF/EPS·주행 검증은 아니다.

gpu_us는 CPU 시계로 잰 H2D/실행/D2H/동기화 구간이다. queue_us는 요청 수신 후 입력 해독·검사·입력 버퍼 채우기이며, total_us는 이 둘과 출력/상태 검사를 포함한다. 응답 직렬화·송신은 total_us 밖이다. 세 값을 합하거나 RTT와의 차이 전부를 USB 지연으로 해석하지 않는다.

## 적용 경계

이 PR만으로 설치된 서명 호스트가 바뀌지 않는다. 지도 경로를 활성화하려면 별도 승인된 런타임 배포·전체 GPU 출력/상태 비교·실제 왕복 재측정이 필요하다. 참고 기여의 약0.14ms CPU 준비 절감은 참고 작업의 결과이며 이번 장치의 전체 왕복 개선으로 인용하지 않는다. 기본 OFF를 유지한다. 차종별 조향/가감속·CAN·다른 차량 기능은 변경하지 않았다.
